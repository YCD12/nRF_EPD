**外置 Flash 删除功能（固件 0x3F）**

在“设备资源 → 删除设备资源”中提供两个入口：

- 选择分区并删除。覆盖分区表、设备配置、日期标注、更新状态、日历、UI 布局、字体、待办和保留区；删除该分区的整个范围。
- 清空全部外置 Flash。擦除全部 512 KiB，包括分区表和保留区；分区表缺失或损坏时仍可使用。

连接后读取分区，即可选择目标。操作前弹出目标名称、容量和不可撤销提示；取消确认不会写入设备。建议先“回读资源 → 保存到本地”，或导出当前工程。网页本地草稿和导入字体不随设备删除操作清除。

设备逐个擦除 4 KiB 扇区，并在返回成功前读取整个扇区校验。进度只计入已确认的扇区。执行期间锁定其他设备操作；断线、超时或读写失败会停止后续擦除，已删除的数据不会自动恢复。重连后可读取状态或重新执行删除。

删除分区表或清空后，发送完整资源可重新初始化。仅删除配置、标注或待办时，发送资源会从待发送包恢复缺失分区，并保留仍然有效的个人分区。恢复个人字库和待办字体应使用相匹配的原资源备份。删除 Flash 不会主动擦除电子纸当前留存的画面。

旧固件的删除按钮禁用，并提示更新到 `0x3F`；普通资源编辑和安装仍可按原版本能力使用。删除功能由 STATUS 的能力位协商，不根据包版本猜测。

**清空后的显示与恢复（固件 0x40 修复）**

`0x3F` 在资源缺失时仍执行分钟、跨日和待办重试调度；整片擦除后，退出维护又可能因配置缺失提前返回，留下旧待办的内存状态，导致无有效资源时反复刷新。

`0x40` 在资源尚未成功激活时暂停周期刷新，并在擦除分区表或待办之前停用旧待办缓存。启动或手动刷新仍可显示 `NO DATA`，之后等待资源恢复；低电量保护仍然工作。重新发送资源并成功激活后，立即绘制并恢复正常定时更新。

连接网页会读取状态，不会自动重装资源。看到“显示资源尚未就绪”时，先“重新生成并载入”或载入备份，再点击“发送资源到设备”。仅连接而不发送资源时，设备应保持当前画面。

**协议**

继续使用资源命令 `0x26`：

| 字段 | 定义 |
| --- | --- |
| STATUS 能力 | `RESOURCE_CAP_ERASE = 0x40` |
| 擦除子命令 | `11`；请求共 9 字节 |
| 字节 0–2 | `0x26`、子命令、请求 token |
| 字节 3–4 | 小端 `partition_id:u16`，0 表示整片芯片 |
| 字节 5–8 | 小端 `offset:u32`，分区内偏移；ID 0 时为芯片绝对地址 |

必须先用现有 ENTER/MIG1 进入独占维护会话，且没有活动上传事务。偏移须按 4096 字节对齐并位于目标范围内。普通分区在每次擦除前重新验证分区表；固定定位的分区表和整片擦除允许在表损坏时恢复。每条命令只擦除一个扇区，避免整片操作长时间阻塞 BLE。重复请求使用现有传输层 ACK 缓存，不重复擦除。

每个扇区的校验复用 Flash CRC 读取及看门狗喂狗路径，预期 CRC32 为 `0xF154670A`（4096 个 `0xFF`）。擦除前失效相关资源缓存，结束维护时重新加载；被删除的必需资源会使应用报告资源不完整，网页区分这一状态与擦除失败。

**验证**

- C 模拟 Flash：边界、16 位分区 ID、维护保护、活动事务互斥、CRC/IO 故障、部分擦除、断电重启、重复 ACK、完整清空与重装。
- 网页：旧固件、取消、各分区隔离、全片清空、个人分区恢复、操作锁、部分失败与断线后过期响应。
- Chrome 本地文件和 HTTP 页面：实际 DOM 中列出全部分区，通过模拟 BLE 验证取消、单分区删除和全片 128 扇区清空。
- 空 Flash 回归：五种显示模式在连接与断开状态跨分钟和跨日保持空闲；待办覆盖配置缺失导致激活提前失败、缺失提示、资源重装 ACK 与恢复绘制。

自动测试未对真实设备执行删除。
