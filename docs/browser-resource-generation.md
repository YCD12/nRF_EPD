# 浏览器生成设备资源

控制台的「设备资源」提供 `build-external-resources.bat` 的资源生成与发送流程。生成逻辑全部在浏览器中执行，无需 Python、批处理、本地后端、预生成 ERS 或 `default-project.json`。

## 使用流程

1. 进入「设备资源」，网页优先恢复此浏览器保存的资源草稿；没有草稿时，从 JS 默认源数据和三个基础字模 BIN 构造完整资源并自动载入待发送区，不读取 `tools` 或 `output` 目录。
2. 点击「生成默认资源」可以重新准备默认资源。新生成的资源包含 `partition-table.ers`、`calendar.ers`、`ui.ers`、`fonts.ers`、`epd-config.ers`、`calendar-annotations.ers` 和 `todo.ers`。
3. 在编辑器修改日历、布局 JSON，也可以导入完整资源工程、日历 JSON 或 EPD-MIG1 迁移备份。「字体与补字」支持选择系统字体、导入 TTF/OTF、输入额外文字或导入 UTF-8 TXT；高级设置仍支持替换兼容的字模 BIN。点击「重新生成并载入」，网页校验内容、补充缺失字模并替换待发送资源。
4. 点击「下载全部资源 ZIP」保存全部 ERS 文件、模块说明、清单、日历和布局源文件、分区表载荷以及完整工程 `epd-resources.json`。ZIP 解压后可通过「选择资源目录」再次加载；需要继续编辑并恢复源字体时，导入其中的完整工程。「导出完整工程」直接备份当前编辑状态，无需先生成成功，尚未写完的 JSON 也能保存。单独下载支持七类 ERS，旧的六包工程没有待办包时会明确提示。
5. 连接设备后点击「发送资源到设备」。有未生成的修改时，网页先重新生成并校验，失败或取消会停止发送。空白 Flash 安装完整资源；已有分区表的设备按现有更新策略更新日历、布局和字体，保留设备配置、日期标注、待办数据和自定义待办字体。

仅生成或下载文件不会写入设备。发送仍使用现有 BLE 资源协议，先检查分区和容量，再分包传输、校验、提交和应用。默认勾选更新完成后断开连接，可取消勾选以保留连接。

## 自定义输入

- **日历数据**：支持编辑器的完整 JSON，也支持批处理第四个参数使用的部分 `calendar-data.json`。未提供的字段沿用当前数据；`holidays` 同时支持编码整数和 `{ "month": 1, "day": 1, "work": false }`。修改年份范围须提供三个匹配的农历、节气计算表，修改休班年份须提供对应 `holidays`。
- **迁移备份**：与批处理第三个参数相同，格式为 `EPD-MIG1`，包含 `epd_config_hex` 和 `calendar_annotations_hex`。网页生成兼容的记录包，并为迁移标注补充字模。备份用于初始化空白设备；已有设备的个人配置与标注仍按原安装策略保留。
- **资源版本**：留空时保留未变化模块的版本，变化模块加一；填写正整数时全部生成文件使用指定版本。每次生成使用同一生成时间，并重新计算头、载荷和时间戳 CRC。

默认计算表覆盖 2025–2027，休班表沿用仓库的 2026 数据。新年份需要用户提供匹配的数据。JS 默认数据与原命令行工具的默认值一致，七类资源的载荷有逐字节一致性测试；导入工程中未修改的待办内容和自定义字体会保留。旧版六包工程仍按原分区布局重新生成。

## 新增字体与文字

只增加几个文字时，直接修改节日/标注或填写「额外需要的文字」，保留「仅补充缺字」即可；资源包中已有的日期标注和待办文字也会纳入补字需求。补字只处理缺失字形，已有字形保持原样。额外文本中的换行和制表符仅作分隔，实际空格会保留；默认日历中的占位文字不参与补字，未编辑时重新生成不会改变载荷或模块版本。

想让资源使用自己的字体时：

1. 点击「导入 TTF / OTF 字体」或拖入字体文件。中文字体应包含所需汉字；支持独立的 TTF/OTF，文件上限 32 MiB，不支持 TTC 集合、WOFF/WOFF2 或 BDF。
2. 选择作用范围：小字、中字、两者或数字槽位。小字、中字、数字使用设备既有的 12、16、22 像素字号及固定槽位几何；导入字体不会改变设备的字体槽位协议。
3. 选择「仅补充缺字」，用于保留原有字形；选择「用所选字体重绘整个槽位」，用于更换已有字形。重绘保留槽位已有字符及资源所需字符，只修改所选基础槽位。待办的独立自定义字体按其原有身份和字号保留。
4. 点击「检查字体并预览点阵」。网页集中检查本次要生成的字符，列出缺字和尺寸不兼容的字符及槽位，便于一次调整字体选择。检查通过后，预览从最终 u8g2 二进制解码，显示所选槽位的 4 倍点阵、基线、样本几何和全部字体载荷容量；同时选择小字和中字时，两者分别显示。填写额外文字可预览指定样本。预览不替换待发送资源。
5. 点击「重新生成并载入」。成功后恢复「仅补充缺字」，避免后续下载或发送重复重绘。然后下载或发送到设备。

导入字体先读取 Unicode 字符表，缺字会明确报错，不使用其他字体代替。系统字体按浏览器的可用字体回退；需要可控的字形效果时使用本地字体文件。字形超出固定尺寸或分区容量时会停止生成，不裁切字形；可容纳的完整点阵会调整偏移，使其落在设备固定边界内，避免分页漏行。度量超出原字库的紧凑编码位宽时，会自动扩展位宽并转码原有字形，保留像素与度量，固定槽位几何不变。设备只支持 BMP 可显示字符，不支持 emoji。

生成和点阵预览分批让出页面执行时间，支持进度与取消，复用 Canvas；同一次生成复用同一字体与样式的缺字检测参考点阵，导入字体的点阵缓存可供预览和正式生成复用。取消或失败保留原先已就绪的资源和当前编辑内容。

系统字体及 Canvas 渲染结果可能随电脑、系统和浏览器变化。需要在多台电脑使用完全一致的字形时，请分发生成后已验证的 ERS/BIN，并保留「仅补充缺字」；导入相同 TTF/OTF 能固定字体来源，但不能保证重新栅格化的点阵逐字节相同。

## 校验、版本与草稿

导入、生成、下载 ERS/ZIP 及发送前检查 ERS 与分区容量、CAL1/UIR1/FPK1、REC1 内部 CRC、标注记录、TODO 内容，以及待办字体槽位/标识/字号/几何和实际字形覆盖。ASCII 字模入口按固件实际查找规则校验，拒绝字模存在但设备无法通过索引找到的 BIN，以及不同记录使用同一字符编码的字库，避免网页与固件读取到不同字形。字符需求包含电压、负温度、名称及同步提示中的 ASCII 字符，并跟随布局指定的字体槽位。布局的中文文字组件不能误用数字槽位。资源载入时复用已校验的模型；点阵预览一次解码每个槽位，避免逐字重复解析整个字库。

载入旧资源时，可容纳的字形偏移会自动校正，保留所有像素和字体身份，只增加发生变化的字体包版本；损坏的压缩数据、超过槽位尺寸或版本溢出仍会拒绝。无效导入不会替换已载入的工程或待发送资源。完整工程备份保留尚未生成的源数据，导入后继续编辑，发送前再生成和校验。

发送时只有设备已校验的载荷长度、CRC 和版本均一致才跳过写入；明确指定更高版本时也会发送。保留设备已补充字模后，如果最终载荷与设备一致，会沿用设备版本，避免每次重复发送都增加版本并擦写 Flash。生成时间单独变化不会强制重写未变化的载荷。

发送前回读待更新分区的旧资源，保留在当前页面内存中；回读失败时停止写入。旧字体的压缩字模损坏时，保留可以解码的字模，记录损坏字符并使用新字体修复。通过「保存恢复备份」下载包含 `before/` 旧资源、`planned/` 本次发送资源及各模块状态清单的 ZIP；无法解析的旧资源以原始二进制保留。空白或尚未提交的分区可能没有可恢复的旧包。

发送中断后，页面显示每个模块是否已提交。重新连接同一设备，保留当前资源选择和编辑状态，点击「重试未完成资源」：网页再次校验设备内容，跳过已经一致的模块，使用中断前准备好的资源继续写入。空白设备初始化中断也会保留完整计划，包括配置、标注和待办。恢复数据只保留在当前页面，刷新或关闭前请保存恢复备份；分区写入不具备整套资源的原子回滚能力。

编辑内容、当前资源包、额外文字、字体设置、导入 TTF/OTF 和尚未生成的 BIN 会保存到此站点的浏览器存储，优先使用 IndexedDB。字体文件单独保存，编辑草稿只保存引用，避免每次输入都重写整个字体；旧草稿可直接读取。IndexedDB 初始化或写入失败时尝试备用本地存储，恢复时比较两处草稿的保存序号，避免存储切换标记失败导致恢复旧数据；容量不足会提示导出工程。无法读取数据库时，不会把错误当作没有草稿。数据库在保存草稿的同一事务中清理不再引用的字体；备用存储只在支持跨标签页锁时清理，避免影响其他标签页读取。

修改后立即显示「草稿待保存」，写入期间显示「正在保存」，只有最新编辑保存成功才显示「已保存」。切换到后台或离开页面时会尝试提前保存；关闭页面可能中止异步写入，需要保留重要修改时请等待保存成功或导出完整工程。

刷新后自动恢复，包括尚未写完的 JSON；恢复的草稿会在发送前再次生成。恢复失败时保留原草稿，暂停自动保存，不生成默认资源覆盖它。可以重试恢复，或点击「导出保留的原草稿」备份已读取的内容；明确清除草稿后才允许自动保存新的草稿。清除草稿保留当前编辑内容，并阻止之前尚未完成的读取重新写回旧草稿。

完整工程使用 `EPD-RESOURCE-PROJECT-2` JSON，包含资源包、编辑源文本、字体与补字设置、导入的 TTF/OTF，以及尚未生成的 BIN；不保存字体点阵缓存。工程导入上限 64 MiB，字体上限 32 MiB；旧 `EPD-RESOURCE-PROJECT-1` 六包或七包工程仍可导入。导入字体会先准备并检查，成功后才替换当前工程和字体。

草稿限同一浏览器和站点，浏览器清理站点数据后会丢失；跨设备迁移请导出完整工程。系统字体名称会随工程保存，字形效果仍取决于目标电脑安装的字体；导入 TTF/OTF 会保存文件本身。

通过 HTTPS 或本地 HTTP 服务打开 `html/index.html`，使网页能够读取基础字模并使用 Web Bluetooth。只需托管 `html` 目录，生成资源无需连接设备。生成期间会禁用资源编辑、目录选择和发送操作；过期的读取结果不会替换后来选择的工程。

## 前端模块

替代 Python 生成流程的 JS 均位于 `html/js/ui_tools/`：

- `resource_defaults.js`：默认日历计算表、节日/休班表、19 个 UI 组件、512 KiB 分区布局、配置值和模块初始版本。数据为可编辑 JS 对象，不含预封装的 ERS 或 Base64 工程。
- `font_store_tool.js`：u8g2 字模检查、槽位几何及界面必需字符检查、FPK1 生成、基础字模加载缓存、缺字收集。三个基础字模作为静态字体素材随网页放在 `html/resources/fonts/`，无需构建时运行 Python。
- `resource_pack.js`：分区表、默认配置/标注记录、空待办、七类 ERS 封装及 CRC/时间戳/容量校验；自定义工程重建、迁移备份打包和模块说明文件导出。复用已有 `resource_builder.js` 的 CAL1/UIR1/FPK1 编码器和 `font_builder.js` 的浏览器字形生成能力。
- `font_sources.js`：TTF/OTF 的 Unicode cmap4/cmap12 检查、FontFace 本地字体加载、缺字拒绝与点阵缓存。
- `resource_project.js`：完整工程 v2 的源数据、字体文件、待生成 BIN 和设置编码/校验，兼容旧版资源工程。
- `resource_draft.js`：IndexedDB 草稿保存、恢复和清除；不可用时回退到浏览器本地存储。

ZIP 包包含原生成流程对应的 `fonts.json`、`calendar.json`、`ui.json`、`todo.json`、`records.json` 和 `partition-table.payload.bin`，以及便于再次编辑的 `calendar-data.json`、`ui-layout.json` 和总清单 `manifest.json`。说明文件的版本和 CRC 描述本次实际生成的二进制。

原 Python 工具仍可用于命令行生成和维护固件源码，网页生成流程不调用它们。基础字模使用兼容的 u8g2 BIN；新增文字由 Canvas 生成点阵，可使用浏览器可用字体或用户导入的本地字体。
