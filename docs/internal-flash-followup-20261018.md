# 内置 Flash 占用解释与进一步优化（2026-10-18）

大字模、日历资料和 UI 布局已经外置。当前占用主要来自执行这些功能的代码，继续搬小表不能再获得多 KiB 收益。本轮在保留现有功能、资源格式和分区的前提下，将应用从 **56,340 B 降为 55,424 B，减少 916 B（1.63%）**；56 KiB 应用区剩余 **1,920 B**。与上一轮开始的 57,044 B 相比，两轮累计减少 **1,620 B**。

改动已应用到源码，原有 Git 暂存区前后 SHA-256 一致。没有提交、刷机或修改 Bootloader。

## 为什么资源外置后仍占这么多

对本轮基线重新生产构建，BIN 与上一轮最终版本哈希一致。直接拆分最终链接 MAP，不按源文件行数或 ELF 文件大小估算：

| 应用镜像内容 | 本轮优化前 | 本轮优化后 |
| --- | ---: | ---: |
| 代码输入节 `.text/.init/.fini` | 54,534 B | 53,634 B |
| 显式只读数据 `.rodata` | 949 B | 949 B |
| 中断向量 | 512 B | 512 B |
| SDK 事件注册段 | 96 B | 96 B |
| RAM 变量初始值 `.data` | 212 B | 208 B |
| 对齐及链接元数据 | 37 B | 25 B |
| **合计** | **56,340 B** | **55,424 B** |

代码输入节也包含函数内的常量池、跳转表，不能把每个字节都称为指令；但独立资源数据确实已很少。最大的显式只读对象也只是 118 B 参数索引、108 B 参数范围表、72 B Unicode 校验范围等。最终 ELF 不含内置 WQY 大字库、旧农历年份数组、FDS/fstorage 或 printf 格式化函数。基线的 libc 代码仅 376 B，不能靠再删格式化库省出几 KiB。

外置的是字体字模、日历资料、布局与文案、配置及待办持久化内容；内置仍需字体查找/解码、排版裁剪、组件解释、包格式与 CRC 校验、SPI 读写、BLE 命令与背压、OLD/NEW 局刷、计时和低功耗调度。资源可编辑后，还需要通用解释和校验代码，因此资源化并不等于整个功能模块都从固件消失。

基线按最终函数入口的调试位置归属，GUI 约 19.7 KB、EPD 约 18.3 KB、Nordic SDK 约 9.5 KB、main 及其内联调用约 6.5 KB。这只是定位热点：LTO 把跨文件调用内联到调用者，不能据此把 `main.c` 的体积理解为纯启动代码，更不能当作删除模块的净收益。

当前工程通过 `fm25q04b_read()` 读取外置资源，函数仍链接在内部 Flash，未实现外置程序加载/执行路径。缩小绘图 RAM 缓冲、删除调试信息或清理已被链接器剔除的旧源码，不会直接减少上述应用 BIN。

## 本轮实际改动

| 阶段 | 应用 BIN | 本阶段减少 |
| --- | ---: | ---: |
| 重新构建基线 | 56,340 B | — |
| 七段绘制合并 + 资源时钟几何约束 | 55,700 B | 640 B |
| 分钟判定简化 + 连续 OLD 复制 | 55,556 B | 144 B |
| 字体记录扫描合并 | 55,524 B | 32 B |
| 单分区 LTO，最终版本 | **55,424 B** | **100 B** |

- `GUI/GUI.c`：七段数字横/竖及前/后半段的四套循环合为同一扫描线轮廓。合法缩放范围内的绘制顺序、坐标、长度和颜色保持一致，独立构建减少 224 B。
- `EPD/epd_clock_refresh.c`：局刷只接受已加载 UI 资源的几何。生产提供者成功时原本就设置 `resource_geometry=true`；明确入口约束后，LTO 可以删除局刷路径中不可达的旧布局分支，独立构建减少 416 B。通用旧布局 helper 仍保留；条件时钟及覆盖关系的全刷回退保持不变。
- `GUI/clock_layout.h`：在保留时间递增、非零前帧及 600 秒上限检查后，用绝对十分钟/小时区间判断数字变化，省掉日内取模及逐位拆分。
- `EPD/epd_clock_refresh.c`：OLD 捕获前已验证源/目标行跨度相等及条带边界，逐行 `memcpy` 改为一次连续复制，保留 512 B 缓冲范围检查和分页顺序。
- `EPD/font_store.c`：ASCII 与 Unicode 记录扫描共用循环，保留各自终止符和最小记录长度、短读、缓存及剩余长度检查。三个头偏移的重复检查收敛到必经的 `font_header_matches_slot()`。
- `Makefile.nRF52_linux`：保留 `-Os -flto`，增加 `-flto-partition=one`。全部 SDK `-fno-lto` 例外、日志配置、屏幕配置和链接边界保持原值。该项在最终源码上实测再省 100 B；没有采用全局禁用小函数内联的实验。

`main.c` 无需改动。把文件合并成大文件本身没有额外收益，跨文件优化已经由 LTO 完成。

最终 `size` 为 text 55,216 B、data 208 B、bss 9,292 B；静态 RAM **9,500 B**，较基线减少 12 B。加上 2,048 B 栈预留后为 11,548 B，15,656 B RAM 预算还余 4,108 B。未测实机栈峰值。

- 34 组 C 主机回归及 Python 跨层检查通过，主机总脚本输出 `HOST_OK`，覆盖资源、服务生命周期、待办时序、刷新失败恢复和逐字节 OLD/NEW 条带。
- 使用本机 VS Code 附带的 Node 运行时执行网页测试，**402 项全部通过**。动态字体生成及固件读取的 **27 组 ABI/像素/重启/CRC 测试通过**。
- 本次重新从网页实现生成资源和参考像素，普通及固定屏幕各 25 组，共 **50 次网页/设备逐像素一致**。
- 七段循环对合法缩放 2/4/6/8/10、两个方向及长度 0～128 的 1,290 组绘线序列与原实现一致。分钟谓词另用超过 1.56 亿组时间对比较原实现，覆盖每秒边界、跨天、600/601 秒和 UINT32 回绕。
- 新增长期保留的时间边界测试；字体测试增加有效 CRC 下的非法偏移、截断记录、截断终止符、非法长度和跨 251 B 缓存边界情况。最终字体源码单独重编译回归通过。
- `git diff --check`、资源生成器检查通过；原暂存区二进制 diff 的 SHA-256 前后一致。

尚未进行物理屏幕耗时、BLE 空口压力和 OTA 安装验证。测试产物为应用 HEX/BIN，不含 SoftDevice、Bootloader 或 settings，也不是签名 OTA 包。

## 若还需要几 KiB 空间

当前应用区仍为 `[0x19000, 0x27000)`，只有 56 KiB。大资源迁出并不会自动扩展这个分区；`0x27000–0x29000` 的 **8 KiB 保留区**仍由链接布局及 Bootloader 的 `NRF_DFU_APP_DATA_AREA_SIZE=8192` 保护。

若后续需要明显大于本轮的空间收益，值得单独评估回收此区，并同步实际 Bootloader、DFU 接收/擦写边界、发布工具和回退兼容性。若完整回收，应用容量可由 56 KiB 变为 64 KiB；按本轮最终镜像计算，余量将为 **10,112 B**。这是容量扩展候选，**不是本轮已实现的代码压缩**，不能只改链接脚本便用于现有设备 OTA。

当前 1,920 B 余量仍未达到项目原有 4 KiB 工程预留目标。
