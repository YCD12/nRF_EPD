# 外置 UI 布局：P3 实施结果

## 本轮结果

P3 已把当前 800×480 产品的三种业务界面布局接入外置 `UIR1` 资源包：全屏日历、时钟日历分屏、全屏时钟。图片模式继续显示接收到的原始图像，不需要额外布局组件。

外置布局包含：

- 日期头、星期栏、月份网格的矩形和字体槽。
- 分屏上下边框、分隔线、右侧日历、左侧日期/温度/底栏位置。
- 分屏与全屏时钟画布、七段数字缩放、位数和局刷几何。
- 全屏时钟日期栏、设备信息栏、上下分隔线、农历/周数/节气底栏。
- 每个文本组最多三个固定字体槽：WQY9、WQY12、HELVB18。

当前页面没有独立位图图标，因此本版没有图标记录。七段数字由内部受限绘制器执行，其画布和缩放来自外置布局。日历单元格计算、文字格式化、分页裁剪和绘制算法仍保留在固件中。

## UIR1 格式

`ui.ers` 位于分区 6。ERS 头之后的 UIR1 载荷为 396 B：16 B 头和 19 条 20 B 组件记录。

头字段：

| 偏移 | 长度 | 内容 |
| --- | ---: | --- |
| 0 | 4 | `UIR1` magic，`0x31524955` |
| 4 | 2 | schema 版本 1 |
| 6 | 2 | 组件数 19 |
| 8 | 2 | 屏幕宽 800 |
| 10 | 2 | 屏幕高 480 |
| 12 | 2 | 记录长度 20 |
| 14 | 2 | flags，当前必须为 0 |

组件记录只允许已知 mode、ID 和 kind；字段为 mode、ID、kind、flags、三个字体槽、保留字节、`x/y/w/h` 及两个由组件类型限定的参数。没有脚本、函数地址、动态表达式或任意内存访问。

固件完整校验 ERS CRC、UIR1 版本、固定屏幕尺寸、记录顺序、组件类型、字体 ID、矩形边界和参数语义。时钟组件还校验：

- 画布横坐标和宽度按 8 像素对齐。
- 七段数字缩放为正偶数且不超过 10，位数固定为 2。
- HH:MM 跨度和高度必须放入画布。
- 局刷画布高度不超过 208，生成的局刷窗口继续受 512 B OLD 条带限制。

布局消费者见 `GUI/ui_resources.c`，默认包生成逻辑见 `tools/resource_pack.py`。

## 局刷一致性

全刷绘制和 `epd_clock_refresh` 局刷现在读取同一份时钟组件。分屏保留原来的 4×scale 居中约定，全屏使用实际 6×scale 绘制跨度，因此修改合法缩放值时不会依赖旧的 `TIME_CS` 常量判断。

全刷成功时会记录当前 UI package revision。局刷前重新比较 revision；revision 不同、布局无效或资源缺失时，旧状态立即失效并拒绝局刷，由服务层执行全刷。更新字体和布局后首次显示从全刷开始。

## Flash 与 RAM

构建继续使用 56 KiB 应用区 `[0x19000,0x27000)`，内部 FDS 和 Bootloader 边界不变。

| 构建 | Flash | 余量 | 静态 RAM | 含 2 KiB 栈后的 RAM 余量 |
| --- | ---: | ---: | ---: | ---: |
| P2 阶段应用固件 | 49,504 B | 7,840 B | 6,000 B | 7,608 B |
| P3 阶段应用固件 | **51,088 B** | **6,256 B** | **6,392 B** | **7,216 B** |

P3 的格式校验、组件缓存及 revision 局刷保护增加 1,584 B Flash 和 392 B 静态 RAM。相对外迁开始前 52,412 B 的基线，该阶段应用固件净减少 1,324 B，并保留超过 4 KiB 的预警余量。

该阶段应用固件 BIN SHA-256：`319E2FADB2C4C40DC0EFCC01E0ECCFACC2B173279817FA0568375205C00343F2`。当前体积和校验值以重新构建为准。

## 验证

- P3 阶段应用固件通过链接、Flash 与 RAM 预算检查。
- UIR1 测试覆盖 header、revision、ID/类型、字体槽、屏幕边界、时钟对齐及损坏拒绝。
- 修改布局 revision 后，已有局刷状态会失效。
- 六种完整 GUI 黄金图 hash 与 P2 一致。
- 分屏和全屏时钟 OLD/NEW 条带保持逐字节一致。
- 全量主机回归、生成器测试、网页资源协议、Keil XML 和 `git diff --check` 通过。

本轮未烧录设备，尚未执行真实外置 Flash 上传、局刷和官方 DFU 实机验证。

## 当前部署顺序

1. 烧录 `build.bat` 生成的完整 HEX。
2. 在网页主页选择资源目录并一键安装，设备有有效分区表时按表更新，空白时先写入分区表。
3. 回读核对资源；更新 UI 后首次显示必须全刷。

应用固件需要有效的日历、UI 和字体包。UI 包缺失或损坏时不会使用未校验坐标绘图；屏幕保持空白，BLE 与资源修复入口继续工作。

## 下一阶段
