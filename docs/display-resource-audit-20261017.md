**显示资源化检查记录（2026-10-17）**

**实施进度：** 以下是实施前的检查快照。现已完成 UIR2 的布局、样式、文案、字体度量外置，以及网页共用点阵预览；迁移和使用说明见 [UIR2 实施说明](display-resources-uir2.md)。图片直传与最小恢复提示仍按文中的边界保留。

检查口径：按本次明确的要求，网页负责设计设备的显示内容与样式，生成资源并发送到外置 Flash；设备读取资源，结合本地时间、温度、电压、待办状态绘制。今后在已有绘制能力内调整位置、颜色、间距、固定文案，应能通过更新资源生效。

结论：当前已完成多类数据的外置保存，但显示样式只完成部分参数化。最明显的遗漏是两种待办模式没有对应的 UI 布局记录。此前直接修改 `DrawTodo()` 坐标只能改变固件默认画面，没有补齐网页设计、资源保存和读取应用的链路。本次只做核查和记录，未重新应用温度位置修改，未修改固件、网页或资源协议。

检查覆盖网页默认数据、编辑器、二进制编码、资源保存与加载、GUI 绘制、网页示意图，以及图片直传路径。以下结论来自当前源码和本地主机验证，未回读设备 Flash 或验证实机画面。

**根本约束在 UIR1 格式**

`GUI/ui_resources.h` 的组件枚举没有待办组件；固件与网页编码器固定 19 条记录，仅覆盖模式 1/2/3。整个 UIR1 载荷为 `16 + 19×20 = 396` 字节。可变参数只有三个基础字体槽位、`x/y/width/height/value0/value1`，且 ID、模式、类型和 flags 必须符合内置表。

当前格式没有通用的固定文本/文本模板、动态数据绑定、颜色、状态样式、对齐锚点、组件显隐、裁剪规则或绘制层级字段。不能仅在网页 JSON 中加一个温度组件或颜色属性就完成下发。未知 JSON 属性还可能被编码器直接忽略，生成结果保持不变。

本地直接调用生产编码器的验证结果：

| 操作 | 结果 |
| --- | --- |
| 编码默认布局 | 396 字节；模式 1 为 3 个组件、模式 2 为 11 个、模式 3 为 5 个 |
| 增加第 20 个组件，模式设为待办 | 拒绝，组件数量不匹配 |
| 把既有组件改为模式 4 | 拒绝，ID/模式/类型/flags 不可改变 |
| flags 设为 1 | 拒绝 |
| 普通组件引用字体槽位 3 | 拒绝，仅允许 0–2 或无字体 |
| 给默认组件增加 `color/text/align/visible` 属性 | 编码成功，但字节与原载荷完全相同，属性未被保存 |

生产 `ui_resources.c` 的主机测试通过，确认当前加载器按上述固定格式工作。验证数据保存在本地 `output/display-resource-audit-20261017/schema-probe.json`。这验证的是现有格式边界，没有验证新格式或新增配置能力。

**需要保留清楚的边界**

时间、温度、电压是运行时数据，设备应继续本地取得；资源保存它们的显示位置、格式、字体和状态样式。历法计算、待办排序与调度、资源校验、字形解码、分页和局刷是执行逻辑，不因仍在 C 中就算样式未外置。屏幕像素格式、字节对齐、最大缓存等还需要固件约束。

`NO DATA` 提示当前使用内置的少量 5×7 图形，能在外置资源缺失时显示。建议把它作为明确的最小恢复例外保留；正常资源齐全时的同步提示、空态和报错文案则可纳入资源。

图片模式已经由网页完成排版和点阵生成，但 `cmd_write_block()` 将数据直接送到屏幕 `write_ram()`，没有写入外置资源分区，也没有保存可重新编辑的画面工程。这是“网页生成”已完成、“外置持久化”未实现的独立路径。[图片直传](../EPD/EPD_service.c#L1241)。此前评审明确单张图片即时传输不要求持久化，见 [2026-09-28 评审](project-design-memory-review-20260928.md#L11)；本次若将图片背景/图标模板也纳入统一样式资源，需要增加相应位图资源及重绘路径，不能把屏幕断电留图等同于外置 Flash 已保存。

**建议后续实施顺序**

1. 定义覆盖模式 1–5 的新版二进制 UI 资源。首先补齐待办标题、温度、正文区域、行/标记样式，再补齐现有日历和时钟的颜色、内部间距、文字模板等缺项。字体引用、度量及几何限制需要一并设计。
2. 网页编辑、生成和预览读取同一份布局与样式模型；设备读取其二进制结果。网页导入设备资源后也应能恢复该模型。同步改造网页编解码、默认源、命令行资源生成、固件加载及热应用，明确版本迁移。
3. 补齐渲染器对资源字段的应用，尤其是线宽/线高、显隐、对齐与裁剪；由资源里的正文矩形计算待办可用高度与最大显示数量，消除多处固定 `384` 的约定。
4. 用同一资源与同一运行时数据，核对网页和设备渲染结果；覆盖模式 1–5、负温度、长标题、日期标注、字号变化和局刷边界。验收包括只更新资源即可改变温度位置、状态颜色及线条粗细，且设备重启后保持设计。

涉及资源格式与绘制能力扩展时需要更新一次固件；扩展完成后，在已支持的样式字段范围内修改设计，应只需重新发送资源。
