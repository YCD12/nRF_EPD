# 当前功能的内置 Flash 优化（2026-10-05）

当前时钟、日历、待办两种布局、离线触发与过期保留、大字号及粗体/斜体功能均保留。相同发布配置下，应用 BIN 从 **55,860 B 降为 55,508 B**，净减少 **352 B（0.63%）**；56 KiB 应用分区余量从 **1,484 B 增至 1,836 B**。静态 RAM 不变。

| 指标 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 应用 Flash / BIN | 55,860 B | 55,508 B |
| 应用区余量 | 1,484 B | 1,836 B |
| ELF `size` 的 text（含只读元数据） | 55,648 B | 55,296 B |
| `.data` | 212 B | 212 B |
| `.bss` | 7,244 B | 7,244 B |
| 栈预留 | 2,048 B | 2,048 B |

测量使用 GCC 9.3.1、`-Os -g3 -flto --gc-sections`、默认固定屏幕及外置字体配置、日志关闭；应用区仍为 `[0x19000, 0x27000)`，容量 57,344 B。优化前重新构建，包含此前已经实现的 TODO v4 功能。ELF 调试信息和 RAM 缓冲大小没有计入 Flash 收益。

## 保留的改动

- `GUI/todo_items.c`：Unicode 控制/格式字符校验改为有序范围表；刷新快照通过完整结构比较，增加无填充编译断言；记录尾部未使用文本和保留字节共用零值检查。全部 65,536 个 BMP 码点与原判定一致，校验范围不变。
- `GUI/font_geometry.c/.h`：将头文件中的字体几何数组改为单一定义，避免字体管理、绘制和待办模块重复存储。87 个数据字节保持一致，GNU、模拟器、Keil 两目标及测试源列表同步登记。最终 ELF 的两张几何表及字号表均只有一个实体。
- `GUI/GUI.c`：固定字体方向构建中裁掉不会使用的反向文字裁剪分支；通用构建继续保留完整方向处理，占位框的竖线裁剪仍保留。
- `EPD/EPD_service.c`：发布构建不再执行只服务于耗时日志的三次时钟读取；启用 RTT 或 BLE 日志时继续测量。GPIO 配置直接遍历已有字段，省去临时引脚数组，保留全部引脚校验。
- `EPD/resource_protocol.c`：每个回复只写实际发送的字节，省去每包 244 B 全缓冲清零。原始读取发生部分 I/O 错误时仍只返回四字节错误头。

待办核心三项单独组合与基线对照减少 176 B；服务计时和 GPIO 两项组合减少 48 B。最终净收益以全部改动一起链接后的 352 B 为准，不能将不同 LTO 组合的局部收益直接相加。

## 排除的候选

字体参数改为指针在当前构建中没有减少 BIN；文字范围改为结构返回增加 16 B；字号限制改用乘法没有减少 BIN。因此只保留字体方向裁剪改动。

关闭仅调用一次函数的内联使 BIN 增加 44 B，关闭 IPA 常量传播增加 1,072 B，关闭 IPA 标量替换没有变化。关闭小函数内联虽减少 172 B，但同时增加静态 RAM，并影响整个固件的调用与执行路径，本轮保留原编译策略。全面禁止内联、同时关闭两种内联策略均导致应用区溢出，试验没有写入生产构建配置。

## 验证

- 通用及固定屏幕渲染与优化前参考逐字节一致，覆盖时钟/日历金图、OLD/NEW 条带、TODO 全屏/分屏、大字号和字形、负 bearing、裁剪、温度及提前/触发/划线保留阶段。
- 待办 v1–v4、时间边界、跨日、时间回退、队列和刷新失败重试通过；字体工具、资源重载、27 个浏览器生成字体包及 24 种字号/样式组合通过。
- 实际服务、两种 TODO 模式、RTT/BLE 四种日志组合通过；GPIO 判定与旧实现逐字节穷举及 100,000 组混合配置一致。
- 资源协议增加脏缓冲区测试，逐字节比较全部实际发送内容及长度，覆盖正常回复、短包、无效操作、CRC、BUSY 和部分 I/O 失败。
- 246 项网页测试全部通过；ARM 发布构建和 Flash 硬边界检查通过。

全量 C/Python 主机回归分段完成：Cygwin 脚本通过全部 C 和前段 Python 检查；最后四项 Python（动态字体、GUI、待办集成和服务流水线）改用本机 Python，解决 Cygwin 无法识别 Windows Node 路径的问题，输出 `HOST_TAIL_OK`。日志位于同级 `host-final.log`、`host-tail-final.log`、`pixels-final.log` 和 `node-final.log`。

尚未刷入设备，实机刷新与 OTA 安装仍需上板验证。优化没有改变协议、外置资源格式或应用/Bootloader 分区；设备功能版本沿用 `0x3D`。

## 下一步判断

字模、日历、UI、配置和待办持久化数据已经外置。当前剩余占用主要是执行代码：按最终函数入口和源码位置归属，EPD 约 19,202 B、GUI 约 18,142 B、Nordic SDK 约 9,444 B、主程序约 6,278 B。LTO 内联归于调用者，这些数字用于定位热点，不代表删除某模块后的净收益。

后续应优先分析显示排版及刷新/命令路径中的公共流程，并逐项对照实际 BIN 与像素/服务行为。若需要数 KiB 的新增功能空间，可以单独评估已有内置 8 KiB 保留区及 Bootloader 的数据保留/OTA 擦写规则；扩容应用区本身不会减少 BIN，不能只修改链接脚本便视为完成。
