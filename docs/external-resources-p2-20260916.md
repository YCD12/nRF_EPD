# 外置字体与日历资源迁移：P2 实施结果

## 本轮结果

P2 已接入三套字体和日历资源的生成、校验与运行时读取。正常业务固件不再编译旧的 `0x25` 字体上传状态机；字体与日历包统一由维护固件通过 `0x26` 资源协议写入。

本轮已外迁：

- 三套字模：WQY9、WQY12、HELVB18。
- 农历月份、日期、星期、生肖、天干、地支和二十四节气文字。
- 2025～2027 年农历年份表、春节日期表和节气计算表。
- 公历节日、农历节日及按规则计算的除夕、母亲节、父亲节、感恩节、清明节名称。
- 2026 年放假、调休表。

仍按后续阶段处理：EPD 配置、用户日历标注和各模式 UI 布局。内部 FDS 的 8 KiB 地址范围没有改动。

## 外置包

| 文件 | 分区 | 文件大小 | 载荷 | SHA-256 |
| --- | ---: | ---: | ---: | --- |
| `partition-table.ers` | 1 | 160 B | 128 B | `145BAE2B745D4A783DAE657440E6A121018ABCE966E98355925DEB4E3173582D` |
| `calendar.ers` | 5 | 1,468 B | 1,436 B | `A3BDA2C923CC750DFF967578C2C1A80BBF99B5C9D00EFBE32A75CDCF7A10CB2D` |
| `fonts.ers` | 7 | 9,622 B | 9,590 B | `F206F9DFF7541225142E88FA58CE6EB089717C4B8641FF635B1B0E7F1DCF6812` |

`CAL1` 包有 16 个带固定条目宽度的 section。包头声明年份范围和调休年份，固件同时校验 magic、版本、section 数量、ID 顺序、条目宽度、数量、偏移、边界以及整个 ERS 载荷 CRC。日历条目按需从外置 Flash 读取，RAM 只保存 section 索引。

`FPK1` 包包含三个目录项和连续字模数据。生成器先校验每套 u8g2 字体结构和界面所需字形，再写入长度及 CRC；固件挂载时校验 ERS CRC、FPK 目录、范围、重叠、每套字体 CRC 和 u8g2 结构。

生成命令：

```sh
python tools/resource_pack.py --check --fonts --calendar --revision 1 --output output/external-resources-p2
```

默认日历算法包覆盖 2025～2027 年。固件从 `CAL1` 包头和 section 元数据读取年份范围与条目数；更换年度放假表或扩展计算年份只需生成新 revision，不需要重新编译固件。

`--calendar-data calendar.json` 可覆盖 `year_min`、`year_max`、`holiday_year` 和以下整数数组：`holidays`、`lunar_month_days`、`solar_new_year`、`jieqi_year_bits`。只更新放假年度时必须同时提供 `holidays`；修改计算年份范围时必须同时提供三张计算表。生成器会校验条数、基准年份和整数宽度。

## 启动与恢复行为

- 存在有效的新分区表时，只接受通过完整校验的新字体包；损坏或缺失时不读取旧地址中的随机数据。
- 没有新分区表时，字体读取仍兼容原 FST2/FST3，便于迁移前设备继续工作。
- 日历包缺失、版本不匹配或 CRC 错误时，日历计算返回无效，文字接口返回占位内容；BLE、外置 Flash 驱动和维护入口仍可用。
- 正常固件对资源写入保持只读，并已移除旧字体上传链路。维护固件保留 `MIG1` 会话和单份资源写入。
- 每个分区仍只有一份数据。提交中断后该包保持无效，需要重新上传，不会切换到镜像副本。

## Flash 与 RAM

构建使用 ARM GCC 9.3.1、`-Os`、LTO 和 56 KiB 发布链接区域 `[0x19000,0x27000)`。

| 构建 | Flash | 56 KiB 余量 | 静态 RAM | 含 2 KiB 栈后的 RAM 余量 |
| --- | ---: | ---: | ---: | ---: |
| P1 正常固件 | 53,884 B | 3,460 B | 6,908 B | 6,696 B |
| P2 正常固件 | **49,504 B** | **7,840 B** | **6,000 B** | **7,608 B** |
| P2 维护固件 | 30,964 B | 26,380 B | 3,612 B | 9,996 B |

P2 正常固件相对 P1 减少 4,380 B Flash 和 908 B 静态 RAM。相对迁移工作开始前的 52,412 B 基线，净减少 2,908 B Flash。正常固件 BIN SHA-256 为 `16939F619F307F1F7C48479338AAB33C54701F48757624456492CECFD0F132B2`。

应用链接区、内部 FDS `[0x27000,0x29000)`、Bootloader 起点 `0x29000` 和官方 Nordic Secure DFU 方式均未改动；外置 Flash 没有固件 A/B 分区。

## 验证

- 正常固件和维护固件均通过链接及 Flash/RAM 预算检查。
- 全量主机回归通过，包括资源掉电中断、CRC、越界、字体结构、农历日期、节气、节日、调休、完整 GUI 黄金图、BLE 生命周期和网页传输。
- 六种 GUI 黄金图 hash 与迁移前一致。
- `resource_pack.py --check`、Keil 工程 XML、网页 JavaScript 语法、网页协议测试和 `git diff --check` 均通过。
- 正常 ELF 中不再包含 `cmd_font_store`、`font_task_*`、`font_stream_*` 或旧字体写入/提交符号。

本轮没有烧录设备，也没有执行真实 SPI 掉电、真实 BLE 上传或 DFU 实机验证。

## 建议部署顺序

1. 先通过官方 DFU 安装维护固件。
2. 如需保留旧外置字模，先导出整片外置 Flash。
3. 进入 `MIG1`，依次上传分区表、`calendar.ers` 和 `fonts.ers`，逐包提交并回读校验。
4. 资源校验成功后，通过官方 DFU 安装 P2 正常业务固件。
5. 实机检查三种显示模式、2025～2027 年边界、节气、节日、调休标记及断电重传。

写入新分区表后不要再启动会按旧 FST2/FST3 地址写字体的旧业务固件。迁移期间应停留在维护固件，直到新资源写入并验证完成。

## 下一阶段

P3 应迁移 UI 布局：定义坐标、字号、字体槽、图标位置、全刷/局刷区域和布局 revision，并让布局 revision 变化时使 OLD/NEW 局刷缓存失效、先执行一次全刷。P3 完成后再迁移 EPD 配置与用户日历标注；内部 8 KiB FDS 仍按当前要求保留到实机迁移验证完成。
