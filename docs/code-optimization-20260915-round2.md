# 第二轮代码优化实施记录

本轮按第二次代码审查列出的顺序，完成 GPIO／SPI 生命周期修复、标注回读续传、标注上传中断恢复、GUI 刷新请求可靠调度、源码职责拆分，以及当前 800×480 黑白红产品配置的 Flash 裁剪。设备报告版本由 `0x30` 升至 `0x31`。

## 功能修复

1. **GPIO／SPI 引用对称释放**
   - BLE 连接显式记录自身持有的引用；断开时不再依赖 `epd` 指针是否为空。
   - 刷新中断开时只释放连接引用，刷新收尾继续释放刷新引用。
   - `EPD_GPIO_Uninit()` 增加零值保护，避免无符号引用计数下溢。

2. **标注回读支持 BLE 背压续传**
   - 新增 `calendar_annotations_tx` 状态机，保存回读偏移和等待状态。
   - `NRF_ERROR_RESOURCES` 时保留当前位置，收到 `BLE_GATTS_EVT_HVN_TX_COMPLETE` 后继续发送。
   - 断开或其他不可恢复的通知错误会取消任务，避免主循环无期限重试。
   - 回读期间拒绝修改标注，保证多包数据来自同一版本。

3. **标注上传中断恢复**
   - 新增接收活动查询和取消接口；连接断开或 10 秒无后续分片时，由主循环恢复最近一次已保存快照。
   - 取消标志在恢复完成前保持有效，避免重连后的新上传被旧取消请求覆盖。
   - 固件构建对一次标注记录查询使用临界区，避免查询过程中 live 缓冲被异步改写。

4. **GUI 刷新请求不再因调度队列满而丢失**
   - 新增可重试、可合并的显示请求状态；只在成功进入 worker 后消费请求。
   - 调度失败时保留 pending，由主循环继续提交；刷新期间到达的新请求保留最新时间戳，并在当前刷新结束后继续。
   - 标注、字体、模式切换、校时和定时刷新统一走同一请求入口。

## 源码结构整理

- `epd_protocol.h` 集中维护命令和响应 ID，服务、策略和测试不再重复硬编码协议值。
- `storage_retry.c` 独立负责 FDS 注册、GC 状态和重试推进；配置与标注存储不再通过配置模块隐式推进共享 GC。
- `calendar_annotations_tx.c` 独立负责多包通知状态，BLE 服务只保留协议适配。
- `epd_display_queue.h` 集中显示请求的合并、入队失败恢复和执行状态。
- GCC 与 Keil 两个目标均加入新模块、相同的产品裁剪宏和临界区配置；Keil 的 `flash_softdevice` 目标补齐 `font_transfer.c`。
- `GUI.c` 移除未使用的硬件驱动依赖；固定文本改用直接输出，整数只格式化一次，固件 GUI 路径不再链接通用 `printf` 格式化入口。

## Flash 与 RAM 结果

测量使用 ARM GCC 9.3.1、`-Os -flto`、发布链接脚本，应用区大小为 57,344 字节，RAM 应用区为 15,656 字节，栈保留 2,048 字节。数据不包含 SoftDevice 和 bootloader。

| 阶段 | 应用 Flash | 静态 RAM | Flash 余量 | 含栈 RAM 余量 |
| --- | ---: | ---: | ---: | ---: |
| 最初基线 | 52,572 | 11,644 | 4,772 | 1,964 |
| 第一轮优化后／本轮处理前 | 53,136 | 6,800 | 4,208 | 6,808 |
| 本轮最终结果 | **52,992** | **6,776** | **4,352** | **6,832** |

相对本轮处理前，Flash 减少 144 字节，静态 RAM 减少 24 字节；相对最初基线，Flash 增加 420 字节，静态 RAM 减少 4,868 字节。Flash 的净变化包含本轮新增的可靠性状态机和恢复路径，因此不能把单独裁剪实验的收益直接当作最终收益。

当前固件固定为 800×480、字体方向 0、黑白红绘制路径。对应宏均可在构建参数中关闭，以恢复通用尺寸、旋转字体或其他颜色面板支持。Keil 的堆保留设为 0；GUI 使用静态分页缓冲，栈仍保留 2 KiB。

## 验证与产物

- 27 个 C 主机测试程序、13 个 Node 子测试、3 个 Python 测试全部通过。
- 通用绘图和产品固定配置各自通过完整画面 golden hash、时钟 OLD／NEW 字节级对比和失败回退测试。
- ARM GCC 发布构建通过；Keil 工程 XML 和两个目标的源文件／宏配置通过静态校验。
- OTA 包、settings HEX 和包含 SoftDevice、bootloader、应用的完整 HEX 均已生成。

发布产物位于 `output/implementation/release-build/`：

- `nrf52811_xxaa-ota.zip`
- `nrf52811_xxaa-full.hex`
- `nrf52811_xxaa.hex`、`.bin`、`.out`、`.map`

应用 BIN 为 52,992 字节，应用 CRC 为 `0x41FC0297`。BIN SHA-256 为 `4EB99EB0D13253CF93E053A758C801BCB541289452379904ADF90221C49229CB`；OTA ZIP SHA-256 为 `D257E43B31BD41A9115C5BC19FED58B1ADC968B7171BC88D7D2B64C2E9FD2598`。
