# 外置字库优化实施记录（2026-09-14）

基线为已合入 `20260913-font-store-update.patch` 和 `20260913-font-store-fix.patch` 的暂存区版本。此次改动在工作区完成，未提交、未烧录硬件。固件应用协议版本为 `0x2F`，网页版本为 `2.0.14`。

## 已实施

- 修复 u8g2 恰好读到字节边界时的额外读取；读取错误在一次查询期间保持有效，宽度查询不再将解码失败报告为成功，绘制失败使用占位符。ASCII/Unicode 记录检查完整长度、最小长度及偏移前进，避免损坏字库造成死循环。
- 将 BLE 字库传输抽出到 `EPD/font_transfer.c`，状态集中到 `font_transfer_state_t`。任务位图、FIFO 和 ACK 队列的共享元数据使用短临界区；Flash 写入和通知调用在临界区外执行。控制缓冲区直到命令执行结束才释放，FIFO 头包直到写入完成才出队。
- 修复通知资源不足时 TX_COMPLETE 与等待标记交错造成的唤醒丢失；保留正在重试的 ACK，处理列表请求重入、调度器满和断连取消。
- 将更新状态压缩为 52 字节。合并 CRC32 实现，取消输入流重复的分槽 CRC 和旧目录副本，以顺序擦除游标替代位图；保留输入整包 CRC、实际 Flash 分槽回读 CRC 和提交前结构检查。
- SPI 读取只发送 4 字节命令头，后续时钟由显式配置的 `ORC=0xFF` 补齐；去掉随读取长度增长的临时 TX 缓冲区。
- C 端共享三个字体槽的几何定义；Python 和网页测试验证现有 BIN 与槽位定义一致。网页在 BEGIN 前检查字体头，整包长度和 CRC 均未变化时跳过写入。
- 更新限频和空闲超时使用与 Unix 校时值无关的秒计数。保留旧 PACK_DATA 协议、三包 FIFO 和三槽整包提交。

## FST3 存储和迁移

数据起点保持 `0x1000`。第一目录扇区仍为 `0x00000`，FST3 首个记录位于 `0x40`；新增第二目录扇区位于 `0x7F000`。数据容量由 508 KiB 调整为 504 KiB。

更新先写不与当前字库重叠的空闲区域，验证后写入非活动目录，最后写提交标记。启动按代次和目录 CRC 选择已提交目录。空间分配先尝试尾部，再复用前部空闲扇区；无足够连续暂存空间时返回 `NO_SPACE=6`，当前字库保持有效。504 KiB 是空设备可装载上限，不是任意旧包都可原子替换的保证。

FST2 旧目录仍可读取。首次成功更新向第一目录扇区剩余空间追加 FST3 记录，不擦除旧目录，也不覆盖可能位于最后一个扇区的旧字体。首次迁移中断后可跳过不完整记录重试；后续复用旧数据前废弃 FST2 回退标记。为支持这些追加记录，启动固定扫描 64 个目录位置，读取约 4 KiB 元数据，然后每个有效槽只读 23 字节字体头；FST2 启动另做全量校验。

目录发布发生 I/O 错误时，设备无法断定提交标记是否已落盘，因此锁止后续更新直到重启重新加载目录。网页提示重启并重新读取字库列表。旧固件不理解 FST3，降级时需使用旧格式工具重新写入字库。

固件、网页和打包工具明确接受项目现有的单 Unicode 块字体（或无 Unicode 记录）。通用多块 u8g2 BIN 会被拒绝，需要先转换成受支持格式；运行时查询仍保留独立边界保护。

## 资源实测

相同 nRF52811 / S112 / GCC 9.3.1、`-Os -flto` 构建，单位为字节：

| 项目 | 基线 | 优化后 | 变化 |
|---|---:|---:|---:|
| 应用 Flash（含初始化数据） | 52,068 | 52,572 | +504 |
| 应用 Flash 剩余 | 5,276 | 4,772 | -504 |
| 静态 RAM | 11,692 | 11,644 | -48 |
| 预留栈 | 2,048 | 2,048 | 0 |
| 扣除静态 RAM 和预留栈后的余量 | 1,916 | 1,964 | +48 |

最终 `size`：`text=52280 data=292 bss=11352`。新增掉电保护、并发同步与边界检查带来的代码开销超过此次去重收益，因此 Flash 是净增加，不能宣称整体缩小。SPI 最大读操作去掉 251 字节临时 TX 数据；这是局部缓冲区变化，不代表已测得整机栈峰值下降 251 字节。

未缩小 FIFO、u8g2 缓存或显示旧帧缓存；这些修改需要实际吞吐、局刷效果和栈高水位数据支持。

## 验证

- `tests/run_host_tests.sh` 全部通过：22 个 C 测试程序、13 个 Node 测试、3 个 Python 测试。
- 新测试覆盖字节末尾解码、截断字形、零长度记录和索引偏移；NOR mock 使用完整 512 KiB 地址空间及只能从 1 写成 0 的约束。
- 掉电测试对两个目录切换方向和 FST2 尾扇区迁移分别注入写入/擦除中断，覆盖目录及提交标记的字节前缀；重启后验证读到完整旧包或新包。另覆盖首次迁移重试、140 次循环复用、504 KiB 满容量及空间不足、空包清除。
- BLE 测试在 Flash 写入、临界区退出和通知调用期间注入收包/发送完成事件，覆盖 FIFO 所有权、控制缓冲区生命周期、ACK 重试、调度器满及列表重入。
- 实际 SPI 驱动的主机测试验证 ORC 配置、4 字节 TX、503 字节读取分为 251+251+1 字节以及地址边界。
- ARM 编译和链接成功；OTA 签名包、带备份页的 settings v2 和合并固件生成成功；`git diff --check` 通过。

上述掉电和 IRQ 验证基于主机模型。硬件上的连续上传、断连恢复、物理断电、SPI 读回和栈高水位仍需上板验证。
