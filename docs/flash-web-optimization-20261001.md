# 外置 Flash 与网页优化实现（2026-10-01）

对应 [分析记录](flash-web-performance-review-20260930.md)。本轮实现传输粒度、Flash 页写入、字体读取缓存、选择性资源重载和网页任务生命周期优化。固件版本 `0x39`，网页版本 `2.0.22`；网页仍支持 `0x38`，资源能力不足时回退到 20 B 请求和旧 DATA 语义。

## 已实现

- 资源协议按实际特征值长度扩包，最大 244 B；数据负载最多 237 B，READ 最多 240 B。保留单槽停等、相同 token/载荷重试及设备端重复响应缓存。
- 新增 `BUFFERED_DATA`，用 256 B RAM 按物理页合并；ACK 分别报告 accepted 和 durable。首个数据页为 224 B，尾页在最终 DATA 回复前写完；COMMIT 仍完整 CRC 校验、回读包头并最后提交有效标记。旧 DATA 仍是同步落盘确认，不能与新 DATA 在同一事务内混用。
- 外置 Flash 从 legacy SPI API 改为直接使用 `nrfx_spim`，保持 SPI1、原引脚、8 MHz、同步调用及 ORC；单次可传完整 4+256 B 页，避免旧 API 的 uint8 长度限制。
- WIP 首次延时 50 µs，随后按 100/200/400/800 µs 退避，最长 1 ms；保留 WEL、WIP、超时、喂狗和按需扇区擦除。
- CRC 扫描块从 64 B 改为 256 B；JEDEC 探测在连接会话内复用，协议重置或 I/O 错误后重新探测。
- 字体块缓存改为 256 B；16 项字形定位缓存按 reader/context/length/revision 区分，保留三个字体源的定位结果，切字体不再丢失全部结果。读取错误仍清理缓存并重试。
- 利用 changed mask 仅失效受影响的字体/日历/UI 消费者；改分区表则全部失效。资源应用仍检查所有必需消费者。GUI 复用一个静态绘图上下文，避免全刷调用链和局刷调用链同时在栈上保留大缓存；绘图入口与已有静态页缓冲一样，仅可串行调用。
- 网页资源、传图、标注、模式、初始化和迁移导出共用任务所有权与 GATT 入口。断线取消 waiter 和状态条；过期任务不能继续发送到新连接或释放新任务的锁。
- 图片状态严格匹配会话、预期块数和 active；每层和每轮重试使用新 session，短回复被忽略，RESET 失败立即停止。重试仍是整层从零开始，不是跨断连续传。
- 新增完整 CRC 元数据查询，按长度和 CRC 跳过相同资源，保留“强制重写”。仅改 UI 不再重复传字体；既有分区表、个人配置、标注按原策略保留。I/O、忙、CRC、ABI 错误分别显示，不把传输异常当作“未安装”。
- 新固件 CLEAR/REFRESH 增加 `0xAB` token 确认；网页等待驱动刷新返回后再结束操作。通知拥塞会重试，BUSY 超时/初始化失败不报告成功。旧固件仍显示“指令已发送”。资源进度使用 durable 字节数，随后显示校验提交和应用阶段。

协议布局与兼容规则见 [BLE 协议](ble-protocol.md)。同内容不同 revision 默认跳过；若需要同步指定 revision，可强制重写。

## 可复现的改进

下表是数据请求数，假定协商 ATT MTU 247，即特征值可用 244 B；不包括 STATUS、BEGIN、擦除、COMMIT 和应用耗时。

| 默认资源 | payload | 原 DATA 请求数 | 优化后 |
| --- | ---: | ---: | ---: |
| 日历 | 1,436 B | 111 | 7 |
| UI | 396 B | 31 | 2 |
| 字体 | 9,590 B | 738 | 41 |

按默认字体包和页边界推算，数据 PAGE PROGRAM 从 772 次降为 38 次，未计包头失效及提交命令。测试另验证 5,000 B 跨扇区 payload 使用 20 次数据页写入，重复片段不会增加编程次数。SPI mock 验证整页实际为一次 260 B 事务。

同一 `tests/test_gui_render.c`、时间/布局/字体下，修改前索引快照与最终源码分别编译执行，结果如下。统计的是字体 source 读取次数，不是实机耗时。

| 模式 | 颜色 | 修改前 | 修改后 | 减少 |
| --- | --- | ---: | ---: | ---: |
| 日历 | 黑白 | 5,911 | 4,299 | 27.3% |
| 日历 | 三色 | 11,221 | 8,160 | 27.3% |
| 时钟+日历 | 黑白 | 5,437 | 4,053 | 25.5% |
| 时钟+日历 | 三色 | 10,686 | 7,955 | 25.6% |
| 全屏时钟 | 黑白 | 872 | 545 | 37.5% |
| 全屏时钟 | 三色 | 1,409 | 865 | 38.6% |

六组 golden hash 保持一致；额外通过可变布局、缺失字体、时钟 OLD/NEW 窗口逐字节对比。只更新 UI 的资源重载测试确认字体区读取次数不增加；修改字体或分区表仍重新读取。

## 发布构建与内存

比较基线为本轮开始前的 Git 索引快照，包含工作区此前已经暂存的修改。两次构建使用同一个 GCC 9.3.1、`Makefile.nRF52_linux` 默认发布配置和 `-Os -flto`，输出分别位于 `output/optimization-20261001/baseline/`、`current/`。

| 指标 | 修改前 | 修改后 | 增量 |
| --- | ---: | ---: | ---: |
| 应用 BIN | 49,816 B | 50,756 B | +940 B |
| `.data + .bss` | 5,316 B | 6,912 B | +1,596 B |
| 栈预留 | 2,048 B | 2,048 B | 0 |

应用区预算 57,344 B，当前余量 6,588 B。RAM 段间有额外对齐；最终 map 中 `__HeapLimit=0x20003DE0`、`__StackLimit=0x20005800`，静态分配与预留栈之间仍有 6,688 B 空间。

反汇编核对函数自身栈帧（包含保存寄存器）：`epd_gui_update` 从 672 B 降到 272 B，`DrawGUI_ClockOnly` 从 520 B 降到 72 B。这不是完整调用链峰值或实机中断叠加高水位。新增 RAM 主要用于三个较大的资源报文缓存、页聚合缓冲和共享 GUI 上下文。

构建产物：`output/optimization-20261001/current/nrf52811_xxaa.{bin,hex,out,map}`。本轮只构建应用，没有生成或刷写 DFU 升级包。

## 实机验收与保留项

尚未连接实机，不能把请求数或读取次数的比例当作吞吐提升倍数。上板应分别记录 BLE DATA、擦除/编程、CRC、资源应用、GUI 绘制和面板 BUSY 耗时，并检查中断叠加后的栈高水位。

优先验证 MTU 23/247、首次空白安装、仅改 UI、同资源再次安装、传输中断后重传、清屏与图片刷新完成确认。重点检查完整 260 B SPIM 事务在实际 MCU/Flash 上运行，以及长擦除期间 BLE 和看门狗表现。

本轮保留单槽停等和同步 Flash 等待；小窗口 credit、异步擦写、32/64 KiB 块擦除、配置日志式记录属于后续按实测决定的结构性改动。SET_MODE 确认仍表示请求被接受，LEAVE 确认表示资源完成应用，二者后续自动 GUI 刷新由现有调度器完成。
