# BLE 协议说明

> **当前主线范围说明:**
> - 本文档描述的是当前 `nRF52811` 主线工程实际使用的 BLE 协议行为
> - 当前主线默认验证重点为 `UC8179 / 7.5寸 / 800x480 / 三色`
> - 若后续扩展到其他屏幕型号或驱动组合，协议层兼容行为可继续沿用，但具体显示结果仍需结合对应固件适配验证

本文档记录当前网页端与 MCU 之间实际使用的 BLE 命令、通知格式，以及与固件版本相关的兼容行为。

## 固件版本

- `0x20` 及以下：不支持静默校时。
- `0x21` 及以上：支持 `EPD_CMD_SYNC_TIME_SILENT (0x23)`。
- `0x28` 及以上：支持 `EPD_CMD_SET_ANNOTATIONS (0x24)` 日历短标签写入。
- `0x29` 及以上：支持同命令 `op=0x02` 回读，通知类型 `0xA2`。
- `0x2A` 及以上：记录 flags bit5 选择位置（0=日期下方，1=右上角）。
- `0x2B` 及以上：右上角与日期下方使用相同的 9 字节标签上限。
- `0x2D` 及以上：支持 `EPD_CMD_FONT_STORE (0x25)` 动态外置字库包管理。
- `0x2E` 及以上：支持外置字库滑动窗口高速传输。

网页端连接后会先读取 APP 版本特征值，再决定是否启用静默校时。

## 连接初始化顺序

当前网页端连接后的典型顺序如下：

1. 连接 BLE 服务并打开通知。
2. 读取 APP 版本特征。
3. 发送 `EPD_CMD_INIT (0x01)`。
4. MCU 初始化完成后通过通知上报：
   - `mtu=<n>`
   - `t=<unix_timestamp>`
   - `v=<mV>`
5. 若固件版本 `>= 0x21`，网页端自动发送 `EPD_CMD_SYNC_TIME_SILENT (0x23)`。

注意：

- `v=<mV>` 电压上报依赖 `EPD_CMD_INIT`，不是“仅建立连接就一定会上报”。
- 旧固件会跳过自动静默校时，避免连接瞬间刷屏。

## 命令表

### `0x01` `EPD_CMD_INIT`

用途：

- 初始化屏幕驱动。
- 回传当前 MTU、当前时间和当前电压。

### `0x20` `EPD_CMD_SET_TIME`

载荷格式：

- `[1..4]` Unix 时间戳，大端序，单位秒，UTC。
- `[5]` 时区偏移，单位小时，`int8_t`，可选，默认 `+8`。
- `[6]` 显示模式，可选。

兼容语义：

- 无论是否携带模式参数，都会立即触发一次刷新。
- 若携带模式参数，则会先切换模式，再立即刷新。

### `0x21` `EPD_CMD_SET_WEEK_START`

载荷格式：

- `[1]` 周起始日，`0=Sunday`，`1=Monday`。

### `0x22` `EPD_CMD_SET_MODE`

用途：

- 切换显示模式。

模式值：

- `0` 图片模式
- `1` 日历模式
- `2` 时钟模式
- `3` 时钟+日历模式

### `0x23` `EPD_CMD_SYNC_TIME_SILENT`

支持版本：

- 固件 `>= 0x21`

载荷格式：

- `[1..4]` Unix 时间戳，大端序，单位秒，UTC。
- `[5]` 时区偏移，单位小时，`int8_t`，可选，默认 `+8`。

行为：

- 只更新时间，不立即触发屏幕刷新。
- 用于网页端连接后的自动静默校时。

### `0x24` `EPD_CMD_SET_ANNOTATIONS`

支持版本：

- 固件 `>= 0x28`

用途：

- 写入或清除日历格子上的用户短标签。数据存在内部 FDS，最多 64 条。
- 不支持旧版外置 Flash 的缺字点阵表（header 保留字节必须为 0）。

载荷：

- `[1] = 0x01`：清除全部标注。
- `[1] = 0x02`：回读当前标注（固件 `>= 0x29`）。MCU 用 `0xA2` 通知按片推送整表。
- `[1] = 0x00`：顺序分片写入。
  - `[2..3]` 偏移，小端。
  - `[4..5]` 总长度，小端。
  - `[6..]` 本片数据。
- 第一片偏移必须为 0，后续偏移必须连续。最后一片写满总长度后校验并落盘。
- 二进制：16 字节 `ANNO` 头 + `count × 16` 字节记录。记录按年月日升序。
- flags：bit0=present，bits1–2=字号，bits3–4=颜色，bit5=位置（0 日期下方 / 1 右上角）。
- 日期下方和右上角标签都最多 9 字节 UTF-8。英文/数字使用现有文泉驿字形，不另加字库。

行为：

- 紧急命令，绕过 2 槽显示队列。
- 写入成功且当前不是图片模式时，强制全刷日历。
- 日期下方：非空标签覆盖节日/农历，并在右上角打红点。右上角：节日/农历保留，短标签画在格子右上角。空标签只打红点。

### `0x25` `EPD_CMD_FONT_STORE`

支持版本：

- 固件 `>= 0x2D`

动态槽位：

- `slot=0`：WQY9，固定 12×12 字体几何。
- `slot=1`：WQY12，固定 16×16 字体几何。
- `slot=2`：HELVB18，固定数字字体几何。
- 三个字库按上述顺序连续存储，只有偏移和长度动态变化。
- 固件 `>=0x2F` 使用 FST3 双目录：主目录在首个 4KiB 扇区的 `0x00040`，备用目录在 `0x7F000` 扇区。数据仍从 `0x01000` 开始，数据区容量为 `0x7E000`（504KiB）；单次更新还需要不与当前包重叠的暂存空间。`0x2E` 固件的 FST2 数据区容量为 `0x7F000`。

载荷：

- `op=0x00`：读取列表。MCU 发送 3 个 `0xA3` 通知。
- `op=0x06`：开始全量包上传，格式 `[op, total:u32LE, pack_crc32:u32LE, (length:u32LE, crc32:u32LE) × 3]`。
- `op=0x07`：写入全量包，格式 `[op, offset:u32LE, data...]`。数据必须从偏移 0 顺序发送。
- `op=0x08`：提交全量包，格式 `[op]`。设备按三个长度计算动态偏移，校验包 CRC、单字库 CRC 和固定字体头参数后写入 Manifest。
- `op=0x09`：取消当前全量包，格式 `[op]`。
- `op=0x0A`：滑动窗口数据包，格式 `[op, seq:u16LE, offset:u32LE, data..., crc16:u16LE]`。CRC16 覆盖 `op` 到 `data`，数据包使用 Write Without Response；设备只接受顺序包并放入 3 包 FIFO。
- 删除某个字库时，全量包中对应槽的 `length=0、crc32=0`；网页端不再发送独立删除命令。

通知：

- `0xA3`：`[0xA3, slot, present, length:u32LE, crc32:u32LE]`。
- `0xA4`：`[0xA4, op, status, slot]`。状态：`0=成功、1=参数/格式错误、2=忙、3=CRC 错误、4=未找到、5=I/O 错误、6=无足够暂存空间`；`6` 从固件 `0x2F` 起支持，返回时旧字库保持有效。
- `0xA5`：`[0xA5, next_seq:u16LE, next_offset:u32LE, credit:u8, status:u8]`，表示累计确认位置和 FIFO 剩余容量。正常传输每 3 包确认一次；发生 CRC、顺序或 FIFO 错误后，设备进入逐包确认恢复阶段，连续恢复一个完整批次后再回到批量确认。

兼容固件的 `op=0x06`、每个 `op=0x07` 分片、`op=0x08/0x09` 都会返回一个 `0xA4` 应答。网页端必须等待当前分片的 `status=0` 后再发送下一片；GATT 写入成功本身不代表外置 Flash 已完成写入。当前固件的 `0xA4` 通过调度器异步发送，BLE 写入事件不会因通知资源不足而延时重试。

固件 `>=0x2E` 时，网页端使用 `op=0x0A` 高速通道：每窗口最多 3 包，按序提交无响应写入并等待累计 ACK。设备用 `0xA5` 累计确认，Flash 写入在专用 FIFO 后台顺序执行。`BEGIN/COMMIT/ABORT` 仍使用带响应写入；数据包使用无响应写入。窗口 ACK 超时最多重发 3 次，设备对重复序号只回复累计位置；无进展或 CRC/顺序错误也有重试上限。

共享命令特征保持原有 `SEC_OPEN` 免配对方式，`INIT`、校时和字库操作均不强制配对。CRC 用于传输完整性校验，不提供身份认证。若将来需要限制写入者，应单独设计认证及绑定生命周期，不能只给共享特征加 `SEC_JUST_WORKS`。字库 `BEGIN` 包总长为 34 字节，因此网页在启动事务前检查可用 BLE 数据长度至少为 34；断连会使旧连接排队的字库操作失效。

字库全量提交后的显示刷新会延迟执行。字库列表只读取 MCU 已缓存的 Manifest 信息，不会重新扫描整个字体数据。

存储行为：

- 每次更新是三个字库的全量包；新包写入与当前包不重叠的空闲扇区，设备不搬移已发布的字库。保留三包 FIFO 和旧 `op=0x07` 兼容路径。
- 数据按 4KB 扇区惰性擦除，避免开始上传时一次性长时间阻塞 BLE。
- `BEGIN` 先尝试尾部追加，再寻找前方可循环复用的空闲区；都放不下则返回 `6`，不会自动覆盖旧包。`COMMIT` 校验输入整包 CRC、实际 Flash 各槽 CRC、字体头和记录结构。输入不再重复维护分槽 CRC。
- 字库限定为当前资源使用的单 Unicode 块格式（`FFFF` 标记、首偏移 4），也接受明确的无 Unicode 标记；提交时拒绝多块格式。运行时对索引、记录长度和解码边界另做检查，异常字形使用占位符。
- Manifest 先写主体及 READY 状态并回读，再最后写 COMMIT 标记并回读。只改写非当前目录所在扇区；冷启动依据有效目录的代次选择新包。提交前掉电保留旧包；提交标记完整落盘后重启使用新包，不会发布混合包。
- FST3 启动扫描主目录区 63 个固定记录位置及备用目录，再读已选包的各槽固定头；不会全量读取 FST3 字体数据。旧 FST2 则先做完整 CRC 和结构验证。FST2 首次提交在原目录之后的空白记录位置追加 FST3，不擦原目录，因此即使旧包使用了最后一个数据扇区也可安全迁移。迁移中断后可使用后续空白位置重试。
- 第一次迁移完成后，下一次更新在复用数据前清除旧 FST2 的有效状态。升级不会要求用户先清空字库；降级到旧固件需要重新准备旧格式字库，旧固件不能读取 FST3。
- BLE 断开或 ABORT 只丢弃未提交事务，已发布目录不变。如果目录提交发生 I/O 错误，可能无法确定提交标记是否已落盘；设备阻止继续覆盖，需重启并重新读取列表确定最终版本后再更新。
- BEGIN 限频和事务空闲超时使用与校时无关的运行秒数；更新间隔仍为 60 秒，空闲超时仍为 30 秒。网页在 BEGIN 前检查字体头，完整包与列表长度/CRC 相同时跳过重写。
- 设备不保留内置字库；槽位缺失或损坏时始终使用固定宽度占位符，不回退到 MCU 内置字体。

## 通知格式

### `mtu=<n>`

- MCU 返回当前链路的可用 MTU。

### `t=<unix_timestamp>`

- MCU 返回当前时间戳。

### `0xA2` 日历短标签分片

- `[0] = 0xA2`
- `[1..2]` 本片偏移，小端。
- `[3..4]` 总长度，小端。
- `[5..]` 本片数据。
- 网页按偏移拼成完整 `ANNO` 表后填入编辑列表。

### `v=<mV>`

- MCU 返回当前电池电压，单位毫伏。
- 网页端会在“设备电压”区域显示该值。
- 当电压 `<= 2800mV` 时，网页端显示低压警告文案。

## 低电量行为

### `<= 2800mV`

- MCU 进入低电量页面。
- 正常自动刷新停止。
- 屏幕显示电池图标和当前电压。

### `< 2700mV`

- MCU 尝试先刷新出 `power off`。
- 随后进入 `SYSOFF`。

### 低电量页轮询

- 低电量页激活后，固件每 `10` 秒采样一次电压。
- 若电压继续低于 `2700mV`，则进入关机流程。
- 若电压恢复到 `> 2800mV`，则退出低电量模式，恢复正常调度。
