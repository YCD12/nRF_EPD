# BLE 协议说明

> **当前主线范围说明:**
> - 本文档描述的是当前 `nRF52811` 主线工程实际使用的 BLE 协议行为
> - 当前主线默认验证重点为 `UC8179 / 7.5寸 / 800x480 / 三色`
> - 若后续扩展到其他屏幕型号或驱动组合，协议层兼容行为可继续沿用，但具体显示结果仍需结合对应固件适配验证

本文档记录当前网页端与 MCU 之间实际使用的 BLE 命令、通知格式，以及与固件版本相关的兼容行为。

## 固件版本历史

以下版本号记录功能演进历史，不再作为当前网页的独立能力门槛。当前完整协议固件的 MCU `APP_VERSION` 与网页 `NEW_WEB_MIN_FIRMWARE_VERSION` 统一为 `0x21`；达到该门槛即按本文完整新版协议处理。

- `0x3D`：TODO v4 保存提前显示与过期保留分钟数（默认 `10/5`）；触发后红色方框、截止后正文删除线、保留结束后隐藏。标题显示当前/当日总数，温度复用日历字体，屏幕去掉截止时间。旧 v1/v2/v3 的时间行为保持兼容。
- `0x3C`：待办字号扩展到 `9/12/16/20/24/32`，支持加粗、斜体及组合。TODO v3 保存字形与字号，网页生成专用字模，按行高限制显示数量；原有 v1/v2 继续兼容。
- `0x3B`：新增模式 `5`（全屏待办）与待办专用字体槽，模式 `4/5` 共用调度和事项。默认 TODO v1 兼容不变，自定义 TODO v2 引用 `FPK1` 可选第四槽；字体与待办在一次资源会话中统一应用。资源和模式确认通知优先于耗时 GUI 刷新，成功待办睡眠不触发循环全刷。
- `0x3A`：新增模式 `4`（待办事项+日历），待办通过外置资源分区 `9` 持久化，设备离线按触发/截止时间调度；见 [待办数据协议与使用说明](todo-calendar.md)。
- `0x39`：资源按协商长度扩包、设备端完整 CRC 元数据查询、显式页缓冲写入、清屏/图片刷新完成确认。当时网页仍支持 `0x38`，按能力位回退旧资源协议。

- `0x20` 及以下：不支持静默校时。
- `0x21` 及以上：支持 `EPD_CMD_SYNC_TIME_SILENT (0x23)`。
- `0x28` 及以上：支持 `EPD_CMD_SET_ANNOTATIONS (0x24)` 日历短标签写入。
- `0x29` 及以上：支持同命令 `op=0x02` 回读，通知类型 `0xA2`。
- `0x2A` 及以上：记录 flags bit5 选择位置（0=日期下方，1=右上角）。
- `0x2B` 及以上：右上角与日期下方使用相同的 9 字节标签上限。
- `0x33` 及以上：配置和标注写入外置 Flash，并用 `0xA8` 通知确认持久化结果。
- `0x34` 及以上：支持 `EPD_CMD_GET_CONFIG (0x93)`，迁移导出可读取已确认保存的配置。
- `0x35` 及以上：资源无需重启即可激活，支持应用后自动断开连接。保持连接时可切换模式并刷新，断开后继续运行并保持原广播策略；单图直写屏幕 RAM 不受此规则影响。
- `0x36`：停用无 CRC 传图和屏幕命令透传；该版本使用旧命令编号，当时网页按版本兼容。
- 历史 `0x37` 起采用紧凑编号，后续 `0x3B` 固件沿用：`REFRESH (0x03)`、`SLEEP (0x04)`、`WRITE_BLOCK (0x30)`、`QUERY_STATUS (0x31)`、`RESET_TRANSFER (0x32)`。当前统一编号 `0x21` 的完整协议固件继续使用这组编号，仅支持带 CRC 的分块传图，图片仍直接写屏幕 RAM。

当前网页连接后先读取 APP 版本特征值，最低支持 `0x21`；低于该版本或读取失败时停止初始化，不发送命令。`0x21` 及以上统一使用完整新版协议。

唯一网页固件门槛定义在 `html/js/main.js` 顶部：`NEW_WEB_MIN_FIRMWARE_VERSION = 0x21`，与 `EPD/EPD_service.h` 中 MCU 的 `APP_VERSION = 0x21` 保持一致。该脚本最先以 defer 方式加载并建立共享的 `EpdFirmwarePolicy`，页面初始化延迟到所有脚本执行后的 `DOMContentLoaded`。网页分流、配置回读、资源、标注、待办、传图与命令确认均共享这一门槛，不再定义独立的配置或资源最低版本。修改网页常量会同步改变全部固件能力判断和提示；`SET_MODE` 的 `0x22`、`SET_WEEK_START` 的 `0x21` 是独立命令编号，不随版本门槛变化。

其中低于 `0x21` 时优先推荐“使用旧版网页”，也可取消；“升级设备”显示“开发中”并暂时禁用。使用旧版时直接跳转 `legacy/index.html`，不主动断开蓝牙，离开页面时由浏览器释放连接；旧版页需要重新连接设备。

整个网页固件升级暂未开放：主页升级入口禁用，直接访问 `dfu.html` 仅显示“固件升级开发中，暂未开放”和返回入口。升级工作台及底层实现保留，但不加载升级脚本，不触发升级蓝牙连接、Bootloader 切换或固件包选择/传输；固件侧 DFU 能力与包生成工具保持不变。

新版网页对达到统一门槛的设备使用紧凑编号：`REFRESH=0x03`、`SLEEP=0x04`、`WRITE_BLOCK=0x30`、`QUERY_STATUS=0x31`、`RESET_TRANSFER=0x32`；模式使用带 token 的 `SET_MODE`。INIT、模式、清屏及图片刷新均等待匹配的完成通知。低于门槛的设备由独立旧网页处理。

标注回读、文字字库检查、右上角位置和持久化确认均在统一门槛启用；字体检查失败则停止标注写入。开发模式发送的原始十六进制命令绕过命令编号转换和业务 token 包装，但仍遵循设备任务锁、写入队列及连接代次检查。资源协议中的 VERIFY、热加载及删除等能力位仍按实际报告检查，不再附加独立固件版本条件。

旧版运行文件及全部 JS、CSS、图标依赖保存在 `html/legacy/`，资源路径均限制在该目录内，不加载外部统计脚本。`D:\Code\html_back` 仅作为本机同步来源，无需提交或部署。部署整个 `html` 目录（含 `legacy`）即可；旧页不依赖新版页面的资源，`legacy` 目录也可独立托管。

旧版页在项目内补充了连接兼容处理：通知监听先于 CCCD 启用，`mtu=/t=/v=` 按前缀解析，配置按共同引脚/驱动字段识别，不再依赖通知先后顺序。版本读取、订阅通知或 INIT 写入失败均停止初始化并清理连接；重连后的通知按连接代次过滤。`tests/test_legacy_connection_flow.cjs` 覆盖这些设备模拟场景。

跳转到旧版页后同样禁止网页 DFU：固件升级按钮显示“开发中”且始终禁用，直接访问 `legacy/dfu.html` 仅显示静态提示与返回旧页链接，不加载任何升级脚本或请求升级服务。

## 连接初始化顺序

当前网页端连接后的典型顺序如下：

1. 连接 BLE 服务并读取 APP 版本特征，确认版本 `>= 0x21`，使用完整新版通信协议。
2. 打开通知。
3. 发送 `EPD_CMD_INIT (0x01)`。
4. MCU 初始化完成后通过通知上报：
   - `mtu=<n>`
   - `t=<unix_timestamp>`
   - `v=<mV>`
5. 网页端自动发送 `EPD_CMD_SYNC_TIME_SILENT (0x23)`。

注意：

- `v=<mV>` 电压上报依赖 `EPD_CMD_INIT`，不是“仅建立连接就一定会上报”。
- 低于 `0x21` 的固件优先使用旧版网页，网页升级暂未开放；`0x21` 及以上由当前网页使用完整新版协议。

## 命令表

下文主命令表适用于达到统一固件门槛的新版设备，使用紧凑编号及完整确认协议。

当前 MCU 的普通控制命令队列单包上限为 16 B。`WRITE_BLOCK (0x30)`、`SET_ANNOTATIONS (0x24)` 和外置资源协议在各自的直接接收路径处理，不受该队列上限影响；BLE 协商 MTU 不变。

### `0x01` `EPD_CMD_INIT`

用途：

- 初始化屏幕驱动。
- 回传当前 MTU、当前时间和当前电压。
- 初始化完成后发送 `0xA6` 完成确认（token、状态、可用数据长度 LE16，见[通知格式](#通知格式)）；网页以此确认初始化成功后再继续后续命令。

### `0x02` CLEAR / `0x03` REFRESH 完成确认

新版网页发送 3 B 请求：`[02, refresh_flag, token]` 或 `[03, 0, token]`。CLEAR 的第二字节沿用旧含义，非零表示清空后刷新，网页默认 1。旧的无 token 请求仍可用，但不产生完成通知。

通知为 `[AB, token, result, command]`，在主循环中的驱动调用和 BUSY 等待返回后排队发送。result=0 表示驱动完成；2 表示资源维护中或命令队列已满；5 表示初始化失败、驱动不可用、BUSY 中止或 UC8179 BUSY 超时。通知队列满时由主循环重试，断连后丢弃旧回复。网页校验 token、命令和连接代次，等待期间保持任务锁；90 秒未确认或断连则失败。模式切换 `0xAA` 的含义仍是“已接受并安排刷新”。

### `0x20` `EPD_CMD_SET_TIME`

载荷格式：

- `[1..4]` Unix 时间戳，大端序，单位秒，UTC。
- `[5]` 时区偏移，单位小时，`int8_t`，可选，默认 `+8`。
- `[6]` 显示模式，可选。

兼容语义：

- 无论是否携带模式参数，都会立即触发一次刷新。
- 若携带模式参数，则会先切换模式，再立即刷新。

固件收到 SET_MODE 后在主循环调度当前模式的 GUI 刷新，不要求先断开 BLE；重复选择同一 GUI 模式也会请求刷新。SET_TIME 仍按既有频率限制处理，SYNC_TIME_SILENT 只校时不刷新。资源维护会话、未就绪资源、传图或未完成屏幕初始化时保留显示互斥；不会因校时或切模式重启设备。

### `0x21` `EPD_CMD_SET_WEEK_START`

载荷格式：

- `[1]` 周起始日，`0=Sunday`，`1=Monday`。

### `0x22` `EPD_CMD_SET_MODE`

当前网页对达到统一门槛的固件发送 9 字节完整请求：`[0x22, mode, token, week_start, utc_be32, timezone_i8]`。`token` 是每次请求的确认编号；`week_start` 为 `0..6`。设备执行模式切换请求后发出 4 字节通知 `[0xAA, token, result, mode]`；`result=0` 表示已接受并安排刷新，`result=2` 表示资源维护中或命令队列已满。网页必须收到匹配的确认才提示已接受，断连或超时则提示失败。确认表示刷新请求已排入执行流程，不表示屏幕物理刷新结束。

时间字段沿用整数小时偏移。网页在半小时或 45 分钟时区，将不足一小时的偏移折入 `utc_be32`，保证设备计算的本地墙钟与待办时间一致；整数小时地区仍发送原 UTC 秒数。设置时间及静默校时使用同一规则，协议长度不变。

用途：

- 切换显示模式。

模式值：

- `0` 图片模式
- `1` 日历模式
- `2` 分屏：左时钟、右日历
- `3` 全屏时钟
- `4` 待办事项+日历：左侧定时/常驻待办，右侧月历
- `5` 全屏待办：整屏显示与模式 `4` 相同的事项列表

模式 `4/5` 的待办标题显示屏幕当前条数/当日未完成总数，右端温度使用日历字体；标题下横线复用日历框线的位置和粗细，分屏中贯通左右区域。正文仅保留事项与阶段方框，不显示截止时间、常驻文字、时钟、日期、底部信息或分隔线。提前显示使用黑框，触发后使用红框，截止后删除线保留至设定时间；黑白屏使用黑框。两种模式共用 `todo.ers`、显示数量和纯 RAM 时间调度，不进入时钟分钟局刷。模式确认通知由主循环先发送；通知队列满时，待办 GUI 请求保持排队，确认成功后再执行刷新。自定义字体缺失或标识不匹配时返回 `result=1`，暂停自动待办刷新，修复资源后可再次应用或切换模式。

### `0x23` `EPD_CMD_SYNC_TIME_SILENT`

支持版本：

- 达到统一门槛的新版固件

载荷格式：

- `[1..4]` Unix 时间戳，大端序，单位秒，UTC。
- `[5]` 时区偏移，单位小时，`int8_t`，可选，默认 `+8`。

行为：

- 只更新时间，不立即触发屏幕刷新。
- 用于网页端连接后的自动静默校时。

### `0x24` `EPD_CMD_SET_ANNOTATIONS`

支持版本：

- 达到统一门槛的新版固件

用途：

- 写入或清除日历格子上的用户短标签。当前数据存在外置 Flash 分区 3，最多 64 条。
- 不支持旧版外置 Flash 的缺字点阵表（header 保留字节必须为 0）。

载荷：

- `[1] = 0x01`：清除全部标注。
- `[1] = 0x02`：回读当前标注。MCU 用 `0xA2` 通知按片推送整表。
- `[1] = 0x00`：顺序分片写入。
  - `[2..3]` 偏移，小端。
  - `[4..5]` 总长度，小端。
  - `[6..]` 本片数据。
- 第一片偏移必须为 0，后续偏移必须连续。最后一片写满总长度后校验并落盘。
- 二进制：16 字节 `ANNO` 头 + `count × 16` 字节记录。记录按年月日升序。
- flags：bit0=present，bits1–2=字号，bits3–4=颜色，bit5=位置（0 日期下方 / 1 右上角）。
- 日期下方和右上角标签都最多 9 字节 UTF-8。英文/数字使用现有文泉驿字形，不另加字库。

行为：

- 紧急命令，绕过 2 槽显示队列。
- 写入成功且当前不是图片模式时，强制全刷日历。
- 损坏或中断的分片只在 BLE 中断中登记恢复；外置 Flash 回读由主循环执行，恢复完成前不暴露半包数据。
- 日期下方：非空标签覆盖节日/农历，并在右上角打红点。右上角：节日/农历保留，短标签画在格子右上角。空标签只打红点。

### `0x93` `EPD_CMD_GET_CONFIG`

支持版本：达到统一门槛的新版固件。载荷 `[1]` 是网页生成的 token。固件等待已排队的配置命令和外置 Flash 保存结束，然后发送 `0xA9` 通知。仅当当前 14 B 配置与已提交记录一致时返回成功；用于生成迁移备份，不会修改配置。

当前固件仅从外置 Flash 的 ERS 字体分区读取字体包；FST2/FST3 旧字库格式不再读取。字体包通过外置 Flash 分区资源协议更新。

### `0x26` 外置资源会话与断连运行

请求为 `26 op token ...`，通知为 `A7 op token result ...`。多字节字段小端；客户端收到匹配 op/token 的响应后再发下一包。同一请求重试必须复用 token 和完整载荷。默认最大 20 B；设备 STATUS 能力 bit3 置位时，取 `L = min(244, 当前特征值可用长度)`。ATT MTU 23/247 分别对应 L=20/244，不能对 `mtu=<n>` 的值再次扣除 3 B。

| op | 请求体 | 行为 |
| --- | --- | --- |
| 0 STATUS | 无 | 返回挂载结果、能力、ABI、活动分区、会话状态、已落盘长度、容量 |
| 1 READ | 地址 u32、长度 u8 | 读取 1–(L−4) B；默认最多 16 B，大包最多 240 B |
| 2 BEGIN | 分区 u8、长度 u32、CRC32 u32、revision u32 | 先使消费者缓存失效，再开始单份写入 |
| 3 DATA | 偏移 u32、1–(L−7) B 数据 | 顺序同步写入，成功 ACK 表示本片已落盘；相同片段可重试 |
| 4 COMMIT | 无 | 校验完整载荷 CRC，最后提交包头有效标记 |
| 5 ABORT | 无 | 放弃当前事务，保持会话；不能恢复被擦除的旧数据 |
| 6 ENTER | ASCII `MIG1` | 获取维护会话，阻止并行显示、配置和标注修改；面板刷新或命令队列忙时返回 2（忙），客户端应在 250 ms 后重试（预算约 90 秒），不能按失败处理 |
| 7 LEAVE | 无 | 终止未完成事务，重载并校验已改资源，退出会话 |
| 8 RUN_OFFLINE | 无 | 校验运行资源，响应发送完成后断连，保持原广播策略（按 STATUS 能力位） |
| 9 VERIFIED_METADATA | 分区 u8 | 重新校验完整 payload CRC；成功返回 revision、长度、CRC32，均 u32；写事务活动时返回忙（能力 bit4） |
| 10 BUFFERED_DATA | 偏移 u32、1–(L−7) B 数据 | 顺序接收并按物理页合并，返回已接收与已落盘偏移（能力 bit5） |
| 11 ERASE | 分区 ID u16、相对扇区偏移 u32 | 擦除一个 4 KiB 扇区并回读校验。ID `0` 表示整片 Flash，ID `1` 定位分区表，其余 ID 按当前分区表解析相对偏移；偏移必须 4 KiB 对齐且小于目标范围，写事务活动时返回忙（能力 bit6） |

STATUS 共 16 B：`[0..3]` 为响应前缀；`[4]` 为能力位；`[5]` ABI=1；`[6]` 活动分区 ID；`[7]` 会话标志；`[8..11]` 已落盘字节数；`[12..15]` Flash 容量。
能力 bit0=读写、bit1=LEAVE 可直接激活、bit2=应用后断连运行、bit3=按 MTU 扩包、bit4=完整 CRC 元数据查询、bit5=页缓冲写入、bit6=按扇区删除。历史固件为 `0x01`/`0x07`，当前服务为 `0x7F`，客户端须按位检查（不得假设固定值）。

BUFFERED_DATA 成功响应固定 12 B：`A7 0A token 00 accepted:u32LE durable:u32LE`。accepted 包含 RAM 尾页，durable 只包含完成编程的数据；32 B ERS 包头使首个数据页容量为 224 B，后续为 256 B。接收到整个 payload 时必须先刷出尾页再 ACK。相同数据重发可跨越已落盘区和 RAM 区，不重复编程；一个 BEGIN 内不能混用 DATA 与 BUFFERED_DATA。COMMIT 仍执行完整 CRC、包头回读与最后有效标记写入。断连后丢弃 RAM 尾页，重新上传，不支持跨连接续传。

VERIFIED_METADATA 成功响应固定 16 B：`A7 09 token 00 revision:u32LE length:u32LE crc:u32LE`；错误响应仅前缀 4 B。网页只有在完整 CRC 检查成功且长度、CRC 都相同时才跳过资源；revision 仅用于显示。同内容高 revision 默认仍跳过，需要同步指定 revision 时勾选强制重写。分区表改变会失效全部消费者，其余更新仅失效对应缓存。

网页按完整任务互斥连接初始化、传图、资源、标注、模式请求和迁移导出，所有 GATT 写入走同一入口。断连取消 waiter，旧任务不能继续向新连接发送。图片状态必须匹配本层会话、总块数和 active，重试从本层第 0 块开始；函数名 `sendImageWithResume` 为兼容保留，不代表断连续传。新固件 REFRESH/CLEAR 使用 `0xAB` 确认驱动完成；资源 LEAVE 的成功表示资源应用完成，之后的自动 GUI 刷新仍由调度器执行。

固件 `0x3B` 在 `LEAVE` 响应等待发送时保留 GUI 请求并优先重试通知，避免全屏刷新阻塞响应。待办保存将字体分区 `7` 和待办分区 `9` 放在同一维护会话内，全部提交及 CRC 校验完成后仅执行一次 `LEAVE`；这保证运行时加载后的字模和事项引用匹配，但不是跨分区掉电原子事务。

待办默认使用 TODO v1，包头 `10–15` 为零。自定义字体使用 TODO v2：包头字节 `10=3`，字节 `11` 为字体名称 UTF-8 长度 `1–64`，字节 `12–15` 为非零 `fontKey:u32LE`；`count × 80` 字节记录之后追加该长度的字体名称，无 NUL 或填充。字体包保持 `FPK1` version `1`，允许 `count=3/4`，前三槽 `flags=0`，可选槽 `3` 的 `flags=fontKey`，其 geometry 必须匹配基础槽 `0` 或 `1`。待办字号及字体标识须与槽 `3` 匹配；记录格式和完整字段见 [待办数据协议](todo-calendar.md)。

结果码：0 成功、1 请求或业务格式错误、2 忙、3 CRC 错误、4 未找到、5 I/O 错误、6 ABI 不兼容、7 写入受保护。COMMIT 成功表示包已持久化；LEAVE/RUN_OFFLINE 还会检查字体、日历和 UI 业务格式，不能只凭 CRC 判定可运行。

断连或会话内连续 60 秒无活动都会取消事务、重载消费者并释放维护状态。超时包含“ENTER 后尚未 BEGIN”和“COMMIT 后尚未 LEAVE”。单份数据没有自动回滚；损坏包需要重新上传，自动 GUI 保持暂停，蓝牙仍可用于修复。

RUN_OFFLINE 保留现有操作码和名称，含义是断开连接后独立运行，不是关闭蓝牙。该命令不允许有正在接收的资源包、图片、标注或待保存配置。设备等最终通知离开发送队列后再关闭链路；保留 RTC、时间戳和 SoftDevice 的内存布局，不执行系统复位。图片模式不要求安装 GUI 资源。

命令断连与普通断连使用相同广播策略：由广播模块自动恢复广播，间隔和超时沿用原配置；未配置唤醒脚时，广播超时后重新广播；已配置时沿用原图片模式休眠、其他模式等待唤醒的处理。资源应用流程不停止广播、不禁止自动重播，也不提前启用唤醒脚。

## 通知格式

### `mtu=<n>`

- MCU 返回当前链路的可用 MTU。

### `t=<unix_timestamp>`

- MCU 返回当前时间戳。

### `0xA6` INIT 完成确认

- 5 B：`[0]=0xA6`，`[1]=请求 token`，`[2]=result`（`0`=初始化完成；`1`=初始化失败，含 UC8179 BUSY 超时），`[3..4]`=可用数据长度 `u16 LE`。
- 由 `EPD_CMD_INIT (0x01)` 的 3 B 请求 `[0x01, model, token]` 触发；`model` 为型号 ID，`0xFF` 表示使用设备默认/已保存型号，token 由网页生成并在确认中原样返回。
- `[3..4]` 与 `mtu=<n>` 同义，均为**特征值可用长度**（`ATT_MTU − 3`），可直接作为传图/资源分块上限，不能再扣 3 B。
- 固件在 INIT 工作完成后的主循环中排队发送，通知队列满时由主循环重试；断连后丢弃旧确认。网页等待约 30 秒，只接受 token 与连接代次都匹配的确认。

### `0xA2` 日历短标签分片

- `[0] = 0xA2`
- `[1..2]` 本片偏移，小端。
- `[3..4]` 总长度，小端。
- `[5..]` 本片数据。
- 网页按偏移拼成完整 `ANNO` 表后填入编辑列表。

### `0xA8` 外置记录提交确认

- 12 B：`[0]=0xA8`，`[1]=分区 ID`，`[2]=rs_result_t`，`[3]=0`，`[4..7]=revision:u32LE`，`[8..11]=业务数据 CRC32:u32LE`。
- 分区 2 是 EPD 配置，分区 3 是用户标注；状态 0 表示持久化成功。

### `0xA9` 配置回读确认

- 17 B：`[0]=0xA9`，`[1]=请求 token`，`[2]=rs_result_t`，`[3..16]=epd_config_t`。
- 网页只接受 token 匹配且状态为 0 的配置，并检查连接代次未变化后生成迁移文件。

### `v=<mV>`

- MCU 返回当前电池电压，单位毫伏。
- 网页端会在“设备电压”区域显示该值。
- 当电压 `<= 2800mV` 时，网页端显示低压警告文案。

## 低电量行为

### `<= 2800mV`

- MCU 进入低电量页面。
- 正常自动刷新停止。
- 屏幕显示电池图标和当前电压。

### `< 2700mV`

- MCU 尝试先刷新出 `power off`。
- 随后进入 `SYSOFF`。

### 低电量页轮询

- 低电量页激活后，固件每 `10` 秒采样一次电压。
- 若电压继续低于 `2700mV`，则进入关机流程。
- 若电压恢复到 `> 2800mV`，则退出低电量模式，恢复正常调度。
