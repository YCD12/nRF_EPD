# 逻辑优化实施记录（2026-09-29）

本轮按 [逻辑复核](logic-optimization-review-20260929.md) 处理已确认的问题，保留单张图片直接写屏幕 RAM、连接中刷新，以及断连后的间歇广播行为。

- CCCD 启用后的配置、MTU、电压通知改在主循环逐项发送；SoftDevice 返回 `NRF_ERROR_RESOURCES` 时保留待发送状态，关闭通知或断连时清除。
- 新网页使用固件版本 `0x38` 和单条 9 字节 `SET_MODE` 请求，包含模式、令牌、周起始日和时间。MCU 执行后返回匹配令牌的状态；队列满或资源维护时明确返回忙，网页收到确认后才提示“已接受”。旧版 2 字节模式请求不再执行；旧固件继续使用对应的旧版网页。
- `SET_CONFIG`、`SET_PINS`、资源激活和冷启动共用配置校验；硬件字段改变时释放旧屏幕和 GPIO 引用，再装入新引脚。仅显示字段改变时不重建 GPIO。
- 自定义 UI 的页裁剪依据字体实际范围；默认界面逐像素结果未变。日历和时钟无关页面跳过相应文本计算。
- 外置 Flash 资源读取在缓存未命中后回填已校验的分区元数据；字体与资源包共用 CRC 扫描函数，并保留写入及重定位时的缓存失效。
- 去掉只从统一命令分发器调用的短命令尾部重复喂狗；分发器执行前后仍喂狗，屏幕驱动等待、Flash 扫描等长操作中的喂狗保留。

验证：`tests/run_host_tests.sh` 全部通过，包括新增的通知背压、忙状态、配置应用、资源缓存和自定义 UI 裁剪用例。默认 GUI 六组 golden hash 未变；例如日历黑白模式每帧字体读取从 10,678 降到 5,911 次。网页端模式确认在 V8 中通过成功、旧令牌、忙状态、断连四种路径的烟测。当前环境没有 Node.js，因此 `tests/test_ble_lifecycle.cjs` 整套测试仍需在有 Node.js 的环境运行。

单线程固件构建 `-j1` 通过。基线 BIN 为 49,112 B，静态 RAM 为 5,308 B；本轮 BIN 为 **49,816 B**，静态 RAM 为 **5,316 B**，剩余应用 Flash **7,528 B**。这轮新增可靠确认和校验使内置 Flash 净增 704 B、RAM 增加 8 B；外置 Flash 和 GUI 改动的主要收益是减少 SPI 读取与渲染计算，并非降低 BIN。尚未做硬件实测，尤其需要在真机上验证 CCCD 背压、冷启动资源恢复及连续切换模式。
