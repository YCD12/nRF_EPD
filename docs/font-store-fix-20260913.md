# 2026-09-13 字库更新问题分析与验证

## 已观察到的问题

在本机真实 Chrome 网页连接 `NRF_EPD_3AA9`，复现了原日志：配置、MTU=244、电压上报成功，首次 INIT 写入时立即断连，随后错误地执行校时、字库读取并显示重连成功。原始记录见 `output/diagnostics/before-fix.hex` 与 `.playwright-cli/console-2026-09-13T13-24-14-537Z.log`。

J-Link 读取到固件停在 `app_error_fault_handler` 内，R0=1（SoftDevice assert）、R1=0x11694、R2=0，当前 PC=0x21E90。故障发生在字库 BEGIN 之前，因此不是上传文件内容或字库列表超时引起。补丁把共享命令特征从 SEC_OPEN 改为 SEC_JUST_WORKS，同时新增了无绑定的配对路径。恢复原有免配对协议是本次针对该回归的修复；SoftDevice 内部断言的具体条件没有符号信息，仍需修复固件的真机回归确认。

## 修改

- 固件恢复共享命令特征的 SEC_OPEN 与不支持配对的原协议，避免 INIT 触发新增的加密流程。CRC/Flash 事务与是否配对没有依赖关系。Just Works 也不等于设备所有者认证；如需限制写入者，应单独设计认证、绑定、清除绑定和恢复流程。参考 [Nordic S112 GAP API](https://docs.nordicsemi.com/r/bundle/s112_v7.3.0_api/page/group_b_l_e_g_a_p_f_u_n_c_t_i_o_n_s.html)。
- 网页初始化失败立即退出，校验每个异步阶段所属连接；断连清除旧 MTU、版本和写队列，恢复重连按钮，防止假成功。
- 字库操作绑定连接会话，阻止旧排队任务、读取中的 BIN 和数据包重试跨连接执行；清除断连时的旧列表显示。
- ACK Promise 在等待 GATT 完成前就注册拒绝处理，避免写入失败/断连引起未处理的拒绝。
- BEGIN 前验证至少 34 字节可用数据长度，在读取文件之前检查容量；检查累计 ACK 的序号/偏移对应关系，限制无进展重试，ACK 丢失时最多重发同一窗口 3 次。
- Flash 一旦尝试擦除数据，就视为旧数据可能已损坏，即使擦除返回超时。覆盖模式 ABORT 不再错误恢复旧 Manifest。
- 网页版本更新至 v2.0.13，更新 JS 缓存参数。
- Windows `build.bat flash` 同步烧录并校验应用和 Bootloader settings。打包脚本生成 settings v2 及备份页。

## 设计评估

三槽全量包、分包 CRC、整包/分槽 CRC、提交前实际 Flash 回读、后台 FIFO 和延迟刷新可以保留。当前 3 个资源共 9,534 字节，完整更新成本较小；全量提交要求所有保留槽重新选择 BIN，属于明确的产品限制，不支持设备端自动保留未上传槽。

当前实现优先在尾部空闲扇区追加；空间不足后才覆盖旧包。追加期间掉电或断连可保留旧包，覆盖期间不能保证旧包可恢复。仍只有一个 Manifest 扇区，重写该扇区时掉电可能丢失整个目录；恢复依赖重新上传，不能称为任意时刻掉电都可回滚的原子更新。下一步若需要该保证，应设计双 Manifest/代次选择及可循环复用的空闲区，同时规划旧格式迁移，不能仅修改地址常量。

## 真机验证尚未完成
