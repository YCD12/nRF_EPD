# 当前代码复核：待办 + 日历日期更新（2026-10-10）

复核当前工作区的显示调度、日历绘制、时间同步和构建入口。本轮修正日期补刷的两个薄弱点，应用、宿主及网页回归通过。当前磁盘还缺少独立 Bootloader 源码目录；应用构建和使用现有配套 Bootloader 的签名发布成功，但不能据此声称 Bootloader 从源码构建完整。

## 日期更新

原代码已经有跨日检测，并非完全缺少午夜刷新。但是跨日状态记录的是定时器最后经过的日期，待办快照只比较显示事项、阶段和数量，不包含右侧日历日期。故障注入复现：定时器观察到新一天后，旧日期的成功帧清除了全刷标志；如果左侧事项、阶段和总数都不变，后续定时检查不再补刷。修改前模式 `4` 的新增回归在“应再次安排当前日期刷新”的断言失败。

本轮在 `EPD/EPD_service.c` 修正：

- 模式 `4` 将当前本地日期与 `last_full_clear` 所记录的最后成功显示日期比较。即使左侧为空或只有常驻事项，日期不同也安排整屏刷新。只在面板刷新成功后更新该日期；字库错误和面板失败不会提交成功状态。
- 待办 GUI 排队后，开始执行时重新读取当前时间，避免等待通知或维护后仍使用排队时的旧日期和旧事项阶段。同一帧继续使用固定时间戳，保证分页一致。
- 如果等待后的成功帧已经显示了今天，定时器随后观察到跨日时跳过重复的日更；日期补刷仍服从现有低电量、传图、维护及字库 I/O 退避规则。失败不会变成持续全屏刷新。

修改没有改变右侧日历的绘制样式、提前显示和过期保留时间、字号及字形，也没有增加 RAM 状态。没有设备跨午夜日志，本轮定位是软件复现出的漏更新路径，尚不能确定这是实机现象的唯一原因。
