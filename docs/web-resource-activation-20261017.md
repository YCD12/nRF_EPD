**网页资源安装确认与慢刷新等待（网页 v2.3.3）**

设备固件 `0x40` 已兼容本次网页修复，无需重新烧录。

资源提交后，LEAVE 的成功确认表示资源已完成消费者校验并激活。固件接着在主循环中同步绘制和刷新电子纸；这期间新资源请求可以进入队列，但需要等刷新结束后处理。

原网页收到 LEAVE 确认后又立即读取一次 STATUS。该请求并不更新资源面板，却可能因三次各 5 秒的等待耗尽，把已经应用成功的安装标记为失败，并阻止后面的自动断开流程。

修复后：

- 去除安装完成后的多余 STATUS 请求；缺少确认、应用校验失败或断线仍按失败处理，不根据“包已提交”推断应用成功。
- LEAVE、RUN_OFFLINE 以及成功激活后 90 秒内的资源请求，每次等待至少 30 秒，最多三次，容纳同步刷新阻塞主循环的时间。其余请求保留原来每次 5 秒的行为；重试沿用同一 token。
- 超时提示包含请求阶段，便于区分“应用资源”“读取资源状态”等情况。
- 自动断开仍先同步当前时间，再由固件应用确认和原断开协议完成；等待期间保持操作锁。
- 已确认资源应用后，如果自动断开单独失败，提示“资源已应用，但自动断开未完成”，保留安装完成状态，避免引导重复安装已成功的包。
- `file://` 页面不加载访问统计，避免本地工具访问第三方统计接口。HTTP/HTTPS 页面继续延迟加载统计。

“使用系统蓝牙选择窗口”表示浏览器没有提供按信号排序的扫描方式，是正常的设备选择路径。“分区表未安装或未提交”如果发生在首次安装之前，表示外置 Flash 尚未初始化。

验证覆盖：旧版 15 秒等待耗尽的复现、延迟 20/35 秒的激活和后续请求、真正丢失确认时的有界超时、同 token 重试、原有快速失败、成功安装时不再进行刷屏中的状态轮询，以及本地文件禁用统计。时间测试使用虚拟时钟和真实 ResourceClient 实现，不依赖实机等待。
