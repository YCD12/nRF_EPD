# 当前固件各模块 Flash / RAM 占用（2026-09-15）

## 总览与统计口径

已重新执行发布构建目标，确认现有产物与当前依赖一致。分析对象为 `output/flash-opt4/release-build/nrf52811_xxaa.out`，GCC 9.3.1、`-Os -flto`、默认发布配置。

| 项目 | 使用/预留 | 容量或余量 |
| --- | ---: | ---: |
| 应用 Flash | **52,716 B** | 容量 57,344 B，剩余 **4,628 B** |
| 应用静态 RAM 节合计 | **6,788 B** | `.data` 208 + `.fs_data` 20 + `.bss` 6,560 |
| RAM 段间对齐 | **4 B** | `.fs_data` 末尾到 `.bss` 起点 |
| 应用栈预留 | **2,048 B** | 不是实测最大栈深度 |
| 应用堆预留 | **0 B** | `__HeapBase == __HeapLimit` |
| 应用 RAM 未分配余量 | **6,816 B** | 15,656 − 6,788 − 4 − 2,048 |

Flash 包括执行代码、只读常量、向量/观察者表，以及初始化 RAM 数据的镜像；RAM 表只统计全局和静态数据，不将共享栈按模块重复计算。

方法：最终 ELF 符号表 + `nm -l` + DWARF 变量声明和地址。对符号别名及重叠地址去重，未标记字节、对齐和公共运行库单列；汇总与 ELF 节大小及 BIN 长度核对。工具脚本和逐符号 JSON 位于 `output/module-memory-20260915/`。

**LTO 会跨文件内联，Flash 按最终符号所属源码归类，不代表删除该模块后的净节省。** 例如 `epd_advertising_init` 已内联到 `main`，其体积包含在主程序行。RAM 按变量定义位置归类，共享结构内部的用途在下一节拆开说明。

### `m_epd` 的内部构成

根据最终 ELF 的 DWARF 类型信息读取，避免使用主机平台的 `sizeof` 代替 ARM 布局：

| 成员/分组 | 大小 |
| --- | ---: |
| `font`：字体传输状态及缓冲 | **1,048 B** |
| `cmd_queue`：普通命令队列 | **502 B** |
| 其他 BLE 句柄、显示/标注状态、配置、时间戳及结构对齐 | **110 B** |
| **合计** | **1,660 B** |

因此按实际功能用途看，字体模块至少包含 **187 + 1,048 = 1,235 B** 静态数据；其中 1,048 B 已计入上表第一行，不能再加到总计。类似地，SDK 广播实例的 248 B 和调度缓冲的 132 B 也在第一行中。

字形解码器使用的 `Adafruit_GFX/u8g2` 上下文和部分临时缓冲在调用栈上，不能从该静态表推导模块运行时 RAM 峰值。现有产物保留 2 KiB 栈，但没有各路径的实机栈高水位数据。

## 整片内存布局

### 内置 Flash：192 KiB

| 区域 | 地址范围（不含末地址） | 分配容量 |
| --- | --- | ---: |
| MBR + S112 | `0x00000–0x19000` | 100 KiB |
| 应用 | `0x19000–0x27000` | 56 KiB |
| FDS 持久化数据 | `0x27000–0x29000` | 8 KiB |
| Bootloader 代码 | `0x29000–0x2E000` | 20 KiB |
| MBR 参数 / settings 备份 | `0x2E000–0x2F000` | 4 KiB |
| settings 主页面 | `0x2F000–0x30000` | 4 KiB |

这是分区分配，不是每区已经写入的有效数据量。当前应用实际末地址为 `0x25DEC`（不含）。设备 FDS 当前记录占用需要读实机，不能从应用 ELF 得知。

### RAM：24 KiB

| 区域 | 地址范围（不含末地址） | 大小 |
| --- | --- | ---: |
| SoftDevice 配置预留 | `0x20000000–0x200022D8` | 8,920 B |
| 应用静态数据及对齐 | `0x200022D8–0x20003D60` | 6,792 B |
| 未分配区域 | `0x20003D60–0x20005800` | **6,816 B** |
| 应用栈预留 | `0x20005800–0x20006000` | 2,048 B |
| **总计** | | **24,576 B** |

SoftDevice 的 8,920 B 是当前链接配置的预留，不能视为实测协议栈峰值。Bootloader 与应用不同时运行，其启动阶段 RAM 用量不能简单叠加到应用运行预算；本次应用 ELF 也不能给出 Bootloader 自身静态 RAM 明细。

**对上一轮 RAM 数字的补充：** UUID 改为 const 后，静态节合计确实减少 4 B，但 `.bss` 仍从 `0x200023C0` 开始，这 4 B 转成段间对齐，所以真实未分配 RAM 没有增加。现有 `memory`/`show_memory` 统计只减节大小，会显示 6,820 B；实际地址核对值应为 **6,816 B**。当前堆预留为零，这段未分配区域也不是可直接 malloc 的堆。
