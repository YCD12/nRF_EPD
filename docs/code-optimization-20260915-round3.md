# 第三轮修复与内置 Flash 优化结果

本轮落实第三轮审查的五类稳定性修复和三项已测量的内置优化。设备版本从 `0x31` 更新为 `0x32`，配套网页版本为 `2.0.15`。代码、主机回归和发布构建已完成；未执行实机烧录。

## 修复内容

1. **标注回读通知竞态**：发送前登记 `waiting_tx`；GET 重启和断连取消增加任务代次，旧发送结果不能推进新任务。发送调用留在临界区之外，临界区仅保护状态与有界数据拷贝。覆盖发送返回前发生 TX complete、资源不足时提前唤醒、GET 重启和取消。
2. **传图会话和 GPIO 收尾**：断开时登记清理请求并丢弃旧连接中尚未执行的命令；主循环负责面板休眠、连接 GPIO 引用释放及传图状态清零。`RESET_TRANSFER` 后无有效活动超过 30 秒也会清理会话，使仍处于时钟／日历模式的设备恢复刷新。图片模式不自动改回时钟模式。刷新中途让出时始终释放自己的 GPIO 引用；如果连接引用尚未取得，则先休眠再释放最后一个引用。
3. **INIT 重入和完成确认**：BLE 入口只登记请求，主循环在面板与字体任务允许时执行初始化。记录 INIT 到达前的排队命令数量，保证 `SET_PINS → INIT → 后续命令` 的次序。快速重连使用连接代次丢弃旧初始化结果；忙时的 `WRITE_BLOCK` 返回重传状态。网页先挂完成等待，再发 INIT，收到匹配 token 的完成通知才继续；失败、超时或断开结束等待，驱动设置和传图入口不再忽略初始化失败。
4. **缺字占位框**：固定方向字体回调仍支持占位框的竖线，修正侧边缺失及多余横线。新增经过真实 GFX 缓冲的像素断言，通用和产品固定配置均运行。
5. **非法 GPIO**：`pinMode` 统一过滤不存在的引脚。引脚配置和整包配置先校验候选，再更新状态；必选引脚不得使用 `0xFF`，可选 BS／EN／LED／唤醒引脚允许 `0xFF`。启动读取到非法映射时恢复板级默认配置。

主要实现位于 `EPD/EPD_service.c` 的请求登记、初始化处理和连接清理函数，以及独立的 `calendar_annotations_tx` 模块。此次按执行上下文明确职责，没有进行无收益的目录搬迁。

## INIT 协议

设备 `0x32` 支持请求 `[0x01, model, token]`，完成通知为 `[0xA6, token, status, mtu_lo, mtu_hi]`。`status=0` 表示初始化完成，`status=1` 表示驱动 BUSY 等待失败。MTU 字段沿用服务的最大通知数据长度。通知队列满时保留完成响应，由主循环重试，期间不会启动新的 GUI 刷新占用主循环。

保留旧 INIT 请求长度和原有 MTU／时间／电压文本通知；新网页连接 `0x31` 及更旧固件时仍走原流程。新固件的完成握手需要配套新网页，旧网页不会利用此确认机制。网页确认等待上限为 30 秒。

设备报告版本 `0x32` 与 DFU 的防回滚元数据版本是不同字段；本轮沿用打包脚本原有的 DFU application version `0x19`，没有更改 bootloader 或 Flash 分区。

## 实测体积

ARM GCC 9.3.1，发布配置 `-Os -flto`。应用 Flash 区仍为 `0x19000–0x27000`，容量 57,344 字节；FDS 双页数据区保留。所有 A/B 构建使用独立目录。

| 构建 | text | data | bss | 应用 Flash | 静态 RAM |
| --- | ---: | ---: | ---: | ---: | ---: |
| 上一版 `0x31` | 52,760 | 232 | 6,544 | 52,992 | 6,776 |
| 本轮全部修复，关闭三项优化的对照 | 53,912 | 232 | 6,560 | 54,144 | 6,792 |
| 本轮最终 `0x32` | **53,656** | **232** | **6,560** | **53,888** | **6,792** |

三项优化分别是 H/V 单轴绘制循环、两个字体初始化函数局部禁止内联、局刷 LUT 公共模板生成。三项合计节省 **256 字节 Flash**，静态 RAM 不变。H/V 的零长度和负长度均不绘制，正长度裁剪结果与通用直线绘制一致。LUT 保留六组各 42 字节数据及发送顺序和喂狗。

包含修复后的最终变化为 **Flash +896 字节、静态 RAM +16 字节**，不能将独立优化收益当成最终净减量。应用 Flash 还剩 **3,456 字节**。RAM 区 15,656 字节，扣除静态占用与保留的 2,048 字节栈后还剩 **6,816 字节**。

LUT 使用 42 字节局部缓冲。最终反汇编显示 `UC8179_Init_Partial` 自身栈帧为 56 字节，对照为 24 字节，局部增加 32 字节；这不等于整条调用链或中断嵌套的最大栈深度。保留原有 2 KiB 栈，未以缩栈换取纸面 RAM 收益。

## 保留的后续事项

本轮没有迁移外置 Flash，也没有替换 FDS：应用区仍有余量，现有持久化布局保持兼容。审查中提出的持久化完成／失败协议、2027 年之后的精确农历与节气数据扩展、分阶段 GUI 刷新仍是后续功能工作；本轮没有宣称这些边界已经解决。

专用内置双页日志需要掉电注入和旧数据迁移验证后才能决定是否采用；外置日历包与完整持久化迁移仍作为内置方案达不到容量目标时的后备路线。

发布前需要目标板验证：刷新期间快速连接／断开与 INIT、传图中断后的时钟恢复和待机电流、无外置字库时的占位框、长时间通知背压，以及包含 BLE 中断嵌套的最大栈使用量。主机测试和构建通过不能替代这些硬件结果。
