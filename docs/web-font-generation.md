# 网页按需补充外置字库

日期标注和自定义日历文字可使用设备字库中尚未收录的字。网页检查实际字库，只把缺少的字用浏览器字体生成位图，再合并到现有字体资源。设备保存的是兼容现有 u8g2 渲染器的字模，更新屏幕时从外置 Flash 加载。

## 使用方式

1. 首次使用设备时安装完整外置资源，确保分区表、日历、UI 和字体包有效。
2. 在日期标注中输入标签，例如“生日”或“出差”，添加到标注列表后点击保存。
3. 网页读取设备当前字体包并核对标签需要的字。如果字库缺字，网页生成字模，更新外置字体包，应用成功后继续保存标注。
4. 后续再次使用相同字体槽位中的字时直接复用，不重复写入字体包。字模保存在设备上，刷新页面或设备重启后仍可使用。

字体来源是当前浏览器能够访问的系统字体，通过 Canvas 实际栅格化文字；不同操作系统的字形可能略有不同。网页无法提供某个字的有效位图时会报告错误，需在运行网页的系统安装支持该字的字体后重试。

日期标注的记录格式保持 ANNO v1：短标签最多 **9 个 UTF-8 字节**，常用中文最多 3 字。按需补字不会增加标签长度上限，也不会改变字体字号、颜色和位置字段。

## 通用接口

网页字模模块和设备安装模块分离，后续文字功能可复用同一能力。

```javascript
// fonts 为 FPK1 解码后的 3 个 Uint8Array 字体槽位。
// requests 中每个项目指定目标槽位和需要显示的文字。
const result = await EPDWebFonts.extendFonts(fonts, [
  { slot: 0, text: '出差' },
  { slot: 1, text: '出差' },
], { fontFamily: '"Microsoft YaHei", "PingFang SC", sans-serif' });
const fontPayload = EPDResourceBuilder.encodeFonts(result.fonts);

// 保存到已连接的设备；复用外层操作锁，成功返回后可继续保存业务数据。
await ExternalResourceInstaller.ensureFonts([
  { slot: 0, text: '出差' },
  { slot: 1, text: '出差' },
], parentOwner, progress);
```

槽位 0、1 为小号和大号日历字体，槽位 2 为数字字体。目标槽位的几何和现有字模保持兼容；新增字号仍须另行提供对应字体方案。日期标注会根据其字号和实际渲染规则检查相应槽位。

`extendFonts` 只处理字体数据，不访问蓝牙、不写设备。它去重请求、保留已有字模、生成缺字，并重新编码为现有 u8g2 字体结构。`ensureFonts` 负责读取设备最新字库、调用生成器、检查容量、传输和应用，供标注等业务在写入内容前调用。

`extendFonts` 返回 `{ fonts, added, missing }`：`fonts` 为合并后的三个槽位，`added` 和 `missing` 为 `{ slot, codePoint }` 列表。`options.fontFamily` 可选，用于指定 CSS 字体族；省略时按微软雅黑、苹方、Noto Sans CJK/Noto Sans、系统无衬线字体的顺序选择可用字体。`options.rasterize` 可替换位图生成步骤，便于接入其他字模来源和测试，其异步签名为 `(codePoint, slot, header, options)`，返回 `{ width, height, x, y, advance, pixels }`；`pixels` 为按行排列的 0/1 点阵。生成器仍会验证尺寸、位宽和压缩记录长度。

`EPDWebFonts.gatherMissing(fonts, requests)` 可同步检查缺字；`EPDWebFonts.mergeFonts(incomingFonts, installedFonts)` 可合并两个完整字库，返回 `{ fonts, added }`。同码点使用待安装字库的字形，设备独有的字模会保留；两套字体编码位宽不同时，合并器解码并重新编码已有位图。

`ensureFonts` 成功返回 `{ changed, added }`，`changed: false` 表示没有缺字，无需写 Flash。失败会抛出异常，调用方应停止保存业务数据。`progress` 接收中文阶段及传输进度消息。

资源编辑器生成日历资源时也调用同一字模生成器。生成的字模随 `fonts.ers` 下载、导出工程或上传，无需另行准备缺字 BIN。

## 存储和协议

字模更新复用现有资源协议 `EPD_CMD_RESOURCE (0x26)`，没有增加字体专用 BLE 命令或新的 Flash 分区：

1. 读取并校验设备实际分区表和字体 ERS 包。
2. 解码 `FPK1`，检查目标槽位已有的 Unicode 码点，只生成缺少的字。
3. 合并全部三个槽位，重新生成字体目录、每个字体的 CRC32 和 ERS 校验信息。
4. 检查整个包能放入设备字体分区，再执行资源会话的进入、开始、分块写入和提交。
5. 收到提交确认后发送 `LEAVE`，由固件重新加载字体和显示资源；只有应用成功才继续发送日期标注。

网页在生成字模后、开始写入前再次检查原字体包的版本、长度和 CRC，防止用生成前的旧快照覆盖已经变化的设备字库。补字需要固件报告资源即时应用能力；没有此能力时会要求升级固件。

这是**整个字体资源包的更新**，并非只往 Flash 追加一个字。分区 7 的默认容量为 256 KiB，是否足够以设备实际分区表为准。字模和其他字体槽位合并后一次提交，已安装字库中的其他字仍保留。

补字与后续标注写入共用 `DeviceOperations` 操作锁，避免资源更新与传图、切换模式或其他保存操作交错。断连、连接切换、写入失败、CRC 错误或 `LEAVE` 应用失败时，当前保存会停止；网页不会把未应用的字体当成已可用。

## 边界与维护

- 当前 u8g2 码点为 16 位，仅支持可显示的 Unicode BMP 字符。Emoji、扩展汉字等超过 `U+FFFF` 的字符暂不支持；控制字符和无效代理项也会拒绝。
- 新字使用现有槽位字号的单色位图，适配既有字模几何。浏览器字体样式可能与原先文泉驿字模不同；已经存在的字形优先使用原字模。
- 字模必须符合槽位的宽、高、偏移和前进宽度位宽，单个压缩记录最多 255 字节。超过这些边界时明确失败，不通过裁掉笔画来强行保存。
- 字体包缺失或损坏时，先通过设备资源安装功能恢复有效字库。按需补字需要已有资源基础，不能独立初始化空白设备。
- 外置资源仍为单份存储，写入中断可能使字体包未提交或不可用，需重新安装或重传。CRC 和提交标志用于拒绝不完整数据，不提供旧字体包自动回滚。
- 字体和日期标注是两次独立提交：字体已更新、标注保存失败时，新字模仍保留在设备，重试标注即可。
- 通过“完整回读”导出资源 ZIP，可保存设备上的字模供后续恢复或发布。设备上生成的字体不会自动改写本地默认模板或命令行发布资源。
- 日后通过同一网页安装新字体资源时，会合并设备中独有的字模，保留先前补充的字；同码点以新安装资源中的字形为准。通信失败时停止更新，包本身损坏或缺失时可使用新包恢复。使用其他烧写工具直接覆盖字体分区时，需要自行包含这些字模。

后续新增文字功能应先整理所需槽位和文本，在持有同一设备操作锁时调用 `ensureFonts`，等待字体应用完成后再写入业务数据。这样无需复制字模生成、Flash 传输和错误处理流程。
