# 当前内置 Flash 占用分析（2026-09-15）

后续已实施优化，最终应用降至 52,716 字节，详见 [优化实施结果](internal-flash-optimization-20260915.md)。本文以下数据保留为优化前基线。

## 结论

当前工作区的 GCC 发布构建占用 **53,888 / 57,344 字节，93.97%**，应用区剩余 **3,456 字节（3.375 KiB）**。能够正常链接，但新增功能的空间已经偏紧。仍有优化方向，不过常见的低成本优化大多已经实施；不能再把历史报告中的收益作为待释放空间。

本次只做构建与分析，未修改业务源码、SDK、分区或发布包，未烧录硬件。分析产物位于 `output/flash-analysis-20260915/`。

## 2. 整片内置 Flash 分配

当前默认目标 `NRF52811_XXAA`，按项目布局使用 192 KiB 内置 Flash。以下地址区间均为左闭右开。

| 区域 | 地址 | 分配容量 |
| --- | --- | ---: |
| MBR + S112 SoftDevice | `0x00000–0x19000` | 100 KiB |
| 应用 | `0x19000–0x27000` | 56 KiB |
| FDS 应用数据 | `0x27000–0x29000` | 8 KiB |
| Bootloader 代码区 | `0x29000–0x2E000` | 20 KiB |
| MBR 参数 / Bootloader settings 备份页 | `0x2E000–0x2F000` | 4 KiB |
| Bootloader settings 页 | `0x2F000–0x30000` | 4 KiB |

依据：`SDK/17.1.0_ddde560/gcc_nrf52.ld`、`Keil/DFU-nRF52.uvprojx`、SDK 的 `nrf_dfu_types.h`，以及 FDS 配置 `2 × 1024 × 4 = 8192` 字节。DFU 配置也保留 `NRF_DFU_APP_DATA_AREA_SIZE=8192`。

逐条解析项目 HEX 的实际数据记录：S112 镜像在片内覆盖 100,884 字节；Bootloader 代码区覆盖 18,588 字节，另有 8 字节 UICR；已有 settings HEX 在主备页各覆盖 804 字节。**这些镜像没有填满分区，并不意味着其空洞能直接分给应用。** FDS 当前真实记录占用和擦写次数需要读取设备，本次没有实机数据。

调试脚本的 84 KiB 应用区是另一种布局，不能用于说明保留生产 Bootloader/FDS 时还有 28 KiB 可用。

## 4. 已经生效的优化

- `-Os`、LTO、独立函数/数据节、链接垃圾回收、nano libc。
- 发布配置关闭 RTT/BLE 日志，排除内置字体，固定屏幕尺寸、颜色和字体方向。
- GUI 使用精简整数输出。最终 ELF 无 `sprintf/snprintf/vsprintf/vsnprintf`、`gfx_vformat`、`mini_vsnprintf`。
- 当前 WDT SDK 实现已使用 32 位换算。最终 ELF 没有软浮点 `__aeabi_f*` / `__aeabi_d*`，也没有 `__aeabi_uldivmod` / `__udivmoddi4`。
- H/V 单轴绘制、两个字体初始化函数局部禁止内联、局刷 LUT 模板生成已经存在；第三轮报告中的 **256 字节节省已包含在本次 53,888 字节内**。

所以，删除未链接函数或被宏排除的字模、去掉 `-g3`、再次替换 printf 或再次移出字体，都不能获得旧报告所述的同一笔收益。缩小 BSS 缓冲和栈主要节省 RAM。

## 5. 仍值得评估的方向

### 优先级一：建立体积预算，并针对热点做小规模 A/B

建议硬上限继续保持 57,344 字节；将 **53,248 字节（保留 4 KiB）**作为近期预警线。当前超出该预警线 640 字节。如果希望保留 8 KiB，则应用应降至 49,152 字节，需净减少 **4,736 字节**。

从 `epd_gui_update`、月历绘制、命令适配和重复状态处理入手，检查重复错误路径、适合共享的实现和局部内联膨胀。函数大只是排查依据，不保证抽函数或增加 `noinline` 就会变小。每个方案用完整发布链接结果比较，并保留现有并发、恢复和 GUI 行为；本次没有新增 A/B 实验，因此不承诺节省字节数。

### 优先级二：精简广播数据编码

当前广播只使用设备全名、Flags，以及扫描响应中的服务 UUID；通用 `ble_advdata_encode` 本身有 918 字节，连同已归属的辅助函数为 1,144 字节。

可评估专用编码器，同时保留现有广播生命周期。预期属于百字节级候选；这些 1,144 字节是现有成本，不是净收益。必须保留设备名长度限制、UUID 类型和编码、扫描响应、重连及 DFU 切换行为，并验证实际扫描结果。

### 优先级三：专用内置双页日志替代 FDS

当前持久化对象为配置和日历标注。可评估保留两页、使用类型/长度/序号/CRC/提交标志的追加日志，继续使用 SoftDevice 兼容异步 Flash 后端。

FDS 已直接归属的符号有 2,360 字节，另有内联到调用方的代码；但新的换页、掉电保护、重试和迁移代码也会消耗空间。它是千字节级优化的候选方向，**净收益必须通过原型确认**。本方案仍占 8 KiB 数据区，不能再把这 8 KiB 算成新增收益。

需验证每个擦写边界的掉电恢复、旧 FDS 数据迁移、两类记录同时保留、异步源缓冲生命周期以及重复更新耐久性。不能简单将 FDS 改成一个页。

### 更大容量需求：完整迁出配置和标注

如果上述方案仍不够，将两类持久化数据全部迁至外置 Flash，才可能移除 FDS，并将应用上限从 `0x27000` 扩至 `0x29000`：**理论增加 8 KiB 应用容量**，新上限为 64 KiB。

这需要为外置存储明确保留分区，防止字体更新覆盖；还要设计过渡固件，在旧 FDS 被更大应用覆盖前完成迁移，并核实实际使用的 Bootloader/DFU 对应用数据保留和镜像大小的限制。仅改链接脚本不构成完整方案。

## 6. 建议

短期优先恢复至少 4 KiB 应用余量，先尝试热点去重和广播编码精简。若需要持续增加数 KiB 功能，再做专用内置日志的隔离原型；完整外置持久化作为扩大容量的后续方案。

本次确认了当前发布配置能够构建、BIN 大小与 ELF 装载数据一致，并检查了实际存活符号。没有修改固件，所以未重复运行功能回归；没有进行新的优化实现、硬件测试或读取设备。Bootloader 与 settings 的字节统计来自仓库现有镜像，不代表设备当前烧录状态。
