# 内置 Flash 数据与外置迁移清单（2026-10-05）

分析对象是当前 `0x3D` 优化固件的 ELF、MAP、BIN 和源代码，没有读取设备实机 Flash。应用镜像为 **55,508 B**，应用分区容量 **57,344 B**，余量 **1,836 B**。

大块业务数据已经外置；仍留在应用镜像中的独立 `.rodata` 输入段只有 **964 B**，另有 **212 B** RAM 变量初值、**512 B** 中断向量表、**96 B** SDK 事件注册段和少量链接元数据。指令中的立即数、跳转表和常量池不能按独立资源的方式直接搬走。当前内置占用主要来自执行代码。

## 内置区域

地址范围采用左闭右开。

| 区域 | 地址范围 | 当前用途 | 外置判断 |
| --- | --- | --- | --- |
| MBR / SoftDevice | `0x00000–0x19000` | 启动及 BLE 协议栈，区域容量 100 KiB | 当前启动链必须保留内置 |
| 应用 | `0x19000–0x27000` | 当前 55,508 B 固件，以下小数据包含其中 | 可评估小资源外置；执行代码仍由内置区运行 |
| 旧 FDS / 应用数据保留区 | `0x27000–0x29000` | 保留 8 KiB；当前应用已无 FDS 读写 | 最值得评估回收的空间，但需调整 Bootloader 和 OTA 规则 |
| Bootloader | `0x29000–0x2E000` | Secure DFU，当前镜像实际 18,588 B | 当前升级入口必须保留内置 |
| MBR 参数 / DFU settings 备份页 | `0x2E000–0x2F000` | 升级参数及 settings 备份 | 保留内置 |
| DFU settings 页 | `0x2F000–0x30000` | 应用校验、版本与升级状态 | 保留内置 |

Bootloader 地址配置另位于 UICR，不属于上述普通 Flash 数据区。

## 应用仍包含哪些数据

下列业务小表合计 **418 B**，已按最终 ELF 确认。`MonthDayMax` 和 `days_in_month` 两个符号共用同一地址，月份天数表只计算一次。

| 数据 | 实际字节 | 外置判断 |
| --- | ---: | --- |
| 基础字体几何参数 | 27 | 可从外置字体头加载，但需缓存和独立边界校验 |
| 待办字体几何参数、字号列表 | 54 + 6 | 可研究，迁移毛量小，新增读表代码可能抵消收益 |
| 待办 Unicode 禁止字符范围 | 72 | 建议保留，固件需要独立校验上传文本 |
| UI 模式和组件类型校验表 | 19 + 19 | 建议保留，属于资源格式约束，不是用户布局数据 |
| 日历 section 项目长度和数量校验表 | 32 + 32 | 建议保留，保证外置日历包符合当前固件要求 |
| 七段时钟数字字形、线段几何 | 10 + 35 | 技术上可放入外置 UI 包，毛量仅 45 B |
| 每月天数、星期算法小表 | 12 + 12 | 技术上可外置，读表开销相对收益太大 |
| `NO DATA` 兜底字形及索引 | 25 + 7 | 保留；外置字库/UI 缺失或损坏时仍要显示提示 |
| 屏幕型号参数 | 12 | 可参数化外置，但当前只有一种面板，收益小 |
| UC8179 驱动函数指针表 | 44 | 保留，与当前固件的代码地址绑定 |

此外，两个合并字符串块合计 **204 B**，包括显示短词、TODO 提示、设备名/BLE 相关文本等。仅显示文案适合资源化；BLE 恢复入口和协议所需字符串应保留。不能把全部 204 B 当作已经可以净节省的空间。

其余 `.rodata` 含 SDK 的 SPI/定时器描述、事件分发表、运行库指针等，以及 SDK 放在常量段中的短延时代码。它们参与启动或硬件运行，不能因段名是 `.rodata` 就作为业务资源搬走。

212 B 的 `.data` 初值包含默认 GPIO、时间/版本状态初值、定时器对象、待办默认参数及 C 运行库状态。它们在启动时复制到 RAM，不是用户配置的持久化副本。当前 GPIO 用户配置已经从外置包读取；活动状态仍需 RAM，迁移初值还会改变启动初始化路径。

UC8179 当前也没有六套 42 B 的内置 LUT 数组：局刷复用一份栈缓冲，由少量常数现场生成；全刷使用控制器 OTP LUT。因此不能再将 `6 × 42 B` 算作可迁移资源。图片直接传入屏幕显示 RAM，固件没有内置整幅图片。

| 内容 | 默认外置区域 |

| 资源分区表 | `0x00000–0x01000` |
| 设备配置 | `0x01000–0x02000` |
| 日历标注 | `0x02000–0x03000` |
| 资源更新状态 | `0x03000–0x04000` |

这些是默认资源布局，现场分区表和实际已保存内容需要设备读回确认。预留区可能有历史 FST 数据，不能直接视为已擦除。

默认发布包 `fonts.ers` 为 9,634 B，`calendar.ers` 为 1,480 B，`ui.ers` 为 440 B，均已外置。源码里仍保留的三套基础字模数组共 9,534 B，但发布配置 `GUI_INCLUDE_INTERNAL_FONTS=0`，最终 ELF 没有这些数组，删除源码数组不会再释放应用 Flash。

## 推荐顺序与预期收益

1. **优先评估旧 8 KiB 应用数据保留区的回收。** 当前设备配置和日历标注都使用外置持久化，最终 ELF 没有 `fds_*` 或 `nrf_fstorage_*` 函数。然而 Bootloader 的 `NRF_DFU_APP_DATA_AREA_SIZE=8192` 和 `DFU_REGION_END` 仍将应用上限限制在 `0x27000`，发布审计也保护同一区域。回收需要同步 Bootloader、链接布局、发布工具及升级兼容验证；仅改链接脚本不足以完成。若确认回收全部 8 KiB，应用容量可从 56 KiB 增至 64 KiB，当前代码大小不变时余量可达到 **10,028 B**。这是候选容量收益，并非本次已实现结果。
2. **如有 UI 资源化需求，再迁显示文案与七段绘图参数。** 原始数据是几十至几百字节，需扩展外置 UI 格式、读取和缓存机制；实际净节省只能迁移后对照构建确认。
3. **保留格式校验、兜底显示、启动及驱动描述数据。** 外置包缺失或损坏时，设备仍需要 BLE 恢复入口和固定的资源约束。剩余小表没有可直接搬走的多 KiB 数据。

本次仅生成清单和审计输出，没有修改固件代码、分区或设备数据。机器可读的符号清单位于 `output/flash-optimization-20261005/data-audit.json`。
