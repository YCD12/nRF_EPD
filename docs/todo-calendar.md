# 待办工作区

新版提供两种待办布局：模式 `4` 为左侧待办、右侧日历；模式 `5` 为全屏待办。两种布局共享同一份事项、显示数量、字体和时间调度。模式 `4` 沿用右侧月历、日期标注、农历及节假日；待办标题提供当天总数和温度，正文区域去掉日期、时钟、底部设备信息及待办分隔线，让事项使用可用空间。

网页统一在「待办事项」工作区管理事项、预览和保存。图片工作台移除重复的待办入口，但保留旧静态待办草稿，可点击「导入旧版待办」手动迁移；导入前不会自动改写旧草稿。

标题行显示 `TODO 当前/总数`。当前为屏幕实际显示条数，包含提前显示、进行中、过期保留及常驻事项，受显示数量限制；总数为未完成的常驻事项加上显示时间窗口与当天相交的事项，包含当天稍后触发和已结束的记录，不受显示数量限制。显示窗口包含提前和过期保留时长，因此跨午夜时当前数量不会超过总数。右端温度复用日历的数字与单位字体，显示屏幕本次刷新读取的温度。标题下横线复用日历框线的位置与粗细，在分屏中贯穿左右区域。网页没有收到设备温度时预览显示 `—℃`。

## 使用

1. 连接版本达到 `html/js/main.js` 顶部 `NEW_WEB_MIN_FIRMWARE_VERSION` 的设备，当前门槛与 MCU `APP_VERSION` 均为 `0x21`。待办读写、两种布局、自定义字体、大字号、加粗、斜体及提前/保留时间统一使用该门槛，不再按历史功能版本分别限制；低于门槛使用旧版网页。设备缺少基础资源时，先安装默认设备资源。
2. 添加事项，设置触发时间和截止时间，截止时间必须晚于触发时间。勾选「常驻显示」时无需设置时间。
3. 设置显示数量 `1–8` 条（默认 `5`）、字号 `9/12/16/20/24/32`（默认 `12`）及字体，可分别开启加粗、斜体或同时开启。字号沿用点数口径，网页生成的实际像素高度约为字号的 `4/3`。大字号按可用行高限制显示数量，选择字号时会提示并调整数量，事项总数和排队规则不变。每项最多 `64` 个 UTF-8 字节，通常约 `21` 个汉字，最多保存 `32` 项。
4. 设置「提前显示」和「过期保留」，默认为 `10/5` 分钟，均可设为 `0–1440` 分钟。设为 `0` 分别关闭提前显示或截止后的保留。两种布局和全部定时事项共用这两个时长。
5. 编辑后先点击「添加事项」或「更新事项」，再点击「保存到设备」。未提交的编辑会提示处理。等待字模生成、Flash 提交、校验和资源应用全部完成，再切换「待办事项+日历」或「全屏待办」。切换模式会校时，保存本身不会切换模式。

时间按网页所在时区的本地日期时间设置。蓝牙断开后，设备继续按自己的计时器调度。断电重启后，待办仍保留在外置 Flash；硬件没有掉电走时能力，需要重新连接网页校时。浏览器草稿和设备内容独立，设备读取或备份导入会替换草稿，保存才会更新设备。

待办 + 日历会在本地日期变化后更新右侧月历及当天红色标记，即使左侧没有事项或只有常驻事项也会更新。日期检查以最后成功刷新到屏幕的日期为准；排队期间跨天或跨越触发时间时，待办刷新使用开始执行时的当前时间。跨午夜的长刷新完成后，下一次定时检查补齐新日期，成功后停止重复刷新；字库读取失败仍按原有间隔退避重试。

## 排序和显示

- 未完成的常驻事项优先，并占用显示名额。常驻事项不受触发和截止时间限制。
- 普通事项从 `触发时间 - 提前时长` 开始显示，按触发时间、截止时间、事项 ID 升序排列。提前阶段使用黑色空心方框；到触发时间方框变红，直到保留期结束。黑白屏使用黑色方框。
- 到截止时间，事项正文每行显示黑色删除线；保留期内仍占显示名额，到 `截止时间 + 保留时长` 消失。时间边界包含开始、不包含保留结束，时间加减使用溢出保护。
- 超出显示数量的事项排队，前面的事项完成或保留结束后自动补位。过期保留中的事项继续占名额。
- 完成立即隐藏，过期在保留结束后隐藏；网页保留记录，便于修改、重新启用或删除。网页上的完成和编辑操作需再次保存后设备才会应用。
- 屏幕只显示事项正文和方框，不显示截止时间或常驻文字。正文按可用行高换行或省略，删除线覆盖实际可见文字。实心黑色方框表示常驻，空心方框表示定时事项。
- 模式 `4` 使用自定义左侧区域；区域没有可用正文宽度，或行高无法容纳所选字体时，暂停待办显示，调整布局或字号后恢复。模式 `5` 使用整屏事项区域。

网页可模拟任意时间，查看提前显示、触发、截止删除线、保留结束、排队和补位。JSON 导入和导出可备份时间、状态、提前/保留时长及字体选择；旧本地草稿和备份缺少这两个时长时采用 `10/5` 分钟，保存到设备后启用。设备回读旧 v1/v2/v3 包时显示 `0/0` 分钟，保留其原有时间行为，可自行修改后保存。手动导入旧图片工作台草稿时，静态待办转换为常驻事项并保留完成状态，长正文按 UTF-8 边界拆分，无法完整转换时保留旧草稿并提示处理。

设备每秒仅在 RAM 中计算显示集合、阶段和当天总数，只有可见列表、可见事项阶段、当前显示数量或当天总数变化、跨日或用户强制刷新时安排全刷。隐藏事项的进行中和排队数量变化不会单独触发刷新，无变化时不进行分钟刷新。传图、资源维护、正在刷新或低电量期间暂停调度，恢复后重新比较。失败刷新不提交屏幕快照，成功睡眠保留快照，避免连续全刷。外置字库首次 I/O 失败后停止当前待办帧的后续读取和分页，不提交画面；连续失败按开机运行时间等待 `1/5/15/30` 秒，之后最多每 `30` 秒重试。用户强制操作、新资源应用、跨日及离开待办模式清除等待，成功后恢复正常调度；正常缺字仍允许占位字形。物理屏幕更新仍需等待墨水屏刷新完成。

## 字体与持久化

缺字复用 [网页字模生成流程](web-font-generation.md)。默认 `9/12` 常规字形保留原有字模并补充缺失的 BMP 字符；自定义字体、更大字号、加粗和斜体在浏览器中生成待办专用字模，不替换日历和时钟的基础字体。字体标识包含字号、字形和字体名称，切换样式后会重新生成，避免复用错误字形。设备按真实字形边界安排基线、换行和省略。Emoji、扩展平面文字、控制及格式字符不接受。浏览器须能使用所选字体，否则无法生成相应字模。

字体包和待办包在同一设备操作锁、同一资源维护会话内提交：写入前检查版本、容量及旧包，先写入和校验 `fonts.ers`，再写入和校验 `todo.ers`，最后只执行一次 `LEAVE` 应用。中途保持 GUI 暂停，避免字体已经替换、待办仍引用旧字体时刷新。连接仍有效且 Flash 可写时，失败操作尝试恢复原字体、待办和分区表，校验后退出维护；无法恢复时明确提示恢复未完成，不提示保存成功。设备优先重试资源和模式确认通知，再执行耗时的 GUI 刷新，避免确认消息被刷新阻塞。

待办使用普通 ERS 包 `todo.ers`，分区 ID/type `9`，默认地址 `0x58000`、容量 `4 KiB`。旧设备首次保存时，网页从保留分区划出一个扇区，配置、日期标注、日历、布局和字体原有地址不变。没有足够保留空间时拒绝迁移。默认资源模板和打包工具包含空待办包；常规资源更新保留已安装待办及其专用字体，完整设备回读包含有效待办包。

单份存储依靠网页内存中的旧包尝试恢复，不保证掉电、断连或持续 Flash 故障后的自动回滚。CRC 和 ERS 提交标记拒绝未提交或不完整的数据；中断后可能需要重新连接并上传完整资源。

## TODO 数据格式

所有多字节字段均为小端。时间为设备本地 wall-clock epoch 秒，与现有计时方式一致。常驻记录的两个时间字段均为 `0`；普通记录的截止时间必须大于触发时间。

新网页保存使用 TODO v4：`16` 字节包头加 `count × 80` 字节记录，记录后附加 `5` 字节时间设置及字体名称。原有 TODO v1/v2/v3 仍可读取：v1 使用默认 `9/12` 常规字形、包头末尾六字节为零；v2 使用原有 `9/12` 自定义字体、trailer 为字体名称；v3 用于更大字号或非默认字形、trailer 为字形字节加字体名称。旧格式的提前与保留时长均为零。

| 偏移 | v1 / v2 / v3 / v4 包头字段 |
| --- | --- |
| 0–3 | `TODO`，魔数 `0x4F444F54` |
| 4 | 默认字体为 `1`；原有自定义字体为 `2`；扩展字形为 `3`；时间设置为 `4` |
| 5 | 记录大小 `80` |
| 6–7 | 记录数量 `0–32` |
| 8 | 显示数量 `1–8` |
| 9 | v1/v2 字号 `9/12`；v3/v4 字号 `9/12/16/20/24/32` |
| 10 | v1 为 `0`；v2/v3 为待办专用字体槽 `3`；v4 使用基础字体为 `0`、专用字体为 `3` |
| 11 | v1 为 `0`；v2 字体名称 UTF-8 字节数 `1–64`；v3/v4 为 `0–64` |
| 12–15 | 基础字体为 `0`；专用字体为非零标识 `fontKey:u32LE` |

v2 的字体名称 trailer 位于偏移 `16 + count × 80`，长度严格等于包头字节 `11`，不含 NUL 终止符或额外填充。名称用于设备回读和恢复网页字体选择，字体标识用于校验待办与字模是否匹配。

v3 同一偏移先保存字形字节：bit0 加粗、bit1 斜体，其余位为零；再保存包头字节 `11` 指定长度的字体名称。完整长度严格为 `16 + count × 80 + 1 + familyLength`。字号 `9/12` 且不加粗、不斜体时使用 v1/v2；v3 的这两档至少开启一种字形。旧 v1/v2 配置仍可读取并保存。

v4 同一偏移先保存 `5` 字节：字形字节 `u8`（bit0 加粗、bit1 斜体）、提前分钟 `u16LE`、保留分钟 `u16LE`，最后附加字体名称。两个分钟字段范围均为 `0–1440`，完整长度为 `16 + count × 80 + 5 + familyLength`，最多 `2645` 字节。默认 `9/12` 常规字形使用基础槽，包头 `10–15` 为零；自定义常规字形沿用 v2 字体标识；更大字号或加粗/斜体沿用 v3 字体标识和扩展 geometry，空名称表示网页默认字体。旧数据回读保持格式和时间语义，保存时统一转换为 v4。

| 偏移 | 每条 80 字节记录 |
| --- | --- |
| 0–3 | 非零、唯一的事项 ID |
| 4–7 / 8–11 | 触发 / 截止时间 `uint32` |
| 12 | bit0 常驻，bit1 完成，其余位为零 |
| 13 | 正文字节数 `1–64` |
| 14–77 | UTF-8 正文，未使用字节必须为零 |
| 78–79 | 必须为零 |

字体仍使用 `FPK1` version `1`，保留原有三个基础槽，允许 `count=3` 或 `4`。前三槽的记录 `flags` 必须为 `0`。可选第 `4` 槽的 index 为 `3`，记录 `flags` 保存非零 `fontKey`；其 geometry 支持原有基础槽 `0/1` 及六档扩展字形的固定边界。TODO v2/v3/v4 使用专用字体时，字号及字体标识必须与该槽匹配，基础字体和自定义字体不能混用。

`fontKey` 为 UTF-8 文本 `sourceSlot:fontFamily` 的 CRC32（基础字号槽为 `0/1`，字体名称先去除首尾空白；CRC 为零时取 `1`）。缺少专用字体、字号或标识不匹配时，拒绝应用并暂停待办自动刷新，重新保存匹配资源后恢复。

v3 字体标识为 UTF-8 文本 `todo-v3:size:bold:italic:fontFamily` 的 CRC32，`bold/italic` 分别为 `0/1`，空字体名称表示网页默认字体，CRC 为零时取 `1`。扩展 geometry 令 `px=ceil(size×4/3)`、`desc=ceil(px/3)`、`overhang=ceil(px/4)`：宽高为 `px+overhang`、`px+desc`，x/y 偏移为 `-overhang/-desc`，ascent 为 `px`、descent 为 `-desc`，占位字形 advance 为 `px+1`。v3 最大显示数为 `min(8, floor(384/(px+desc+6)))`。

发送沿用 `EPD_CMD_RESOURCE (0x26)` 的进入、分块写入、CRC 提交、校验查询和退出应用，不新增专用待办命令。模式切换使用 `SET_MODE (0x22)` 的 9 字节请求，mode=`4/5`；`0xAA` 表示模式已接受并安排刷新，不表示物理刷新完成。

打包：`python tools/resource_pack.py --check --records --fonts --calendar --ui --todo --output <目录>`。网页默认模板由 `tools/export_web_template.py` 生成。
