# Flash 去重实测（2026-09-16）

## 结果

按优化路线第 1 步完成本轮代码去重。生产配置重新编译的基线为 **52,716 B**，最终应用为 **52,412 B**，减少 **304 B**（约 0.58%）。56 KiB 应用区余量由 **4,628 B** 增至 **4,932 B**。

| 改动 | 单独启用后的应用大小 | 相对基线节省 |
| --- | ---: | ---: |
| GUI：公历数字/单位、农历月日、干支文字共用输出 | 52,540 B | 176 B |
| EPD 服务：时间、电压、MTU 共用格式化和发送封装 | 52,620 B | 96 B |

以上是同工具链、同生产配置的最终 BIN 对比，不是源文件行数或删除函数的理论大小。GUI 首轮仅合并公历输出省 64 B，随后合并农历输出又省 112 B；最终表格已包含两部分，不能再次叠加。

## 实现与兼容性

### EPD 服务

`EPD/EPD_service.c` 新增 `epd_send_prefixed_uint()`，三个通知入口共用缓冲、格式化和发送流程。最长前缀 `mtu=`、10 位无符号数字和终止符共需 15 字节，统一使用 16 字节局部缓冲。

保持 `t=`、`v=`、`mtu=` 的原有协议和发送顺序。格式化函数负责终止字符串，发送长度不包含终止符，无需将整个局部缓冲预先清零。

### GUI

`GUI/GUI.c` 提取三个公共函数：

- `gui_print_date_part()`：输出公历数值和单位，保留数字颜色、字体、补零和末尾空格。
- `gui_print_lunar_md()`：共用农历月日格式化缓冲和输出。
- `gui_print_lunar_year()`：共用天干、地支输出；各页面继续负责生肖、“年”及其颜色。

不改变各页面的坐标、分页裁剪和字体来源。已有整帧 golden 校验值全部保留，优化后的图像与原值一致。

### 字体传输

`EPD/font_transfer.c` 提取 `font_notification_send()`：先登记等待 TX，再调用 BLE 通知；队列满时等待 TX_COMPLETE，其他错误登记原有重试状态。

三个调用者继续各自维护在途回复、列表位置和流 ACK 快照，成功更新状态后才唤醒后续任务。失败的流 ACK 在当前 scheduler worker 返回前恢复；重试只登记/排队，不会同步执行另一个 worker。调试日志统一为 notification failed，生产配置仍关闭日志。

## 后续判断

当前已验证的去重收益为百字节级。主程序和服务的大函数包含跨模块内联，源码看似重复不一定对应两份最终机器码；不能按模块体积推算可删除量。

INIT 排序、断连代次、刷新取消、ACK 快照等分支承担不同状态语义，本轮没有将这些分支强行合并。FST2 兼容、CRC、掉电提交顺序也继续保留。

现有余量约 **4.82 KiB**。如果后续明确需要千字节级空间，应按[优化路线](flash-optimization-roadmap-20260915.md)继续评估专用存储日志；需要扩大应用分区时再处理配置和标注外置迁移、字体分区及 Bootloader 边界。
