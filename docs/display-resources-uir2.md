**显示资源 UIR2：网页设计 → 外置 Flash → 设备绘制**

历史固件从 `0x3E` 开始使用 UIR2；当前完整协议固件统一编号为 `APP_VERSION = 0x21`，网页的全部新版能力统一由相同的 `NEW_WEB_MIN_FIRMWARE_VERSION = 0x21` 判断，不再按历史功能版本分段限制。五种模式的正常显示布局与样式由资源决定；设备只负责取得时间、温度、电压、待办状态，以及执行历法、字形解码和绘图算法。

本次完成了审计列出的固件样式外置：

| 范围 | 现在保存在资源中的内容 |
| --- | --- |
| 待办 | 独立标题和温度、正文矩形、缩进、行距、方框、状态色、常驻填充、删除线、省略符、空态及错误文案 |
| 日历 | 星期栏颜色、当天圆形、节日/周末颜色、日期和副标题间距、虚线、休班标记、角标和红点的大小与偏移、ASCII 字号规则、标注字体引用 |
| 时钟 | 数字段码、七段的位置及长度、数字间距、冒号、居中跨度和偏移；局刷窗口由同一份几何计算 |
| 文字 | 年月日、星期、农历、节气倒计时、温度单位、电压单位、名称格式及名称尾部字符数；同步提示和网址 |
| 字体 | 普通组件可引用槽位 0–3；基础槽位的度量从字库头读取，可在网页重绘为新的像素字号 |
| 通用能力 | 图层顺序、模式、显隐条件、前景/背景/强调色、文字对齐、组件矩形裁剪、线条宽高 |
| 网页预览 | 资源编辑器、待办、日期标注使用同一个点阵渲染器，读取将要编码的 UI 模型和真实外置字模 |

待办温度是默认布局的 **组件 23**，两种待办模式共用，默认右边界为 `775`、基线为 `36`。以后移动它只需要改网页布局并重新发送资源。

**使用和迁移**

1. 编译并更新到当前完整协议固件（`APP_VERSION = 0x21`）。旧 UIR1 不能直接由新版固件绘制；BLE 维护入口仍然可用，缺少新版资源时显示最小恢复提示。
2. 在网页载入原资源工程，或生成默认资源。旧 UIR1 二进制/19 组件布局会迁移成 UIR2：拆分原组合文字，补入待办和原来隐含的样式。原有日期、待办和字模内容继续保留。迁移后应检查五种模式的预览，再发送新版资源。
3. 在“布局与样式”JSON 中编辑组件。资源编辑器的“预览模式”包括模式 1–5；待办和标注工作区也使用该布局。未知字段会报错。
4. 点击重新生成并发送资源。现有 ERS 分区、CRC、维护事务和热加载路径继续负责保存。重启后从 UI 分区 6、字库分区 7、待办分区 9 恢复。
5. 导出完整工程或 ZIP，保留 `ui-layout.json` 与其他资源。字体、字号和未完成的编辑也可存入网页草稿/工程。

网页对达到统一固件门槛的设备开放 UIR2 资源传输，不再设置 `0x3D/0x3E` 等独立网页门槛。设备需实现对应的新版资源格式；读写、即时应用和删除仍按设备实际报告的能力位协商。布局、颜色、文案和参数调整只需要发送资源。

网页支持直接打开 `html/index.html`，也支持 HTTP/HTTPS。`file://` 下从随网页生成的 `default_fonts.js` 读取默认字模，避免浏览器拦截对本地 BIN 的 `fetch()`；字模内容与原 BIN 一致，仍可导入个人字库和工程。更新默认字模后运行 `tools/export_web_template.py`，其 `--check` 同时检查网页工程模板和默认字模脚本。

资源包的待办字体依赖只从包内 TODO 设置读取。旧版本省略的字体、加粗和斜体字段按默认值处理，不混入浏览器待办草稿的选择；因此本地草稿使用自定义字体也可正常载入默认资源。包内真正缺失或不匹配的字库仍会阻止发送。

历史固件 `0x3F` 增加了[外置 Flash 分区删除与整片清空](external-flash-delete.md)，已包含在当前统一编号 `0x21` 的完整协议固件中，可在“设备资源”中操作并在删除后重新安装。

历史固件 `0x40` 修复清空后仍周期刷新及旧待办缓存未停用的问题，当前完整协议固件 `0x21` 包含该修复：显示资源缺失时等待重新安装，成功激活后恢复定时刷新。连接网页不会自动重装资源；设备资源面板会提示生成或载入资源后发送。

**编辑模型**

根对象为 `{ "version": 2, "components": [...] }`，最多 64 个组件，数组顺序就是绘制顺序。完整默认工程见 [resources/ui-layout.json](../resources/ui-layout.json)，参数和校验范围见 [resources/ui-schema.json](../resources/ui-schema.json)。

| 字段 | 含义 |
| --- | --- |
| `id` | 唯一 ID，1–255。12/17 供分屏/全屏时钟调度查找；20/21 是默认待办正文 |
| `modes` | 模式位图：日历 1、分屏时钟 2、全屏时钟 4、待办日历 8、全屏待办 16；可相加共用组件 |
| `kind` | 1 文字、2 矩形/分隔线、3 月历、4 七段时钟、5 星期栏、6 待办正文 |
| `flags` | 1 隐藏；2 仅未校时时显示；4 仅距离下一节气非零天时显示；8 仅节气当天显示 |
| `x/y/width/height` | 800×480 内的矩形；所有图形及字形都裁剪在其中 |
| `fonts` | 三个字体引用，0–3；255 表示不用。文字模板的 `f0/f1/f2` 选择其中一个引用 |
| `foreground/background/accent` | 0 黑、1 白、2 红；具体控件还可配置状态颜色。透明文字不会自动填充整个矩形，可用底层矩形组件设计背景 |
| `align` | 文字左/中/右对齐：0/1/2；其他控件为 0 |
| `value0/value1` | 时钟缩放与每组位数；缩放为 2–10 偶数，时分各两位；其他组件为 0 |
| `style` | 对应控件类型的完整参数对象；字段及范围由 schema 定义 |
| `text` | 文字组件一条模板；月历两条纯文本为“班/休”；待办三条纯文本为空态、错误、省略符 |

文字模板支持 `{year}`、`{month}`、`{day}`、`{month2}`、`{day2}`、`{weekday}`、`{lunar_month}`、`{lunar_day}`、`{stem}`、`{branch}`、`{zodiac}`、`{week}`、`{temperature}`、`{voltage}`、`{ssid}`、`{name_tail}`、`{jieqi}`、`{jieqi_days}`、`{todo_count}`、`{todo_daily}`。`{c0/c1/c2}` 切换颜色，`{f0/f1/f2}` 切换字体引用。

例如温度模板 `{temperature}{f1}℃` 中，数字用 `fonts[0]`，单位用 `fonts[1]`。电压 token 仅输出数字，单位 `V` 是可编辑文本；小数位由 `voltage_decimals` 控制。名称尾部按 UTF-8 字符计算，数量由 `name_tail` 控制。

字体槽位 3 与待办专用字体共用；改变待办字体也会影响引用槽位 3 的其他组件。普通 UI 可使用三个基础槽位独立设计。基础字库支持最大宽 64、高 80 的有界度量；网页重绘提供 8–43 像素字号，待办点字号仍提供六档。度量、字形边界、分区容量均保留校验。

待办行数上限取所有可见正文矩形的最小容量，由实际字体高度和 `row_padding` 计算，不再依赖固定 `384`。布局缩小时需同步减少行数。旧字号的基线/行距与扩展字体的度量布局分别由对应样式参数控制。

**二进制与生成**

外层仍为 ERS ABI 1，UI 模块资源版本为 2。UIR2 头为 16 字节：`magic:u32="UIR2"`，其后六个 `u16` 分别是版本 2、记录数、800、480、记录长度 32、保留 0。所有整数均为小端。

每条组件记录为：8 个 `u8`（模式位图、ID、类型、flags、三个字体、对齐），6 个 `i16`（矩形及 value0/value1），4 个 `u8`（三色和保留 0），`params_offset:u16`、`params_count:u8`、`text_count:u8`、`text_offset:u16`、`text_length:u16`。记录表后依数组顺序存放每条记录的参数和文本，禁止间隙及尾随数据。

参数是 schema 顺序的 `i16`。文本是以 NUL 结尾的 UTF-8/模板操作流：1+字段 ID、2+字体引用、3+颜色；其他字节为字面文本。单条含结束符不超过 255 字节，运行时字段展开不会作为格式字符串执行。

源文件改动后运行：

```text
python tools/ui_resource_codec.py
python tools/export_web_template.py
python tools/ui_resource_codec.py --check
python tools/resource_pack.py --ui --ui-layout resources/ui-layout.json --output output/my-resources
```

生成器同步输出网页 schema/默认源、固件参数索引/范围和测试载荷；命令行和网页对默认源生成相同的字节。

**验证与边界**

[test_ui_render.py](../tests/test_ui_render.py) 将网页产生的 UI、TODO、标注和字模交给真实 C 分页渲染器，对普通版与固定屏幕版逐像素比较。场景覆盖五种模式、温度移位/负温度、长文本、状态色、粗线、标注、节气/校时、字体与裁剪。

`build.bat` 的主机测试保持 Node.js 可选：未安装时会明确跳过网页和像素对照测试，继续编译固件。需要执行完整网页验证时，将 `node` 加入 PATH，或为像素对照测试设置 `HOST_NODE` / `NODE_BINARY` 指向可执行文件。

时钟局刷使用资源中的实际段形边界。彩色时钟或画布与其他组件重叠时回到完整绘制，避免单色局刷损坏资源设计。

本次验证：完整主机测试返回 `HOST_OK`，389 项网页测试通过，25 个场景分别在普通版与固定屏幕版完成 50 次逐像素一致性比较，模拟 Flash 重启和资源热加载通过。Chrome 直接打开本地文件及 HTTP 页面均可生成七个资源包、预览五种模式，本地文件不再请求 BIN 字模。生产 ARM 构建成功，应用占用 57,044 / 57,344 字节，剩余 300 字节；后续新增固件能力需要留意空间预算。固件与默认资源包分别位于 `output/ui-externalization/firmware/` 和 `output/ui-externalization/uir2-resources.zip`；默认包包含默认配置和空待办，已有个人数据应通过网页载入原工程后迁移。

内置 `NO DATA` 保留为资源缺失时的最小恢复例外。单张图片直传仍是既有独立路径，未新增图片持久化或轮播。本次自动验证使用主机与模拟 Flash；实际断电重启和屏幕观感仍需上设备核对。
