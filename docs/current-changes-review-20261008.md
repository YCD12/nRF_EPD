## 已确认并修正的问题

| 问题与触发条件 | 修正后的行为 |
| --- | --- |
| 隐藏待办进入、触发或离开队列，可见事项和标题不变仍请求全刷 | 刷新判断只比较影响画面的集合、阶段和数量；模式 4/5 的实际 96,000 B 画面相同，刷新请求保持 1 次，原实现为 3 次 |
| 外置字体发生读取错误，后续字符成功掩盖错误，带占位字形的画面被当作成功 | 读取错误累计到整帧，失败帧不提交待办快照、不触发面板刷新，后续自动重试；正常缺字仍可使用占位字形 |
| 普通资源升级保留了旧待办，却用另一字体替换待办专用槽 | 普通升级同时保留原专用字体身份和全部字模；主动修改待办字体继续按用户选择替换 |
| 新字体提交后待办上传、校验或应用失败，留下字体和事项不匹配 | 写入前完成旧包、版本及容量检查；可恢复的失败恢复旧字体、待办或原分区表，校验后退出维护；恢复失败明确报告，不返回保存成功 |
| UTC+5:30、UTC+5:45 等时区被整小时字段截断，与网页待办时间不一致 | 将剩余分钟折入既有时间字段，保持协议兼容；正负时区、跨日和模式切换均覆盖 |
| SDK 的 ECDSA 启动校验分支直接返回成功 | 恢复实际 P-256/SHA-256 验证；签名、固件、公钥篡改及 crypto 错误均拒绝。当前默认发布仍使用 CRC 启动校验和签名 InitCommand |
| Bootloader BIN 包含 UICR 地址跨度，膨胀到约 256 MiB | BIN 只含连续程序内容，HEX 保留必要 UICR 记录 |
| 实际 Makefile、编译参数及链接脚本变化未触发增量重建 | 在构建图中追踪实际入口、有效参数和链接脚本；修改后重新编译或链接，无变化时不重编 |
| 发布检查只验证地址范围，可能接受错误向量或错误 SoftDevice | 验证固定入口处的栈指针和 Thumb 复位地址，并核对 S112 7.3.0 信息字段、大小及 DFU firmware ID |
| 重新打包失败会先删除旧 ZIP/settings/full，却留下旧清单 | 在临时目录生成和审计，成功后发布，清单最后替换；可捕获的失败保留或恢复已有产物 |

待办说明也同步到实际行为：隐藏队列变化不刷新，过小自定义窗口暂停显示，单份 Flash 下的恢复有明确限制。

## 剩余限制与优化顺序

1. **优先控制 Bootloader 体积。** 84 B 已非常接近链接上限。新增日志、功能或切换工具链前必须实编检查；不要通过关闭验签换取空间。若继续扩展升级功能，需要重新评估分区。
2. **外置资源可评估持久恢复日志或双槽。** 目前恢复副本在网页内存中；掉电、断连、持续 Flash 故障，或浏览器挂起超过固件 60 秒维护超时，仍可能留下不匹配的单份包。CRC、提交标记和字体身份校验能拒绝坏包，但无法自动找回旧数据。双槽方案需先按实际字体包大小评估剩余 156 KiB，不能直接假设足够容纳另一份完整字库分区。
3. **继续搬迁小常量的收益有限。** 大块日历、布局、字体、待办和配置已经外置。上次 ELF 审计的独立 `.rodata` 仅 964 B，可迁移显示文案及小表约几十至几百字节，增加读取、缓存和校验代码可能抵消收益。优先减少实际重复代码和无效刷新。
4. **可减少失败恢复中的额外擦写。** 当前保守地在调用上传前标记可能已修改，即使失败发生在 BEGIN 前也可能恢复整包。客户端未来可报告写入阶段，保留对 BEGIN ACK 丢失的保守处理，同时减少确定未写入时的恢复成本。

首次安装此内置布局仍需配套 full HEX 经 SWD 更新 Bootloader；应用 OTA 不会更新 Bootloader。后续硬件验证应覆盖实际签名 DFU、满容量应用、断连/掉电恢复、栈使用峰值以及真实墨水屏刷新。宿主验证和静态检查不能替代这些项目。
