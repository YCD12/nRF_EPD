# 外置配置与用户标注：P4 实施结果

## 结论

P4 已将 EPD 配置和用户日历标注的持久化后端从内部 FDS 切换到外置 Flash 分区 2、3。运行时仍保留 14 B 配置副本和最多 1,040 B 的标注活动缓冲；固件不再链接 FDS/fstorage 执行代码，但按既定要求继续保留内部 `[0x27000,0x29000)` 8 KiB 地址区域，链接范围和 Bootloader 配置没有改变。

外置数据仍为单份存储。没有外置固件槽，没有记录主备副本。

## REC1 单记录格式

配置和标注继续使用已经验证的 32 B ERS 包头。ERS 载荷以 16 B REC1 头开始：

| 偏移 | 大小 | 内容 |
| ---: | ---: | --- |
| 0 | 4 | 记录 magic：配置 `EPC1`，标注 `ANC1` |
| 4 | 2 | schema，当前为 1 |
| 6 | 2 | REC1 头长度，固定 16 |
| 8 | 2 | 业务数据长度 |
| 10 | 2 | flags；bit0 为配置删除墓碑 |
| 12 | 4 | 业务数据 CRC32 |

ERS revision 是记录序号。保存时依次执行：使旧提交失效、擦除单个 4 KiB 分区、写 REC1 和业务数据、回读计算 ERS CRC、写 ERS 头、最后写提交标志。任何一步失败都不会把未提交数据加载为有效配置。

- 配置业务数据固定 14 B；默认资源包共 62 B。
- 标注业务数据沿用 ANNO v1，16–1,040 B；空标注资源包共 64 B，最大包为 1,088 B。
- 内容未变化时直接返回成功确认，不擦除 Flash；一旦单份记录写入失败，立即取消内存去重缓存，再次保存相同内容仍会真实重写 Flash。
- I/O 失败最多执行四次尝试；最终失败会发送失败状态，不会报告保存成功。
- 配置清除写入已提交墓碑，只有提交成功后才允许复位。
- 标注保存期间锁定活动缓冲；收到清除请求时顺序完成当前保存，再提交空 ANNO 记录。

## 保存确认

应用版本提升为 `0x33`。持久化完成后固件发送 12 B `0xA8` 通知：

| 字节 | 内容 |
| --- | --- |
| 0 | `0xA8` |
| 1 | 分区 ID：2 配置，3 标注 |
| 2 | `rs_result_t`，0 表示成功 |
| 3 | 保留 |
| 4–7 | 已提交 revision，小端 |
| 8–11 | 业务数据 CRC32，小端 |

网页保存标注前计算预期 CRC，只接受分区 ID 和 CRC 都匹配的成功通知。写特征成功仅表示 BLE 已接收；网页不会再据此显示“已保存”。断连、超时、CRC 不匹配或设备错误均显示未确认。

后续修复版本提升为 `0x34`，增加迁移导出专用的配置回读确认：网页发送
`0x93 + token`；固件等所有配置命令和外置 Flash 保存完成后返回
`0xA9 + token + result + 14 B epd_config_t`。只有 `result=0` 才允许生成迁移文件。
旧固件连接期间修改过配置时，网页会要求断开重连后再导出，避免把连接时的旧缓存写入备份。

损坏或中断的标注上传只在 BLE 中断里设置恢复标志；旧记录的外置 Flash 读取在主循环执行，恢复完成前不会向显示和回读路径暴露接收了一半的数据。

## 旧数据迁移

当前网页增加“导出配置/标注迁移备份”。它先从旧固件读取设备配置和 ANNO 标注，再下载 `EPD-MIG1` JSON。该文件不写回设备，只作为主机备份。

转换命令：

```bash
python tools/resource_pack.py --migration-bundle epd-migration.json --revision 1 --output migration-pack
```

工具严格检查配置为 14 B，并校验 ANNO magic、版本、记录宽度、总长度、条数、日期、flags、标签长度和日期排序。输出：

- `epd-config.ers`
- `calendar-annotations.ers`
- `records.json`

新设备或无需保留旧数据的设备可使用 `--records` 生成板级默认配置和空标注。

建议迁移顺序：

1. 使用网页连接旧固件，导出 `EPD-MIG1` 备份并保存在主机。
2. 用打包工具生成配置和标注 ERS 包。
3. 官方 DFU 安装维护固件。
4. 上传分区表、日历、UI、字体、配置和标注包，并逐项回读验证。
5. 官方 DFU 安装 P4 正常固件；读取设备配置和标注核对。

## 容量结果

应用区仍为 `[0x19000,0x27000)`，容量 57,344 B；RAM 链接区为 15,656 B，继续预留 2,048 B 栈。

| 构建 | Flash | 剩余 Flash | 静态 RAM | 扣除栈后剩余 RAM |
| --- | ---: | ---: | ---: | ---: |
| P3 正常固件 | 51,088 B | 6,256 B | 6,392 B | 7,216 B |
| **P4 正常固件** | **48,100 B** | **9,244 B** | **5,948 B** | **7,660 B** |
| P4 维护固件 | 27,320 B | 30,024 B | 3,148 B | 10,460 B |

P4 相对 P3 正常固件减少 2,988 B Flash 和 444 B 静态 RAM。相对外迁前 52,412 B 基线，正常固件净减少 4,312 B。主要收益来自移除应用的 FDS、fstorage、GC 和两套异步 FDS 状态机；内部 8 KiB 数据地址仍未回收。

## 验证

- 两种资源存储编译模式的断电、CRC、边界、重复包和提交测试通过。
- 配置/标注测试覆盖加载、去重、失败重试、配置墓碑、标注锁和延迟清除。
- 网页测试覆盖匹配 CRC 才确认成功及设备失败不误报成功。
- 资源打包器覆盖默认记录、迁移 JSON 和损坏 ANNO 拒绝。
- 完整主机回归通过，六种 GUI 黄金图 hash 与 P3 一致。
- 正常和维护 ARM 固件通过 56 KiB Flash 与 RAM 预算检查；最终 map 中没有 FDS/fstorage 符号。
- Keil XML、JavaScript 语法和生成文件检查通过。

本轮未烧录设备。真实 SPI 擦写耗时、断电重传、网页迁移、配置清除复位和官方 DFU 串联流程仍需在隔离测试设备上验证。
