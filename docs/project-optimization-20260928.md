# 资源生命周期与内存优化实施记录

基于[设计评审](project-design-memory-review-20260928.md)做局部重构，保留内置固件逻辑、外置业务数据和单张图片直写屏幕 RAM 的架构。当前实现无需重写屏幕驱动或 BLE 基础设施。

以下体积对照和 37 项网页测试为 2026-09-28 的实施记录；2026-09-29 复审后的修复、44 项网页测试和最新构建数据见文末。

广播行为已按 2026-09-29 用户澄清修正：断连后保持原间歇广播策略；“离线”不表示关闭蓝牙。此前新增的停止广播与禁止自动重播路径已撤回。

## 已实现的链路

```mermaid
flowchart LR
    A[网页编辑日历 / 布局 / 字模] --> B[生成并校验 ERS]
    B --> C[ENTER 维护会话]
    C --> D[BEGIN 使缓存失效]
    D --> E[顺序写入 / CRC / COMMIT]
    E --> F[LEAVE 重载与业务校验]
    F --> G[可选 校时 / RUN_OFFLINE]
    F --> I[使用外置数据刷新和计时]
    G --> H[通知发送完成 / 断连 / 保持原广播策略]
    H --> I
    D -->|断连或超时| J[取消事务 / 重载 / 可重传]
    F -->|格式错误| J
```

`resource_store` 管存储事务；`resource_protocol` 管维护会话与操作码；`resource_transfer` 管小包、重复请求和连接代次；新增 `epd_resources` 管字体、日历和 UI 的整体就绪状态。BLE 服务负责协调面板、配置和标注，`main.c` 负责广播与唤醒。资源模块不引用 BLE 服务结构体。

维护会话开始后，显示及配置/标注写入不能交叉执行；进入会话后再检查空闲状态，覆盖 ISR 恰好插入命令的窗口。断连清理、整个 ENTER 会话的 60 秒超时和重复 BEGIN/COMMIT 不会重复擦除或保留过期就绪标志。失败的业务校验保留待验证分区，不能通过再次请求离线绕过校验。

保持连接时 GUI 可正常刷新；网页切换模式会请求刷新，时钟继续走，单张图片仍可直接传入面板。资源维护会话、未就绪资源、传图和未完成的屏幕初始化保留显示互斥。断开时仍安排刷新以应用最新模式、时间和资源，但断连不是刷新的前提。显式断连命令等待最后通知发送完成，再关闭连接；不停止广播、不调用系统复位，也不释放/复用 SoftDevice RAM。命令断连和普通断连均沿用原广播间隔、超时及唤醒策略。缺失 GUI 资源时保持蓝牙恢复入口；图片模式允许没有 GUI 资源。

## 网页数据生成

- `resource_builder.js` 是可在浏览器和 Node 中运行的二进制编码器，处理 CAL1、UIR1、FPK1、ERS 头、CRC、时间戳与分区容量。
- `resource_editor.js` 管编辑、布局示意、字模文件、导入/导出工程；`resource_installer.js` 管设备上传、激活和离线，不负责生成格式。
- 未修改的模块保留原包；修改的模块 revision 加一。布局越界、时钟几何错误、UTF-8 溢出、字体结构损坏、计算表年份不匹配、容量/版本溢出均在上传前拒绝。
- 已有设备只更新日历、UI、字体，保留实际分区表、设备配置和标注。空白设备按原顺序初始化六个包。
- 根据 STATUS 能力位选择直接激活；旧固件继续使用原重启方式。新固件更新不会再靠重启使资源生效。
- 默认模板由 `tools/export_web_template.py` 从既有 Python 生成器输出；测试要求浏览器重新编码的载荷与 Python 逐字节一致。

范围：19 个固定组件的参数编辑和布局示意；不支持任意组件树、脚本或设备端 JSON。TTF/BDF 仍需转换成兼容 u8g2 字模；网页可替换和打包 `.bin`，并提示日历文字缺字。默认计算表覆盖 2025–2027，节假日表沿用仓库的 2026 数据，未重新核验或自动生成新年份的法定休班安排。

## Flash/RAM 实测

GCC ARM 9.3.1，`nrf52811_xxaa` 发布配置，`-Os/LTO`、固定 UC8179 三色面板、外置字体。Flash 上限仍为 57,344 B，栈仍为 2,048 B，堆为 0。

| 版本 | BIN | 静态 RAM 地址跨度 |
| --- | ---: | ---: |
| 实施前基线 | 49,188 B | 5,976 B |
| 相同新功能，撤销体积优化的对照版 | 51,156 B | 5,988 B |
| 最终实现 | **51,028 B** | **5,780 B** |

优化本身省 **128 B Flash / 208 B RAM**。计入新增生命周期与离线功能后，相比旧基线 Flash **增加 1,840 B**，静态 RAM **减少 196 B**。这是功能补齐后的净结果，不是 Flash 总体减小。

最终 `.data=212 B`、`.bss=5,564 B`，两段之间有 4 B 对齐，故静态跨度 5,780 B。应用 Flash 余 6,316 B；堆起点对齐后与栈保留区之间余 7,824 B，这不代表已测得运行栈高水位。

已采用：

1. `resource_crc.c` 统一 IEEE CRC32，字体与包存储共用；不增加查表常量。
2. 删除 GUI 层重复的外置字体就绪标志，由字体仓库维护唯一状态。
3. UI 的外置记录仍为 20 B；加载时验证 ID、模式、类型、flags，再只缓存运行所需字段。19 个组件的缓存从 380 B 降为 304 B。
4. 绘图页从 1,536 B 降为 1,400 B。800 像素三色仍为每页 7 行，共 69 页；单色从每页 15 行变为 14 行，总页数从 32 增为 35。三色字体读取次数和 golden hash 不变；单色画面 hash 不变，但读取次数有所增加。
5. 删除对 `epd_get_model()` 返回空指针的无效判断；该接口始终返回匹配型号或默认型号。最终构建进一步减少 16 B Flash，保留原型号回退行为。

保留：两槽 244 B 命令载荷、旧 WRITE_IMAGE/SEND_DATA、FST2/FST3 读取、512 B 时钟 OLD 缓冲、2 KiB 栈、247 ATT MTU、内置 8 KiB 保留区。没有把绘图与接收缓存强行合并，也没有给单图增加外置中转。进一步省 RAM 应先测实际栈和刷新耗时；控制队列裁剪须解决旧长包兼容，暂不默认牺牲可靠性。

2026-09-29 更新：用户确认存量设备已全部迁移到 ERS 字体包，随后已移除本段提到的 FST2/FST3 固件读取路径；新版本仅加载外置分区的 ERS 字体包。其余保留项未因此改变，实测数据见 [内置 Flash 占用复核](internal-flash-usage-review-20260929.md)。

## 2026-09-29 复审与修复

- `resource_installer.js` 补齐异步会话检查：旧上传进度/异常/离线结果不能覆盖新连接；重新绑定重置忙状态。资源加载使用选择代次，后台自动目录和较早目录读取不能覆盖后来的手动选择。
- `resource_store.js` 在已收到成功 RUN_OFFLINE 应用 ACK 的情况下接受随后 GATT 写入关闭；未确认成功的断连仍拒绝。支持 ACK 到达后、写入 Promise 完成前的正常离线断连。
- `EPD_service.c` 在同一临界区检查响应所属连接并发送；若激活过程中已断连/重连，取消旧请求的待发送离线状态，避免新连接被锁住。
- `resource_transfer.c` 仅在连接代次变化或离线仍有会话残留时清理，不再在每次离线主循环清除读取缓存。
- 业务激活只在资源改变或未就绪时重载；成功 LEAVE 后的 RUN_OFFLINE 复用验证结果。BEGIN 仍使缓存失效，失败不能通过该路径绕过检查。

新增回归覆盖过期上传回调、重连时的忙状态、离线 ACK/断连顺序、后台/目录加载竞争、真实服务旧响应取消、激活重载次数及离线读取缓存保留。Node **44 项通过**，C/Python 回归通过，GCC 发布构建通过；实机、Keil 编译及真实浏览器验收仍未完成。

该阶段产物：`output/project-review-20260929/final/nrf52811_xxaa.{out,bin,hex,map}`。BIN **51,076 B**，`.data=212 B`、`.bss=5,564 B`，静态 RAM 地址跨度 **5,780 B**。相比 09-28 的实现增加 48 B Flash，静态 RAM 不变；Flash 剩余 **6,268 B**，栈前未分配地址空间仍为 **7,824 B**。09-28 的 A/B 优化收益保持为当日实验结果，不重新当成本次收益。

## 2026-09-29 广播策略修正

按用户澄清，应用资源后的断连沿用原间歇广播策略。移除 `m_offline`、主动停止广播、禁止断连自动重播、断连前提前启用唤醒脚；`advertising_start()` 恢复原实现。主循环收到最终 ACK 完成请求后只调用 `disconnect_for_run()` 断开连接。广播间隔、超时及唤醒规则不变，资源损坏时保持恢复入口。

网页按钮改为“应用并断开连接”，勾选项改为“更新完成后自动断开连接”，移除关闭广播及必须重启/按键才能重连的提示。操作码 8 和 RUN_OFFLINE 名称保留，其语义在协议中明确为断连独立运行。

最新构建 BIN **50,916 B**，静态 RAM **5,780 B**，应用 Flash 剩余 **6,428 B**；相对上次复审减少 **160 B Flash**。构建产物为 `output/advertising-policy-20260929/final/nrf52811_xxaa.{out,bin,hex,map}`。广播回归改为检查应用后断连、原有超时重播/唤醒行为，以及资源损坏恢复；SDK 广播状态机回归继续覆盖断连自动广播。

该修正已通过 C/Python 主机回归、44 项 Node 测试、GCC 发布构建与差异格式检查；未烧录设备，实机验收状态不变。

## 2026-09-29 恢复连接期间刷新

用户要求网页选定模式后立即看到屏幕响应。此前 `epd_gui_update()` 将 BLE 连接存在也作为拒绝刷新的条件，SET_MODE 已经到达 MCU 并进入显示队列，仍会在此被丢弃。本次移除该条件；资源维护、资源未就绪、屏幕初始化、断连清理以及传图期间的互斥仍保留。

日历、分屏时钟、全屏时钟可保持连接切换并刷新；时钟的周期刷新也不再因连接存在而被拦截。图片模式继续使用原来的屏幕 RAM 直传流程。网页和协议文档不再要求先断连才能看到刷新，断连后的广播策略沿用上节修正。

新增 `connected_refresh_fixture.c`，提取生产代码的 SET_MODE、模式更新、定时策略、显示队列和 GUI 刷新函数，只替换调度器及硬件边界。在修改前，保持连接选择日历的测试明确失败；修改后，三个 GUI 模式、同模式刷新请求、分钟刷新、无连接刷新及维护/传图/初始化互斥测试通过。该验证覆盖到面板刷新调用，不能替代实机屏幕观测。网页另验证三个模式均实际发送 SYNC_TIME_SILENT 和 SET_MODE，并保持 GATT 连接，Node 共 **45 项通过**。

GCC 发布构建 BIN **50,900 B**，静态 RAM **5,780 B**，应用 Flash 剩余 **6,444 B**；相比上一节减少 16 B Flash，RAM 不变。最新产物位于 `output/connected-refresh-20260929/final/nrf52811_xxaa.{out,bin,hex,map}`，未烧录实机。

## 2026-09-29 恢复固件刷新后的首次刷新

启动代码本来会调用 `ble_epd_on_timer(..., true)`，但 `epd_gui_update()` 把 `epd_resources_ready()==false` 当成全局拒绝条件。外置 Flash 缺少任意一个字体、日历或 UI 包时，队列中的启动刷新被直接消耗，屏幕没有动作。现在显示队列只在资源维护会话、屏幕初始化、断连清理或传图并发冲突时让出；单纯缺包不会抑制硬件刷新。UI 布局存在时继续绘制当前模式，缺少 UI 布局时绘制内置的 `NO DATA` 提示，避免刷新成白屏。图片模式使用屏幕 RAM 直传，MCU 重启后无法从固件重绘单图，因此跳过启动空白刷新并保留电子纸上已有画面。固件更新不会自动安装外置资源包，完整日历和字形仍需通过网页安装对应数据。

主机测试覆盖缺包仍触发面板刷新、缺少 UI 布局时实际产生非空白帧、图片模式重启不清屏、连接期间的模式切换及既有互斥。GCC 单任务编译通过，BIN **51,076 B**，静态 RAM **5,780 B**，Flash 余 **6,268 B**；产物在 `output/boot-refresh-20260929/firmware/`。尚未在实机测量刷新效果。

## 2026-09-29 MCU 旧传图路径裁剪

按用户确认，网页继续保留对旧固件的无 CRC 传图与命令透传，新 MCU 固件（版本 0x36）不再接受 `0x30/0x03/0x04`。普通控制队列改为每槽 16 B，CRC 图片块及日期标注绕过队列直达处理。GCC BIN **49,704 B**，静态 RAM 地址跨度 **5,312 B**，应用 Flash 余 **7,640 B**。早期章节关于“保留旧命令、244 B 队列”的描述只对应当时的阶段，不代表当前实现；详细收益与限制见 `docs/internal-flash-usage-review-20260929.md`。

后续用户明确旧固件使用独立网页。当前网页只连接固件 `0x37` 及以上，`REFRESH/SLEEP` 改为 `0x03/0x04`，CRC 传图命令改为 `0x30–0x32`。上一段是 `0x36` 阶段记录，当前协议见 `docs/ble-protocol.md`。
