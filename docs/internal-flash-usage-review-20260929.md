# 内置 Flash 占用复核（2026-09-29）

结论：当前发布配置已经把日历内容、UI 布局、字体、设备配置和日期标注放在外置 Flash；内置 Flash 的主要压力是**执行代码**，不是尚未迁移的大块业务数据。保持单张图片直传屏幕 RAM 的方案即可。以下数据针对 GCC `nrf52811_xxaa` 发布配置，不代表 Keil 调试配置或板上当前实际安装内容。

## 测量口径

- 产物：`output/boot-refresh-20260929/firmware/nrf52811_xxaa.{out,map,bin}`，编译选项见 `Makefile.nRF52_linux`：`-Os -flto --gc-sections`，`GUI_INCLUDE_INTERNAL_FONTS=0`，关闭 RTT 日志。
- 内置 Flash 应用区为 `[0x19000, 0x27000)`，容量 **57,344 B**；BIN 为 **51,076 B**，结束地址 `0x25783`，余量 **6,268 B**。
- ELF 的 `.text` 为 **50,760 B**，其中含代码、向量表、只读常量；其它只读观察者段合计 **96 B**，`.ARM.exidx` **8 B**，`.data` 初值 **212 B**，合计 51,076 B。`.bss` **5,564 B** 不占 BIN，但占 RAM；另有 4 B 对齐，静态 RAM 地址跨度为 **5,780 B**。`.stack_dummy` 预留 2,048 B，仅占 RAM。
- ELF 中体积很大的 `.debug_*` 是调试信息，不写进 BIN；不能用 `.out` 文件大小当作内置 Flash 用量。
- `readelf` 的 375 个不同地址的有大小函数符号合计 **48,844 B**。用 `addr2line` 按函数入口回溯源码后得到下表。LTO 的内联代码归到调用者，未命名代码、常量、向量表和填充不在该表；所以该表适合找热点，**不能把各行当成拆除模块后的净节省量**。

| 函数源码归属 | 可归属函数大小 | 较大的文件 |
| --- | ---: | --- |
| `EPD/` | 19,610 B | `EPD_service.c` 9,532 B；`resource_store.c` 1,794 B；`UC8179.c` 1,616 B；`fm25q04b.c` 1,378 B；`font_store.c` 1,228 B |
| `GUI/` | 13,460 B | `GUI.c` 5,560 B；`Adafruit_GFX.c` 2,724 B；`u8g2_font.c` 1,460 B；`Lunar.c` 1,114 B；`ui_resources.c` 1,028 B；`calendar_resources.c` 936 B |
| Nordic SDK / nrfx | 9,558 B | `nrfx_gpiote.c` 1,192 B；`app_timer2.c` 1,064 B；`nrfx_spim.c` 910 B；BLE 广播 704 B |
| `main.c` | 5,998 B | `main()` 5,396 B，含启动、BLE、定时器和循环逻辑 |

最大的单个函数分别是 `main()` **5,396 B**、`epd_gui_update()` **5,052 B**、`DrawMonthGrid()` **2,640 B**、`epd_execute_command()` **2,080 B**。这些函数的大小包含编译器内联，拆分文件或函数不会自动省下相应字节。

`.text` 中的只读常量、字符串、驱动描述和对齐区约 **1 KiB**。可辨认的常量包括节气/时间算法小表、星期/月份规则、七段数字几何、19 个 UI 组件的合法模式/类型表、字体槽位几何、UC8179 驱动描述，以及缺少 UI 包时的 `NO DATA` 提示字形。它们是固定规则、硬件参数或无外置资源时的恢复信息；迁到外置 Flash 还要增加读取和校验代码，收益很小。源码 `GUI/fonts.c` 中虽有 4,315 / 4,830 / 389 B 的三套内置字体数组，但发布配置将 `GUI_INCLUDE_INTERNAL_FONTS` 设为 0，**它们没有进入上述 BIN**。`GUI/Lunar.c` 的可变年份、节日和文字内容也改为读取外置包；源文件中的旧表说明注释不等于发布数据。

## 内、外置 Flash 边界

| 区域 | 地址或容量 | 当前作用 |
| --- | --- | --- |
| S112 SoftDevice | `[0x00000, 0x19000)`，100 KiB 地址窗口 | 仓库 HEX 实际写入 100,884 B，含 BLE 协议栈；不计入应用 BIN |
| 应用固件 | `[0x19000, 0x27000)`，56 KiB | 屏幕驱动、渲染、BLE 服务、外置资源读取/校验；当前占 51,076 B |
| 内置保留区 | `[0x27000, 0x29000)`，8 KiB | DFU 配置保留的应用数据区；目前配置/标注存外置，不应未经 Bootloader 核验直接并入应用区 |
| Bootloader | `[0x29000, 0x30000)`，28 KiB 地址窗口 | 仓库 Bootloader HEX 在该区写入 18,588 B；另含 8 B UICR 配置，不计入应用 BIN |
| 外置 FM25Q04B | 512 KiB | 分区表、14 B 设备配置记录、日期标注、日历、396 B UI 包、字体、更新状态及预留分区；分区**容量**不等于实际已写入数据量 |

外置布局见 `EPD/resource_layout.h`：分区表 4 KiB、配置 4 KiB、标注 4 KiB、状态 4 KiB、日历 16 KiB、UI 64 KiB、字体 256 KiB、预留 160 KiB。仅刷新 MCU 固件不会写入这些外置包。单张图片仍只写屏幕控制器 RAM，固件重启后无法从 MCU 重新绘制图片。

虽然 SDK 配置头中保留 `FDS_ENABLED=1`，当前应用 ELF 没有链接 `fds_*` / `nrf_fstorage_*` 实现，应用源码也没有调用它们；8 KiB 内置保留区是分区/DFU 约束，不代表项目数据仍写在内置 Flash。

## 后续优化顺序

1. **先保住兼容性与可恢复性。** 保留缺资源提示、CRC/边界校验、资源会话中断恢复、已验证的 UC8179 时序和当前 BLE 广播策略。把字形、日历、布局再从内置搬出不会有大收益，因为发布固件已这样做。
2. **优先审计过时兼容路径，再做独立 A/B。** 用户已确认现存设备均迁移到 ERS 字体包，本轮已移除 FST2/FST3 固件读取路径；具体收益见下文。旧图片/命令协议尚未核对网页和在用设备，不宜仅按函数大小删代码。
3. **围绕实际热点整理控制流。** `EPD_service.c` 的显示刷新与命令分发、`main.c` 启动流程、`GUI.c` 的月历绘制占大头。可先消除重复状态判断或分支，但每次都要保留刷新、BLE 连接、低电量和资源维护回归，并以同配置 BIN 差值判断是否真省空间。为了“模块化”单纯拆文件不会省 Flash。
4. **若压力主要在 RAM，单独评估队列与绘图缓存。** 用户已确认 MCU 无需旧长包兼容，普通控制队列现已收缩到每槽 16 B，图片和标注走直接处理路径，实测收益见下文。1,400 B 绘图页、512 B OLD 条带和 2 KiB 栈仍不应在缺少实机耗时/栈高水位数据时继续压缩。
5. **确需扩大应用区时，再评估 8 KiB 保留区。** 这只增加链接地址空间，不会减少 BIN 大小，而且要同时核对已部署 Bootloader 的 `NRF_DFU_APP_DATA_AREA_SIZE`、OTA 擦写边界、回滚和版本迁移。仓库 `SDK/17.1.0_ddde560/dfu/sdk_config.h` 配为 8 KiB，但当前预编译 Bootloader HEX 的编译参数没有在本次审计中得到独立证明。

未读取真实设备内部/外部 Flash，也未验证 Keil 发布二进制。板上如出现资源缺失，应先确认外置 Flash 是否安装了同版本分区表、日历、UI、字体；固件体积统计不能替代运行时资源状态。

## 已迁移设备的字体兼容裁剪

当前余量足以继续沿用内置 Flash 执行固件、外置 Flash 存资源的方案，不需要重设计存储架构。若后续功能使余量接近 4 KiB，再评估 8 KiB 内置保留区与 Bootloader/OTA 的实际擦写约束；修改分区只增加应用可链接空间，不减少 BIN。nRF52811 当前外置 SPI Flash 不是可直接执行代码的 XIP 区域，不能把上述固件函数搬过去当作一般的体积优化。
