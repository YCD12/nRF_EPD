# 内置 Flash 优化实施结果（2026-09-15）

## 结果

在当前工作区基线上完成广播初始化精简与构建体积检查。最终应用 **52,716 字节**，比优化前减少 **1,172 字节**；应用分区余量从 **3,456 增加到 4,628 字节**，达到保留 4 KiB 的近期目标。

| 指标 | 优化前 | 最终结果 | 变化 |
| --- | ---: | ---: | ---: |
| `size` 的 text | 53,656 | 52,488 | -1,168 |
| `size` 的 data | 232 | 228 | -4 |
| bss | 6,560 | 6,560 | 0 |
| **应用 Flash / BIN** | **53,888** | **52,716** | **-1,172** |
| **应用 Flash 余量** | **3,456** | **4,628** | **+1,172** |
| 静态 RAM | 6,792 | 6,788 | -4 |

测量配置：仓库 ARM GCC 9.3.1，`-Os -g3 -flto`，默认发布配置，应用区域 `[0x19000, 0x27000)`，容量 57,344 字节。栈保留 2,048 字节，FDS 仍占原来的 8 KiB，设备报告版本沿用 `0x32`。

## 实现

### 1. 专用广播启动适配器

新增 `EPD/epd_advertising.c/.h`，按当前产品的固定广播内容初始化 SDK 广播实例：

- 广播包保持原 Flags、GAP 设备名；名称超过 26 字节时，与原 SDK 一样截断并使用 Shortened Local Name 类型。
- 扫描响应包含一个完整服务 UUID。通过 `sd_ble_uuid_encode` 获取 SoftDevice 注册的 UUID 字节，正确处理当前自定义 128 位服务，不把 vendor type 当作 16 位服务 UUID。
- 使用 SDK 实例内部的长期缓冲，保留广播间隔、超时、连接配置标签和事件处理函数。
- 首次配置仍以空数据指针申请广告句柄，实际启动继续由 `ble_advertising_start` 配置数据；重连、超时、DFU 配置更新继续使用原 SDK 状态机。
- 名称读取、UUID 查询/编码和句柄配置失败均返回错误；只有配置成功后才标记 initialized。已经初始化的实例拒绝重复调用该启动适配器。

适配器面向 SDK 17.1 和当前单服务、传统广播配置，要求传入零初始化实例。`main.c` 的 `BLE_ADVERTISING_DEF` 静态实例满足该条件；未来若增加厂商数据、多服务或扩展广播，需要扩展适配器及其 SDK 对照测试。

原 SDK 源码未修改。最终 ELF 不再包含通用 `ble_advdata_encode`，原广播事件处理和启动函数仍在。GCC 源文件列表及 Keil 两个目标均已加入新模块。

先只替换初始化时，Flash 为 52,720 字节；进一步将单个服务 UUID 声明为 `const` 后，最终为 52,716 字节，静态 RAM 同时减少 4 字节。

### 2. 自动体积预算

新增 `tools/check_flash_budget.py`，发布目标 `nrf52811_xxaa` 在生成 BIN 后调用，包括增量构建：

- 超过 57,344 字节、空文件或文件不可读取：返回失败。
- 剩余空间不足 4,096 字节：输出预警。
- 调试布局不套用生产分区预算。

脚本读取 BIN 长度，避免把 ELF 调试信息或 BSS 算进 Flash。发布链接脚本的硬边界仍然保留。Windows 默认使用 `python`，其他平台默认 `python3`；可通过 `BUILD_PYTHON` 指定解释器。

## 已测量但未采用的显示内联调整

各变体使用独立源码副本和构建目录。下表为广播优化前的基线，正数表示节省，负数表示增大。

| 单独禁止内联的函数 | 应用 Flash | 相对 53,888 字节节省 |
| --- | ---: | ---: |
| `epd_perform_full_refresh` | 53,904 | -16 |
| `DrawGUI` | 53,856 | 32 |
| `GetFestival` | 53,936 | -48 |
| `DrawDateHeader` | 53,856 | 32 |
| `epd_clock_refresh_try` | 53,952 | -64 |
| `gui_set_text_style` | 53,872 | 16 |
| `epd_battery_guard` | 53,920 | -32 |

这些单独实验收益有限，且 `epd_clock_refresh_try` 变体还增加 8 字节静态 RAM；本轮没有把这些函数属性加入生产代码，也没有把各变体的节省简单相加。

## FDS 和分区评估

当前已达到 4 KiB 余量目标，继续替换 FDS 的成本高于本轮收益需求，因此保留现有存储实现与分区。

专用内置双页日志仍是后续千字节级候选，但 FDS 代码的现有体积不能视为净收益，新日志仍需序号、提交标志、CRC、换页、异步重试和旧数据迁移。保留双页时也不会释放 8 KiB 数据分区。本次没有实现该原型，没有宣称取得这部分收益。

如果后续需要保留 8 KiB 应用余量，当前仍需再减少 **3,564 字节**；届时再评估专用日志或完整外置持久化迁移。

## 验证与产物

- 完整主机回归通过：30 个常规 C 测试程序，加 1 个提取实际服务处理函数的 C 集成程序；16 个 Node 子测试；3 个 Python 单元测试。
- 新广播测试直接编译仓库原 SDK 的 `ble_advdata.c` 和 `ble_advertising.c`，只替换 SoftDevice 调用及硬件相关工具头。比较 9 种名称长度与 16/128 位 UUID 的 18 组结果：广播字节、扫描响应字节以及归一化实例指针后的完整 SDK 初始化状态一致。
- 广播测试覆盖空指针、重复初始化、名称读取失败、UUID 查询/编码失败、不支持的 UUID 长度/类型、配置失败和重试；使用真实 SDK 状态机验证启动、断连重广播、超时进入 idle 和 DFU 禁止重广播。
- 通用/固定配置 GUI golden、时钟 OLD/NEW、存储故障、字体传输、UC8179 命令序列等现有回归均通过。
- 体积检查覆盖空文件、52 KiB 临界值、预警区、56 KiB 硬上限、超限和文件缺失。
- GCC 发布构建及体积检查通过；Keil 两个目标的源文件登记通过 XML 静态检查，未执行 Keil 编译。
- HEX 校验和有效，HEX 应用数据与 BIN 一致；镜像末端为 `0x25DEC`（不含），没有进入 FDS 区域。
