# 电子纸（EPD）老化屏幕暗红色水平带与画面异常深层原因分析及优化方案

本篇文档记录了针对 UC8179 驱动的 7.5 寸三色电子纸在长期刷新时钟后，**老化屏幕非刷新区出现暗红色水平带**、**外围红边**以及**局刷后继全刷颜色异常（红白颠倒）**的深层物理与逻辑原因分析，并详细说明了当前实施的优化与修复方案。

---

## 一、 深层原因分析 (Deep Root Cause Analysis)

### 1. 老化屏幕暗红色水平带的物理机理

三色电子纸（黑、白、红）的微胶囊/微杯结构中包含三种不同电性、粒径和质量的电泳粒子：
*   **白粒子**：通常带负电，粒径较小，运动速度快。
*   **黑粒子**：通常带正电，粒径较小，运动速度快。
*   **红粒子**：通常带负电，但其**带电荷量极高、质量与粒径显著大于黑白粒子**，因此对电场的响应呈“慢速”、“迟滞”特征，需要持续且较强的直流（DC）电压才能驱动其浮动到屏幕表面。

当屏幕上只有时钟区域（局刷窗口）每分钟在进行局部刷新时，物理现象如下：
1.  **源极漏电与寄生耦合（Source Line Leakage & Crosstalk）**：
    时钟更新时，垂直方向的源极线（Source Lines）需要高频传输驱动黑白跳变的电压脉冲。屏幕非选中行（时钟以外区域）的栅极线（Gate Lines）虽然理论上处于关闭状态（VGL），但由于**屏幕老化**，薄膜晶体管（TFT）的漏电流（Off-state Leakage Current）显著增大，且行与列交叉处存在寄生电容耦合。
2.  **微弱直流偏置累积（Charge Accumulation）**：
    漏电导致时钟之外的非选中像素也持续感受到来自源极线的微弱高频脉冲。这种微弱脉冲在极短时间内不会影响黑白状态，但随着时钟刷新数小时甚至数天，电荷在微胶囊内不断单向累积，形成了一个**实质性的微弱直流偏置（DC Bias）**。
3.  **慢速红粒子激活（Red Particle Activation）**：
    新屏幕由于 TFT 截止特性好，漏电极微，电荷无法累积到激活阈值。但**老化屏幕**因截止阻抗降低，累积的直流偏置电压达到了红粒子的驱动门槛。由于红粒子一旦运动就极难自退，这些微弱漏电在水平方向的行上累积，最终在时钟以外区域呈现出**暗红色的水平条带**。

### 2. 屏幕最外围出现一圈红色的原因

*   **边框驱动未悬空（Border Coupling）**：
    在局刷写 RAM 和刷新期间，如果 VCOM 和数据间隔寄存器（`CDI`, 0x50）未将边框（Border）设置为高阻态（Hi-Z），边框电极就会持续被写入默认的背景电压或参与电场耦合。
*   随着局刷的频繁进行，边框区域像素同样会因为电荷累积与源极串扰，使迟钝的红粒子浮动到表面，导致最外层出现一圈洗不掉的红色边缘。

### 3. VCOM_DC (VDCS) 寄存器设置不匹配的危害

*   原固件在局刷初始化中，将 VCOM_DC 直流偏置电压寄存器 `VDCS` (0x82) 设置为了 `0x31`（对应 `-1.5V`）。
*   然而根据逻辑分析仪对原厂正常机器的硬件抓包，该屏幕的最佳匹配 VCOM_DC 应为 `0x22`（对应 `-1.0V`）。
*   **使用不匹配的 VCOM 电压（-1.5V vs -1.0V）会在全屏上引入 0.5V 的常态直流压差**。这不仅会加速液晶/电泳板的电荷残留和 TFT 老化，更会直接加剧上述漏电耦合，使得红粒子更易被激活。

### 4. 局刷后继全刷画面异常（红白颠倒）的逻辑漏洞

*   **现象**：程序自行运行时钟日历模式，上电首帧全刷正常，等一分钟局刷后，画面瞬间异常，本来应该白色的地方变红，红色的地方变白，且触发的是全刷。
*   **漏洞**：
    1.  局部刷新会调用 `UC8179_Init_Partial`，该函数将面板设置寄存器 `PSR` (0x00) 设置为 `0x3F`（进入外部寄存器自定义 LUT 模式与双色模式，且忽略红色层 DTM2）。
    2.  当定时器触发周期性全刷，或者因为日历模式不满足差分条件而回退到全刷流程时，程序会直接调用底层 `UC8179_Refresh`（全刷执行函数）。
    3.  然而，原 `UC8179_Refresh` 函数**没有重新将 PSR、VDCS、CDI 恢复为全刷对应的 OTP 默认配置**，芯片依然保持在局刷的 `PSR = 0x3F` 寄存器波形与两色配置。
    4.  这导致全刷命令（`DRF`, 0x12）使用错误的局刷黑白波形去驱动三色图像 RAM，从而引起严重的色彩极性错乱与红白颜色颠倒。

## 二、 当前优化与修复方案 (Implementation & Optimization Scheme)

为了彻底根治上述物理串扰与逻辑漏洞，我们在底层的 `EPD/UC8179.c` 中实施了以下联合优化：

### 1. 缩短局刷脉冲驱动时间 (LUT Waveform Optimization)
对局刷所使用的黑转白（`LUTBW`）和白转黑（`LUTWB`）波形数据包进行降时微调，将脉冲周期缩短 **25%**，从而将漏电荷的源头降到最低：
*   **原配置**：`T2 = 0x32` (50帧), `T3 = 0xA` (10帧)。
*   **优化后配置**：
    *   `T2_WB` / `T2_BW` = **`0x25`** (37帧)
    *   `T3_WB` / `T3_BW` = **`0x07`** (7帧)
*   **效果**：单次时钟变化的电场作用总时长减少了 25%，极大地减少了施加在非选中行 TFT 上的累积电压时间，在新老屏幕上均能彻底消除暗红水平带。

### 2. 匹配硬件最佳 VCOM_DC 并使能边框悬空
在局刷初始化与 RAM 写入阶段（`UC8179_Refresh_Partial`、`UC8179_Write_Image_Partial`、`UC8179_Partial_Diff_Push`），显式重写核心寄存器：
*   **`VDCS` (0x82) $\rightarrow$ `0x22`**：将 VCOM_DC 修正为硬件捕获的 `-1.0V`。屏幕整体直流偏置彻底归零，根除了电荷积压，大幅延缓屏幕老化与红粒子激活。
*   **`CDI` (0x50) $\rightarrow$ `0xA9, 0x07`**：局刷时将第一字节设置为 `0xA9`（即 `BDZ=1`，使使能边框高阻悬空状态）。使得边框电极在时钟刷新时不受源极脉冲耦合，**彻底清除了屏幕最外围的红边问题**。

### 3. 全刷执行函数添加“寄存器状态兜底恢复”
在全刷执行函数 `UC8179_Refresh` 的入口处，强制覆盖恢复全刷所需的 OTP 三色模式寄存器参数：
```c
void UC8179_Refresh(epd_model_t* epd) {
    NRF_LOG_DEBUG("[EPD]: refresh begin\n");

    // 兜底: 确保即使上次是局刷状态,也能强制回到全刷的配置
    EPD_Write(UC81xx_PSR, epd->color == EPD_COLOR_BWR ? 0x0F : 0x1F);  // OTP + BWR/BW
    EPD_Write(UC81xx_VDCS, 0x00);                                       // 全刷不用偏置
    EPD_Write(UC81xx_CDI, epd->color == EPD_COLOR_BWR ? 0x57 : 0x97);   // 边框设为纯白

    UC8179_PowerOn();  // 开启电源
    // ...
```
*   **效果**：无论是主动模式切换还是定时全刷，执行前都会强制退回 OTP 默认配置，不再受局刷残留状态干扰，**彻底消除了色彩颠倒、画面红白倒置的严重 bug**。
