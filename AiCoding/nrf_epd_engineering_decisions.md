> 本文档记录将 UC8179 7.5" 逆向寄存器移植到 nRF52811 平台过程中，**超出"纯寄存器替换"范围**的两个工程决策的详细分析、原因、实现，以及它们绕开/兜底的实际问题。

## 决策一：局刷采用「全驱动 + 整窗重绘」而非参考固件的「真差分局刷」

### 1.1 问题陈述

参考固件（esp32 + UC8179）的局刷可以做到「**只更新变化的像素**」——白底纹丝不动，只有数字笔画微微闪一下。这是 UC8179 标准的「**真差分局刷**」工作模式。本次移植到 nRF52811 后，做不到这种效果，只能做「整窗每像素都驱动一次」（局部全刷）。**这不是软件能修的 bug，是硬件硬约束**。

### 1.2 参考固件的真差分局刷工作原理

UC8179 局刷模式（PSR=0x3F，KW 两色，寄存器 LUT）下：

- **DTM1 RAM** 存放「上一帧画面」（OLD frame）
- **DTM2 RAM** 存放「这一帧要显示的画面」（NEW frame）

DRF 触发后，芯片对窗口内每个像素读取 (OLD bit, NEW bit) 二元组，根据组合选择应用哪张 LUT 表：

| (OLD, NEW) | 物理含义 | 命中的 LUT 表 |
|------------|----------|---------------|
| (W, W) | 上一帧白，这帧仍白 | LUTWW |
| (K, K) | 上一帧黑，这帧仍黑 | LUTBB（也叫 LUTKK） |
| (K, W) | 由黑变白 | LUTBW（也叫 LUTKW） |
| (W, K) | 由白变黑 | LUTWB（也叫 LUTWK） |

参考固件在 DRF 之前加载的是逆向出的 **LUT set#2（温和单相波形）**：

```
LUTC  : 0x00 0x01 0x32 0x0A 0x00 0x01 ...   // VCOM
LUTWW : 0x00 0x01 0x32 0x0A 0x00 0x01 ...   // 波形字节 0x00 = 保持，不驱动
LUTBW : 0x20 0x01 0x32 0x0A 0x00 0x01 ...   // 0x20 = 单相驱动到白
LUTWB : 0x10 0x01 0x32 0x0A 0x00 0x01 ...   // 0x10 = 单相驱动到黑
LUTBB : 0x00 0x01 0x32 0x0A 0x00 0x01 ...   // 波形字节 0x00 = 保持，不驱动
```

关键点：**WW 和 KK 表的波形字节都是 `0x00`（保持，不施加电压）**。这意味着：

- 未变化的像素（WW/KK）→ 芯片**不驱动** → 电泳液不动 → 无闪烁、无残影
- 只有变化的像素（KW/WK）走单相波形被驱动到目标色

→ 这就是"只刷变化区域"的物理机制。

### 1.3 把这套机制移到 nRF 上需要什么？

真差分局刷的**前置条件**：DTM1 必须包含「上一帧的真实数据」（真 OLD）。否则 (OLD, NEW) 比对的结果就是错的，本该 hold 的像素被驱动 / 本该驱动的像素被 hold → 残影或不显示。

OLD 帧的来源只有两条路：

#### 路径 A：MCU 自己缓存上一帧

参考固件 esp32 走的就是这条。它有 ~400KB SRAM，存一个 48000B 的整帧绰绰有余。

本机 nRF52811 不行：

| 约束 | 数值 | 来源 |
|------|------|------|
| nRF52811 整机 SRAM | 24KB | 芯片规格 |
| 协议栈 + 堆 + 栈占用后剩余可用 | ~15.6KB | linker map |
| 一帧整屏数据大小 | 800 × 480 / 8 = **48000B** | 屏幕分辨率 |
| 当前 GFX 绘图缓冲 | **7680B 单块分页缓冲** | [GUI/Adafruit_GFX.c:135](../GUI/Adafruit_GFX.c#L135) `static uint8_t s_gfx_buffer[7680]` |

GFX 缓冲是「**分页**」工作模式：每次只画一块 7680B 的子区域，画完通过 `write_image_partial_with_offset`（[EPD_service.c:394](../EPD/EPD_service.c)）写到芯片，然后**复用同一块缓冲**画下一块。这块缓冲既存不下整帧，更不可能再额外开一块 48000B 的 OLD 帧——**整机剩余 RAM 总共也就 15.6KB，连一帧都装不下**。

即使把屏幕缩到时钟窗口（384 × 150 = 7200B），也和 GFX 缓冲冲突，无法独立保留。

→ **路径 A 物理不可行。**

#### 路径 B：让 UC8179 芯片自己保留 OLD（N2OCP 自动 NEW→OLD）

UC8179 自己有内部 RAM 存 DTM1/DTM2。理论上可以让芯片自己把"这帧的 NEW"在下次刷新前自动当作"下帧的 OLD"——不用 MCU 操心 OLD 数据。

需要满足的条件：

1. 启用 N2OCP（CDI 寄存器 bit3）
2. 刷新结束后**只 POF（Power-Off）不进 DSLP（Deep Sleep）**——芯片要保留内部 RAM
3. 不能复位 RES 引脚——一旦硬复位，内部 RAM 全清零
4. EPD 供电不能被切

但本机 [EPD_service.c](../EPD/EPD_service.c) 现有的刷新编排破坏了所有这些条件：

- **每分钟整点对齐**触发 `init_partial`，里面有 `EPD_Reset()`（拉低 RES 50ms）→ **芯片 RAM 清零，OLD 没了**
- **BLE 断开**进 `UC8179_Sleep`（POF + DSLP 命令 0xA5 深睡）→ 芯片掉电 → 内部 RAM 也丢
- 电池时钟产品**绝大多数时间都是断连状态**，每次刷新都是从冷启动开始

→ **路径 B 在当前编排下也走不通。**

#### 想走路径 B，需要的架构改造

| 改造点 | 影响 / 代价 |
|--------|-------------|
| 时钟模式期间不调 `init_partial` 的 Reset | 改 EPD_service.c 整套刷新编排 |
| 不进 DSLP，仅 POF 待机 | 待机功耗 POF > DSLP，**电池续航变差** |
| 保证 EPD 供电不被 GPIO_Uninit 切掉 | 还得审 BLE 断连/低电量路径 |
| 第一次冷启动后 OLD 还是脏的（芯片 RAM 上电随机） | 头一次刷新会有伪影，需要至少跑 1 次全刷"播种" OLD |

这不是改个开关——是**用待机功耗换刷新质感**的取舍。需要产品决策（功耗预算 vs 显示效果），不在本次"寄存器移植"任务范围内。

### 1.4 当前方案：DTM1=~新帧 + DTM2=新帧 + set#2

既然没有可信的 OLD 帧，DTM1 只能"将就着填"。我经过两轮迭代得到当前方案。

#### 初版（已废弃）：DTM1 = DTM2 = 新帧 + set#1

逻辑：每像素的 (OLD, NEW) 都退化成 (W,W) 或 (K,K)，必命中 LUTWW 或 LUTBB。但 set#2 的 WW/KK 是 `0x00` 保持不驱动——画面不会变。所以配 **set#1（激进 3 相全驱动波形）**：

```
LUTWW : 0x10 0x0F 0x0F ...   // set#1: WW 改造成主动驱动到白
LUTBB : 0x80 0x0F 0x0F ...   // set#1: KK 改造成主动驱动到黑
```

效果上等于「对窗口做局部全刷」，无需 OLD。

**实测失败**：
1. set#1 是 3 相波形（每相 15 帧 × 3 相），对 BWR 三色面板的红色颗粒扰动大 → **白底泛暗红**
2. 3 次黑白翻转 → **整窗强闪**

#### 当前方案：DTM1 = ~新帧 + DTM2 = 新帧 + set#2

让每像素都成为 K↔W 过渡，必命中 KW/WK：

```
白像素: GFX black bit = 1 (W),  DTM1 = ~ = 0 (K), DTM2 = 1 (W)  → (K,W) → LUTBW(KW) 驱白
黑像素: GFX black bit = 0 (K),  DTM1 = ~ = 1 (W), DTM2 = 0 (K)  → (W,K) → LUTWB(WK) 驱黑
```

set#2 的 KW/WK 是单相驱动（`0x20` / `0x10`，T2=0x32=50 帧），是参考固件 DRF 前实际加载、对该面板验证过的温和波形：

- ✅ **不再泛红**：单相单次驱动，不扰动红色颗粒
- ✅ **闪烁大幅减弱**：从 3 相强驱动降为单相单次扫描
- ❌ **仍是「整窗每像素都被驱动」**：因为 DTM1 是构造出来的伪 OLD，命中的不是 WW/KK 而是 KW/WK，所以未变像素也被驱动

代码：[EPD/UC8179.c::UC8179_Write_Image_Partial](../EPD/UC8179.c)

```c
// 局刷数据策略 (本机无 OLD 整帧, 配 set#2 温和过渡波形):
// DTM1(OLD) 写【新帧的取反】, DTM2(NEW) 写【新帧】。这样每个像素的 (OLD,NEW)
// 都是 K->W 或 W->K 过渡 -> 用 set#2 的 KW(驱动到白)/WK(驱动到黑) 温和单相波形
// 把窗口整体重绘到位。WW/KK(保持)不会被命中。
EPD_WriteCmd(UC81xx_DTM1);
UC8179_Write_Image_Rows(black, wb, h, 0xFF, true);    // DTM1 = ~NEW (invert=true)
EPD_WriteCmd(UC81xx_DTM2);
UC8179_Write_Image_Rows(black, wb, h, 0xFF, false);   // DTM2 = NEW
EPD_WriteCmd(UC81xx_PTOUT);
```

### 1.5 老实交代：「只更新变化区域」做不到

用户期望 `局刷应该是只更新变化区域`，**这在当前硬件 + 编排下无法满足**。

| 期望 | 现实 |
|------|------|
| 未变像素 hold，只刷变化笔画 | 整窗每像素都被驱动一次（伪 OLD 撑出 KW/WK 过渡） |
| 白底纹丝不动 | 白底会被微闪一次（单相 50 帧 = ~1 秒驱动） |

**当前方案是不动架构前提下能达到的最接近"无残影局刷"的效果**。要追求真差分，必须做 §1.3 路径 B 的架构改造（功耗 vs 刷新质感的产品决策）。

## 决策二：周期全刷在 `UC8179_Refresh` 内自己复位寄存器（不依赖 init 是否被调过）

### 2.1 问题陈述

时钟模式（MODE_CLOCK_CALENDAR）的刷新编排有一处**编排假设**：整点全刷不走 `drv->init`，直接调 `DrawGUI` + `drv->refresh`。这导致 driver 收到 refresh 调用时，寄存器状态是上一次局刷遗留的——直接做 DRF 会得到错误的全刷结果（残影清不掉、显示异常）。

这是一个 driver 接口对调用方的隐式依赖：**"调 refresh 之前你必须先调 init"**。这个假设在编排里被违反了。

### 2.2 编排实际是怎么走的

[EPD_service.c::epd_gui_update](../EPD/EPD_service.c) 的两条路径：

#### 路径 A：每分钟局刷（正常时钟工作）

```
init_partial             →  设 PSR=0x3F (寄存器LUT/KW两色) + VDCS=0x00 + BTST + 加载 set#2
DrawGUI                  →  write_image_partial (DTM1=~NEW, DTM2=NEW)
refresh_partial          →  设 VDCS=0x22 + CDI=0xA9 0x07 → PON → DRF → POF
```

→ 寄存器全部走局刷配置，DRF 用 set#2 单相波形。OK。

#### 路径 B：整点全刷（每小时一次，清局刷累积残影）

```
（不调 init！）
DrawGUI                  →  write_image (BWR 三色数据写入 DTM1/DTM2)
refresh                  →  PON → DRF → POF
                            ↑ 此刻寄存器状态：上次局刷遗留的 PSR=0x3F + VDCS=0x22 + CDI=0xA9 0x07 + set#2 LUT
```

### 2.3 这会出什么问题？

PSR=0x3F 的含义：

```
bit5 REG = 1  → 用寄存器 LUT（不是 OTP）
bit4 KW  = 1  → KW 两色模式（无红层）
```

整点全刷应该用 PSR=0x0F（OTP + BWR 三色），结果继承了 PSR=0x3F。导致：

1. **红层数据被忽略**：DTM2 的红 bit 在 KW 模式下没有意义 → 红色完全不显示
2. **波形完全不对**：set#2 是温和单相过渡波形，对全刷强度严重不足 → 残影清不掉，画面泛灰
3. **三色面板用两色驱动**：电泳液状态混乱，长期可能伤面板

→ 「整点全刷」这件事根本没真正发生。

### 2.4 修复方案

让 `UC8179_Refresh`（全刷的 refresh）在 DRF 之前**自己把所有跨模式寄存器拨回全刷状态**——不管来时是什么状态都兜底，使 driver 接口对编排无隐式依赖。

代码位置：[EPD/UC8179.c::UC8179_Refresh](../EPD/UC8179.c)

```c
void UC8179_Refresh(epd_model_t* epd) {
    // 兜底: 即使上次是局刷状态(PSR=0x3F/VDCS=0x22/CDI=0xA9 0x07/set#2),
    // 这里强制回到全刷的 OTP 三色配置, 保证整点全刷真的是全刷。
    EPD_Write(UC81xx_PSR,  epd->color == EPD_COLOR_BWR ? 0x0F : 0x1F);  // OTP + BWR/BW
    EPD_Write(UC81xx_VDCS, 0x00);                                        // 全刷不用偏置
    EPD_Write(UC81xx_CDI,  0x77);   // ★ 用 0x77 不能照搬 RE 的 0x11 0x07, 见 §2.5
    // (TRES/TCON 已在芯片 RAM 里, 不需重设)

    UC8179_PowerOn(epd);
    EPD_WriteCmd(UC81xx_DRF);
    EPD_WaitBusy(LOW, 30000);
    UC8179_PowerOff(epd);
}
```

### 2.5 全刷 CDI 必须用 `0x77`，不能照搬逆向值 `0x11 0x07`（一个独立的坑）

CDI（0x50）寄存器位定义（datasheet §6.2.10）：

```
bit7    BDZ      边界 Hi-Z
bit6:5  BDV      边界 LUT 选择
bit3    N2OCP    N2OCP 使能
bit2:1  DDX[1:0] 数据极性  ★关键
bit0    CDI      数据间隔
```

**DDX[1:0] 决定 DTM2（红层）bit 与红/非红的映射极性**：

| CDI 值 | DDX | DTM2 bit = 1 表示 | DTM2 = 0xFF (整字节填 1) |
|--------|-----|-------------------|--------------------------|
| **0x77** | **11** | **不是红 / 白**   | **整片白**（无红） |
| 0x11（逆向值） | 00 | 是红 | 整片红 |

本机 GUI 的清屏路径走 `EPD_FillRAM(DTM2, 0xFF, 48000)`——意图是「**把红层填白**」。这里 GFX 的极性约定假设 DTM2=0xFF 表示无红。所以 CDI 必须用 `0x77` 配套。

如果照搬逆向出来的 `0x11 0x07`：DDX=00 → `0xFF` 被解释为"全是红" → **整屏变红**。

这就是为什么之前出现过「全刷清屏屏幕显示的是红色不是白色」的 bug——把 RE 值无脑搬过来了。

esp32 参考固件之所以能用 `0x11 0x07`，是因为它的帧缓冲极性反过来——它的"无红"对应 DTM2=0x00。本机 GUI 的极性约定与之相反，所以 CDI 也得反着配。

**局刷不受影响**：局刷 PSR=0x3F 是 KW 两色模式，根本没有红层。所以局刷 CDI 可以保留逆向值 `0x11 0x07`（init）/ `0xA9 0x07`（refresh，DDX=00）。

### 2.6 为什么不改 EPD_service.c 让整点全刷也走 init？

最干净的修复确实是让整点全刷也调 `drv->init`——就不会继承局刷状态。但这有几个考虑：

1. **每整点多 ~50ms BUSY 等待**：init 含 `EPD_Reset()`（拉低 RES 50ms）+ 一系列寄存器写。时钟整点本来已经是用户关注点（看时间跳变），多这 50ms 增加可见性。
2. **改编排会牵动其他模式**：EPD_service.c 不只服务时钟模式，还有日历、天气、自定义图等。改编排得回归测试每条路径。
3. **driver 应该自保护**：以后任何调用方调 `drv->refresh`（不管来时啥状态），都应该得到正确的全刷行为——这是 driver 的基本契约。把状态兜底逻辑放在 driver 内部更鲁棒。

→ 选了 driver 内自保护这条路。EPD_service.c / GUI.c 零改动。

### 2.7 同样的兜底也应用于 init_partial 之外的"无 init 局刷"吗？

目前不需要。EPD_service.c 的所有局刷调用路径**都先走 `drv->init_partial`**（每分钟整点对齐时调）。换句话说，局刷端没有"绕过 init"的路径，所以 `UC8179_Refresh_Partial` 不需要自己复位寄存器。

但这条假设以后如果被破坏（比如有人加了"BLE 推送局刷"且不走 init_partial），同样的兜底逻辑也应该加进去。

## 决策三：参数化重建 OLD 帧——时钟模式实现真差分局刷（已落地）

### 3.1 背景：决策一是「整窗温和重绘」，但其实可以更进一步

决策一（§1）老老实实承认了一个事实：**因为存不下整帧 OLD，做不了"只刷变化像素"的真差分**。但这个结论的隐藏前提是**"OLD 帧只能整帧缓存"**。

时钟模式打破了这个前提。它的画面是**强参数化**的：

| 信息 | 决定显示什么 | 字节数 |
|------|--------------|--------|
| 当前显示哪 4 个数字（HH 十/个位 + MM 十/个位） | 完全确定数字字模、分隔符等所有像素 | **4 字节** |
| 数字字位的屏幕坐标 | GUI 编译期常量（`Draw7Number` 布局） | 0 字节（常量） |
| 字模本身 | ROM（7 段编码 + 段几何） | 0 字节（ROM） |

→ 我们**不需要存上一帧的像素数据**，只需要存「上一帧是哪 4 个数字」（4 字节）。需要 OLD 时，**临时调用 `Draw7Number` 重画**那 4 个数字到一块缓冲，得到的位图就是真 OLD。

把决策一的对比表加上这一行：

| 方案 | OLD 帧来源 | RAM 成本 | 抗复位/抗 DSLP | 适用 |
|------|------------|----------|----------------|------|
| 参考固件（§1.3 路径 A） | 整帧缓存 | 48000B | 否 | esp32 等大 RAM 平台 |
| N2OCP 自动 NEW→OLD（§1.3 路径 B） | 芯片内部 RAM | 0 | 否（POF 待机才行，DSLP/Reset 即丢） | 不复位、不深睡的场景 |
| **参数化重建（决策三）** | **MCU 用字模 + 4 字节状态重画** | **4B 状态 + ~1.4KB 临时渲染缓冲** | **完全不依赖芯片 RAM** | **画面强参数化的模式（时钟）** |

### 3.2 工作原理：OLD/NEW 两次重画 + 真差分

每分钟时钟更新流程改为：

```
1. 读上一分钟的数字状态 prev_digits[4]   (从静态 RAM, 4 字节)
2. 计算当前应显示的数字状态 curr_digits[4]
3. 对每个变化的字位 i (prev_digits[i] != curr_digits[i]):
     a. 用 GFX 把 prev_digits[i] 画到内存缓冲 -> old_bm  (真 OLD)
     b. 用 GFX 把 curr_digits[i] 画到内存缓冲 -> new_bm
     c. 设 PTL 窗口为该字位的矩形, DTM1 <- old_bm, DTM2 <- new_bm
4. PON -> DRF -> POF, set#2 真差分自动生效
5. 把 curr_digits 拷到 prev_digits, 等下一分钟
```

DRF 时 UC8179 对窗口内每个像素做 (OLD bit, NEW bit) 比对：

| 字位内的某像素 | (OLD, NEW) | 命中 LUT | set#2 该 LUT 的波形字节 | 物理动作 |
|------|------------|----------|--------------------------|----------|
| 笔画外的白底 | (W, W) | LUTWW | `0x00`（保持） | **不施加电压** |
| OLD 和 NEW 共有的笔画区 | (K, K) | LUTBB | `0x00`（保持） | **不施加电压** |
| OLD 有但 NEW 没有的笔画（如"3"独有的中段） | (K, W) | LUTBW(KW) | `0x20`（驱白） | 驱动到白 |
| NEW 有但 OLD 没有的笔画（如"4"独有的左竖） | (W, K) | LUTWB(WK) | `0x10`（驱黑） | 驱动到黑 |

3→4 切换大概只有 ~30% 像素被实际驱动 → **效果就是几个笔画微微闪一下、背景纹丝不动**，与参考固件完全一致。

### 3.3 关键观察：通常每分钟只有 1 个字位需要驱动

```
14:23 → 14:24    1 个字位变 (MM 个位 3→4)               -> 1 个 PTL 窗口, ~1.4KB 数据
14:29 → 14:30    2 个字位变 (MM 个位 9→0, MM 十位 2→3)    -> 2 个 PTL 窗口, ~2.8KB 数据
14:59 → 15:00    最多 3 个字位变 (MM 两位 + HH 个位)      -> 3 个窗口
23:59 → 00:00    最多 4 个字位变 (整 HH:MM 全变)          -> 4 个窗口（罕见）
```

每个字位 ~ 80×140 px → 80/8 × 140 = **1400 字节 / 字位**。两份 OLD+NEW 共 **2800 字节**，且因为是逐字位串行处理，可以**复用同一块 1400B 缓冲**（先画 OLD 推 DTM1，再覆写画 NEW 推 DTM2）。完全在 nRF 的 RAM 预算内。

### 3.4 状态机：什么时候 prev 是可信的，什么时候必须先全刷"播种"

`prev_digits` 在以下情况**不可信**，必须先做一次全刷把已知值"播种"进去：

| 触发 | 原因 |
|------|------|
| MCU 冷启动后第一次进时钟模式 | RAM 初值未定 |
| 整点周期全刷之后 | 整点全刷会用 OTP 三色波形重写整屏，OLD 已与状态变量脱钩 |
| 从其他模式切回时钟模式 | 屏幕上是其它内容，prev 与之不符 |
| 用户强制全刷 / `force_full_refresh` | 同上 |

实现用一个 `valid` 标志：

```c
static struct {
    bool valid;        // false: 下次必须走全刷; true: 可以走真差分局刷
    uint8_t digits[4]; // [HH/10, HH%10, MM/10, MM%10]
} s_clock_prev;
```

策略：
- `valid=false` 时 `epd_clock_diff_try_partial()` 直接返回 false，让 EPD_service.c 回退走原全刷路径
- 全刷成功后，由 EPD_service.c 调 `epd_clock_diff_seed(hh, mm)` 把当前数字写入 prev 并置 `valid=true`
- 下一次局刷时差分路径生效

### 3.5 为什么不影响其它模式

| 模式 | 画面参数化程度 | 走真差分？ |
|------|---------------|------------|
| **MODE_CLOCK_CALENDAR** | 强（时间是 4 数字 + 固定布局） | ✅ 真差分（决策三） |
| **MODE_CLOCK** | 强（同上，但全屏） | ✅ 真差分（同 CALENDAR） |
| MODE_PICTURE | 任意位图 | ❌ 没法重建 OLD，仍走决策一的整窗温和重绘 |
| 自定义模式 | 含动态文本/动态图形 | ❌ 同上 |

→ 决策三是时钟模式的**优化叠加层**，不替代决策一。其它模式继续用决策一的 DTM1=~NEW 整窗重绘路径。

### 3.6 实现拆分（落地后）

```
EPD/UC8179.c
  + UC8179_Partial_Diff_Push(x, y, w, h, old_bm, new_bm)
    -- 单字位真差分推送: PTIN -> PTL -> DTM1=old_bm -> DTM2=new_bm
    -- 不调 PON/DRF/POF, 留给上层批量调度

EPD/epd_clock_diff.h / .c           (新增)
  - s_clock_prev (4B 数字状态 + valid)
  - epd_clock_diff_seed(hh, mm)            -- 全刷成功后调
  - epd_clock_diff_invalidate()            -- 切模式 / DSLP 后调
  - epd_clock_diff_try_partial(epd, hh, mm)-- 主入口: 可行返回 true 并已驱动屏幕
                                           --        不可行返回 false 让上层走原路径
  - 内部 render_digit_bitmap() 调用 GFX Draw7Number 渲染单字位到内存缓冲

EPD/EPD_service.c                   (轻量改动)
  - 时钟分钟分支首先调 epd_clock_diff_try_partial; 成功就 return
  - 失败回退到原 DTM1=~NEW 整窗重绘路径
  - 全刷完成后调用 epd_clock_diff_seed
  - 模式切走/睡眠时调用 epd_clock_diff_invalidate
```

### 3.7 边界与限制

1. **字位坐标必须 8 像素对齐**：UC8179 PTL 命令的 X 起始/结束必须按字节对齐。`Draw7Number` 的字位起点不一定对齐，需要在 `epd_clock_diff` 里向前向后取整到 8 边界（多算几像素白色无害）。
2. **温度极端时 set#2 强度可能不足**：set#2 是定值，没温度补偿。低温（<5°C）下电泳响应变慢，单相 50 帧（T2=0x32）可能驱动不到位 → 残影。靠每整点一次的全刷兜底；若实测有问题，set#2 的 T2 可微调。
3. **AON-像素重叠的非数字元素**：如果时钟字位区域里画了非数字内容（图标、装饰线等），重建 OLD 时会漏掉它们 → 这部分会被错判变化而被驱动一次。当前 `DrawTime` 仅画数字+冒号，无叠加；以后若有，需把这些静态元素也纳入"重建"范围。
4. **冒号是常显的**：因为始终为黑、不变，差分判定为 (K,K) 命中 LUTBB hold → 不被驱动，符合预期。当前实现把冒号视为"始终在 OLD 也始终在 NEW"的固定笔画，渲染时同时画进 old_bm 和 new_bm。
5. **跨整点的衔接**：整点全刷由 `UC8179_Refresh` 的全刷路径执行（决策二保证它真是全刷）。全刷完成后必须调 `epd_clock_diff_seed`，否则下一分钟的差分会用错误的 OLD。
6. **字位完全不变（如分钟个位 0→0 不可能但容错）**：try_partial 检测到 0 个字位变化时，跳过整个 DRF（不驱动），保持原画面。这比"假装刷一下"省电省屏。

### 3.8 设计权衡总结

| 维度 | 决策一（DTM1=~NEW 整窗） | 决策三（参数化重建真差分） |
|------|--------------------------|--------------------------|
| 视觉效果 | 整窗温和重绘，背景被一起刷 | 只有变化笔画微闪，背景纹丝不动 ★ |
| RAM 占用 | 0 (用 GFX 主缓冲) | +4B 静态 + 复用 1.4KB 临时缓冲 |
| Flash 占用 | 基线 | +约 1KB 代码 |
| CPU 时间 | 1 次 GFX 渲染 + 2 份 RAM 推送 | 1~3 次额外渲染 + 1~3 个 PTL 窗口推送（仍 < 1s） |
| 鲁棒性 | 无状态，重启即可工作 | 需要 prev valid 状态机；冷启动/整点后必须先全刷"播种" |
| 范围 | 任意画面通用 | **仅时钟模式适用** |
| 与决策一关系 | 基线 fallback | 优化叠加层；失败时回退到决策一 |

决策三在时钟模式下提供"参考固件级体验"，其它模式继续用决策一兜底——两者**不互斥**而是分层。

| 问题 | 现象 | 根因 | 修复 |
|------|------|------|------|
| 局刷不能"只刷变化区域" | 整窗微闪 | RAM 不够存 OLD + 编排会复位芯片，无法做真差分 | 退而求其次：DTM1=~新帧 + set#2 → 整窗温和重绘 |
